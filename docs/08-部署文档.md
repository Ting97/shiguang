# 08 · 部署文档 —— shiguang.ting97.cn（腾讯云）

> 2026-09-17 首次部署成功。本文档保证可重复部署/迁移。

## 生产环境

| 项 | 值 |
|---|---|
| 地址 | **https://shiguang.ting97.cn**（Let's Encrypt 证书，Caddy 自动续期） |
| 服务器 | 腾讯云 CentOS Stream 9 / x86_64 / 3.6G 内存（SSH 别名 `tencent`，114.132.169.158） |
| 应用 | Next.js standalone，Node 22（`/usr/local/shiguangri-runtime`），systemd 守护 `shiguangri.service`，监听 127.0.0.1:3000 |
| 数据库 | 服务器本地 PostgreSQL 13（scram 认证，仅 127.0.0.1），库名 `shiguangri` |
| 反代 | 复用已有 Caddy（同机还有 trade/tend 两个站点，互不影响） |
| 目录 | `/opt/shiguangri`（应用 + `.env`） |

## 发布流程（增量更新）

```bash
# 1. 本地构建
cd apps/web && rm -rf .next && npm run build

# 2. 同步产物
rsync -az --delete .next/standalone/ tencent:/opt/shiguangri/
rsync -az .next/static tencent:/opt/shiguangri/apps/web/.next/

# 3. 重启服务
ssh tencent "systemctl restart shiguangri"
```

## 常用运维命令（在服务器上）

```bash
systemctl status shiguangri          # 状态
journalctl -u shiguangri -f          # 实时日志
systemctl restart shiguangri         # 重启

# 数据库备份（建议加 cron：0 3 * * *）
sudo -u postgres pg_dump shiguangri > /root/backup/shiguangri-$(date +%F).sql

# 数据库恢复
sudo -u postgres psql shiguangri < backup文件
```

## Schema 变更

修改 `packages/db/schema.sql` 后，在服务器执行增量 SQL：
```bash
ssh tencent "psql 'postgresql://postgres:<密码>@127.0.0.1:5432/shiguangri'"
```
（Phase 2 起建议引入 migration 目录管理增量，避免手工执行。）

## 坑位记录（迁移时注意）

1. **CentOS PG13 默认密码加密是 md5**，pg_hba 改 scram 前必须先 `set password_encryption='scram-sha-256'` 再改密码，否则永远认证失败。
2. `pg_hba.conf` 的 127.0.0.1 行要从 `ident` 改为 `scram-sha-256` 并 reload。
3. monorepo 的 standalone 产物在 `.next/standalone/apps/web/server.js`（镜像目录结构），static 需手动补到 `apps/web/.next/static`。
4. 时区：库按 `Asia/Shanghai` 显式切分日期（API 已内置），服务器系统时区也确认是 CST。
5. 环境变量在服务器 `/opt/shiguangri/.env`（不入库）；本地仓库的 `.env` 仅用于开发。

## 凭据管理约定（2026-09-17 确认）

- **生产凭据唯一来源：服务器 `/opt/shiguangri/.env`**（含数据库密码、智谱 Key、模型名），长期保存在服务器上，其他终端需要时直接取用：
  ```bash
  ssh tencent "cat /opt/shiguangri/.env"
  ```
- 仓库永远不存密码（.env 已 gitignore，.env.example 只留字段名）。
- 新终端接入开发的前提：配好 SSH（`~/.ssh/config` 加 `tencent` 主机 + 对应私钥），即可读取凭据、发布代码、查日志。
- 若泄露需要轮换：改服务器 .env → `systemctl restart shiguangri` → 同步更新本地开发 .env。

## 数据说明

- 服务器库与本地开发库**相互独立**（各自积累数据）。
- 本地数据迁移到服务器：本地 `pg_dump --data-only` → 服务器 `psql` 导入（注意用户 id 一致，当前都是开发单用户）。
