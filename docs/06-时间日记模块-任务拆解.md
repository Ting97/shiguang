# 06 · 时间日记模块 —— 任务拆解（拾光复利 P0，首个开工模块）

> 定稿 2026-09-16。产品：**拾光复利**（个人经营系统：钱·时间·人）。本篇是 Phase 1（5 周）的实施规格：页面清单、AI 解析规则、数据落地、验收标准。
> 已确认需求（详见 05 篇 §3）：语音+文字双输入、AI 回填推断、无被动追踪、预设 8 类可自定义、四级日历视图、复盘要日结构+周月趋势+年度热力图、含金额语句自动联动财务。

## 1. 模块目标

> 说一句话（或敲一行字），系统自动识别**做了什么、什么类别、几点到几点、有没有花钱**，落进日历——你一天的 24 小时由此完整可见，日/周/月/年逐级回看。

**总验收**：① 打卡→结果确认 ≤5 秒；② 20 句真实话术解析准确率 ≥85%；③ 日视图能完整呈现一天的每段时间；④ 你连续 7 天真实使用。

## 1.5 记录即动态（2026-09-17 改造确认）

> 记录体验对齐微博/朋友圈：**说一句话 = 发一条动态**，AI 在动态之上自动识别意图。

- **动态本体** = `entries`（`created_at` 即"记录于 今天 15:32"）；首页为动态流（`/api/feed`，按记录时刻倒序，按天分组），每条卡片展示：记录时刻、心情 emoji、AI 识别产物（日程时间段/待办/金额/人物）；可删除（级联清理该动态生成的日程/待办/流水/往来）。
- **AI 意图三分**（`intent`）：
  | intent | 触发 | 落库 |
  |---|---|---|
  | `schedule` | 过去/正在做的具体事（时间、花销、做了什么） | time_blocks (+transactions/contacts/interactions 草稿) |
  | `todo` | 未来计划（明天/待会儿/打算） | todos（due_at/remind_at） |
  | `status` | 纯心情/状态/感想（"今天有点累"） | 仅 entries，不生成日程 |
- **心情维度**（`mood`，与意图正交）：任何话术都可带情绪 → `entries.mood`（中文词）+ `mood_score`（-100~100，正=积极）；LLM 给词为主，规则引擎兜底（离线/降级），score 缺失按心情词基准分补全。
- Schema 变更见 `packages/db/migrations/001-entries-mood.sql`。

## 3. AI 解析规则（核心，Phase 0 PoC 验证对象）

### 3.1 输入 → 输出 Schema

输入：`{ text: 转写文本 | 用户键入文本, now: 当前时间 }`
输出（单次 GLM 调用，JSON Schema 约束）：

```json
{
  "activity_id": "fitness",            // 归属类别
  "title": "跑步",                     // 简短标题
  "time": {
    "mode": "explicit | relative | default",
    "start": "2026-09-16T18:20:00+08:00",
    "end":   "2026-09-16T19:00:00+08:00",
    "duration_min": 40,
    "confidence": 0.92
  },
  "finance": { "has_amount": true, "amount": -600, "keyword": "随礼",
               "pre_category": "人情往来", "counterparty": "老王" },  // 联动财务草稿
  "people":  [ { "name": "老王", "event": "送礼" } ],                  // 联动人际草稿
  "ambiguity": null                     // 非空时触发追问气泡
}
```

### 3.2 时间推断算法（回填引擎）—— 含「未来→TODO」分流（2026-09-17 确认）

**语义总则**：**未来话术创建待办（todos：计划时间+提醒），过去/当前话术记录日程（time_blocks）。**

| 模式 | 触发词例 | 规则 |
|---|---|---|
| **future → TODO** | "明天下午三点看牙""待会儿倒垃圾""下周三上午开会""打算/要交…" | 不钳制；计划时刻=日期词(明天/后天/下周X)+钟点(三点/15:30)+时段锚点推导；`createsTodo=true`，落 todos 表（due_at/remind_at 默认提前15分钟）；完成打卡时再生成 time_block 并回填 done_entry_id |
| 显式时长 | "跑了40分钟"、"聊了俩小时" | end=now（"刚…"）或时段锚点；start=end-时长 |
| 相对时段 | "下午/上午/晚上/中午…" | 锚点+类别默认时长；锚点在未来视为昨天（过去语境） |
| 纯事件 | "跑步了" | 类别默认时长（设置页可改），end=now |
| 未记录缺口补录 | 日视图点缺口 | 表单 + AI 根据上下文猜测选项 |

**边界**：跨天（"昨晚熬夜到2点"）、重叠冲突、时点模糊追问；正在进行（"正在开会"）暂按过去处理，开放式时间块二期评估。

### 3.3 测试集（Phase 0 你提供 20 句，持续累积错例库）

样例预期（真实话术会进入回归测试 `packages/ai/tests/parser.spec.ts`）：
- "刚跑完步，练了40分钟" → 健身/跑步/now-40m
- "下午跟客户聊了两个小时" → 工作/会客/14:00-16:00
- "中午和老王吃饭花了260" → 社交+餐饮花销/12:00-13:00 + 财务-260 + 人际(老王)
- "晚上刷了会儿抖音" → 娱乐/默认30m

## 4. 数据落地（对应 03 篇 Schema）

- `entries`（原始记录：text 来源 voice|keyboard + media）→ `voice_logs`（音频/转写）→ `time_blocks`（确认后生成）；
- `finance` / `people` 命中时写**草稿表**（Phase 2/3 接管确认流，一期先落 `transactions.draft=true` 与 `contacts` 自动建档）；
- 解析失败/低置信：`ambiguity` 非空 → 追问气泡（"是支出 600 元给老王吗？"），用户选择即样本。
