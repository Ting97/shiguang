# 03 · 技术方案与架构设计

> 目标：构建「**个人经营系统：钱 · 时间 · 人**」——以 Mooly 式记录流与 AI 管线为骨架，以财务复盘、语音时间记录、人际图谱为三大核心差异化模块。团队为"1 人 + ZCode（智谱 Pro 套餐）"，技术选型以**单人可维护、AI 辅助开发效率最大化**为第一原则。此为 v0.2（2026-09-16 按定制需求修订），待 05 篇需求确认后定稿。

## 1. 技术选型总览

| 层 | 选型 | 理由 |
|---|---|---|
| Web 前端 | **Next.js 15 (App Router) + TypeScript + Tailwind CSS + shadcn/ui** | 与 Mooly Web 端同栈（已验证可行）；ZCode 对该栈生成质量最高；SSR 利于官网/SEO；shadcn 可定制性强 |
| 移动端 | **React Native (Expo + expo-router)** | 与 Web 共享 TS 类型、API 层、提示词与校验逻辑（monorepo）；Expo 支持OTA热更新、推送、语音；规避双端原生团队 |
| 后端 | **阶段1：Supabase**（Postgres + Auth + Storage + Realtime + Edge Functions）；**阶段2：按需引入 NestJS 服务**（重业务：AI 管线编排、账单、推送调度） | 单人+AI 开发最快路径；Auth/OSS/实时同步开箱即用；BeeCount 已验证中文用户对 Supabase 方案接受度 |
| LLM 接入 | **GLM 系列为默认主力**（智谱 Pro 套餐内含额度，成本最优且与 ZCode 生态协同）：GLM-4.6V 做多模态识别、GLM-4.7-Flash 做免费分类提取（2026-09 调研定稿，替代 GLM-4-Flash：同为免费但 200K 上下文、支持缓存与原生 JSON 输出）；备选降级 DeepSeek/Qwen；统一 OpenAI 兼容网关 | 服务端代理保密钥安全；可按 Agent 分级配模型控成本；套餐额度优先消耗 |
| ASR 语音转写 | 阶段1 云端 ASR（GLM-ASR/讯飞，按量计费）；阶段2 可选本地 Whisper（隐私敏感用户） | 语音打卡是高频入口，转写成本需纳入成本模型 |
| 向量与记忆 | **pgvector**（Supabase 内置）+ 分层记忆设计 | 不引入独立向量库，降低运维；检索记忆 + 结构化画像混合 |
| 图谱可视化 | **AntV G6**（备选 Cytoscape.js） | 人际关系图谱渲染，中文文档全，React 集成成熟 |
| 日历集成 | 内置日历视图 + **ICS 导出/订阅**；阶段2 CalDAV/系统日历双向同步 | 用户要求"日历自动登记每天每个时间段"，先自有日历后互通 |
| 定时任务 | 阶段1 Supabase pg_cron + Edge Functions；阶段2 独立 worker | 周报/月报/主动消息调度 |
| 部署 | **需求方自有国内服务器 + 域名，Docker Compose 直接部署**（Web/SSR + Postgres + AI worker 一把梭）；域名走备案流程 | 零额外成本，数据自主可控；备案与上线并行不误开发 |
| 可观测 | Sentry + 简易后台日志表 | 单人团队规模适配 |

**monorepo 结构（Turborepo + pnpm）**：

```
apps/
  web/          # Next.js
  mobile/       # Expo
  server/       # NestJS（阶段2）
packages/
  api-client/   # 统一 API SDK
  db/           # 数据库 schema（Drizzle/Prisma）+ 类型
  ai/           # 提示词模板、Agent 定义、结构化输出 schema
  ui/           # 共享组件（可选）
  config/       # eslint/ts/tailwind 配置
```

                      --   content, media_ids, visibility, created_at

## 4. AI 能力层设计（系统的灵魂）

### 4.1 记录处理管线（一条记录发布后）

```
entry 创建 ──► 入队 ──► 管线（并行/串行混合，参考 memex 多 Agent 编排）
  1. 媒体预处理：语音→转写（ASR）；图片→场景/食物识别（VLM）
  2. 结构化提取（便宜模型，JSON Schema 约束输出，1 次调用合并多任务）：
     情绪(标签+valence) / 待办 / 关键动作匹配 / 热量 / 维度归属+贡献分
  3. 记忆沉淀：判断是否值得写入长期记忆；生成 embedding 入库
  4. AI 回应（人设模型）：注入 用户画像+相关记忆(RAG top-k)+目标上下文
  5. 维度日聚合更新（花瓣生长）
```

**成本控制三板斧**：模型分级（提取用 flash 级、陪伴对话用旗舰级）、结果缓存、合并调用（一次 prompt 出全部结构化字段）。

### 4.2 Agent 运行时

- Agent = 系统提示词（人设）+ 模型路由 + 工具集 + 记忆注入策略。
- 内置智囊团可先做 3 个（目标教练/记录整理/复盘洞察），其余按需扩展——Mooly 8 个 Agent 中部分（使用指导）可用规则替代。
- 参考 lobehub 的 Agent 元数据结构，为"角色市场"留好 schema。

### 4.3 记忆系统（分层）

| 层 | 内容 | 技术 |
|---|---|---|
| 工作记忆 | 当前会话上下文 | 会话历史 |
| 情景记忆 | 用户全部记录/事件 | entries + embedding 检索 |
| 语义记忆 | 提炼出的事实（"每周三跑步"） | memories(semantic) |
| 用户画像 | 稳定特征：偏好、目标、人际、习惯 | 结构化 profile + 定期 Agent 总结更新 |

### 4.4 语音打卡管线（时间模块的核心交互，2026-09-16 新增）

```
用户说一句话（"刚跑完五公里，练了40分钟" / "给老王家孩子随了600块礼"）
   │
   ▼
ASR 转写（GLM-ASR / 讯飞 / 本地 Whisper，分级选择）
   │
   ▼
意图识别 + 结构化提取（单次 LLM 调用，JSON Schema 约束）：
   {
     "domains": ["time", "finance", "people"],   // 一句话可同时命中多域！
     "time":   {"activity": "健身", "duration_min": 40, "ends_now": true},
     "finance": {"amount": -600, "category": "人情往来", "counterparty": "老王"},
     "people": {"contact": "老王", "event": "送礼", "note": "给孩子随礼"}
   }
   │
   ▼
落库：time_blocks / transactions / interactions 三表联动写入
   （"随礼600"自动同时进 财务流水+人际往来+分类"人情往来"——数据打通是灵魂）
   │
   ▼
确认气泡（App 端轻交互：识别结果卡片，一键确认/修正——修正数据反哺提示词优化）
```

设计要点：
- **多域联合解析**：财务/时间/人际常常发生在同一句话里（请客吃饭=钱+时间+人），必须一次解析多域落库，这是三大模块"打通"的关键，也是所有竞品都没做到的。
- **低置信度回问**：置信度 < 阈值时 AI 追问一句（"是支出 600 元给王先生吗？"）。
- **时间块的默认策略**：说到"刚完成"则回溯填充（默认时长 or 上一活动结束时刻起算）；日历视图可手动拖拽修正。

### 4.5 三大模块复盘引擎（AI 交叉归因，2026-09-16 新增）

复盘不再按模块孤立生成，而是**交叉归因**（差异化核心）：
- 周/月复盘的固定分析框架：财务结构变化 × 时间投入变化 × 人际互动密度 三轴对照；
- 典型输出例："本月人情往来支出 +38%（3 场婚礼），同时社交时间 +12 小时；学习时间下降 40%，与刷短视频时长上升相关"；
- 数据源全部来自结构化表（非让 LLM 现算数字——先 SQL 聚合出事实，LLM 只负责解读与建议，**杜绝编数字**）。

### 4.6 人际图谱可视化（2026-09-16 新增）

- 渲染库选型：**AntV G6**（中文文档、图谱场景全、React 集成好）备选 Cytoscape.js / react-force-graph；
- 图模型：本人为中心的自我中心网络（ego network），节点=联系人（大小=亲密度/互动频率），边=关系类型，颜色=分组；
- 交互：点击节点 → 该联系人时间线（interactions 按时间排列）+ 关联财务（礼尚往来合计）；
- "淡出预警"：亲密度 = 互动频率 × 亲疏评级的时间衰减函数，低于阈值标灰提醒。

### 4.7 八维平衡轮算法（降级为可选模块）

```
维度日分 = Σ(条目贡献分 × 时效衰减权重 × 行动加成) 归一化到 0~100
花瓣半径 = 近 7/30 日维度分滑动平均
"生长"动效 = 分数变化驱动 CSS 动画
```
先做可解释的规则版（用户能看懂为什么长），后续再引入模型直接评估做校准。

## 5. 关键技术风险与对策

| 风险 | 对策 |
|---|---|
| LLM 推理成本失控 | audit_logs 全量记账；免费额度限流；模型分级；批处理合并任务 |
| AI 输出不稳定（JSON 解析失败） | 结构化输出（JSON Schema/函数调用）+ 重试 + 降级默认值 |
| 隐私合规（日记数据极敏感） | 端到端最小化收集；传输/存储加密；隐私政策；支持导出与注销（个保法要求）；境内部署 |
| 生成内容安全 | 接入内容审核 API（敏感词+模型审核），陪伴类对话加安全护栏提示词 |
| 多端数据一致性 | 服务端为唯一事实源；Realtime 订阅；离线队列（App 端） |
| 小团队工程稳定性（Mooly 的教训） | CI + 灰度发布 + Sentry 崩溃监控 + 数据库每日备份 |
