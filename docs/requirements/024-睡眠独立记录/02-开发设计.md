# 024 · 睡眠独立记录 · 开发设计

## 数据模型（迁移 `061-sleep-logs.sql`）

```sql
create table if not exists fitness_sleep_logs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references profiles(id) on delete cascade,
  log_date date not null,
  sleep_h_x10 int not null check (sleep_h_x10 between 0 and 160),
  source text not null default 'manual' check (source in ('manual','checkin')),
  created_at/updated_at timestamptz,
  unique (user_id, log_date)
);
-- 存量搬迁：session_logs.sleep_h_x10 非空的行 → insert ... on conflict do nothing
```

repo：`listSleep(userId, from, to)` / `upsertSleep(userId, logDate, sleepHX10, source)`（on conflict 更新 + returning）。

## API

`/api/fitness/sleep`（仿 metrics）：
- `GET ?from&to` → `{sleep: [{log_date, sleep_h_x10, source, hours}]}`（hours=小时，服务端换算）
- `POST {date, hours}` → 同日 upsert（source=manual；service 层 saveSleep 第三参供打卡路径传 checkin）

## 打卡路径改写（service）

- `updatePlan` doneLike 分支与 `addLog`：`insertLog` 不再传 sleepHX10（repo 参数移除，列保留历史只读）；`v.sleepHours != null` 时改调 `upsertSleep(userId, 计划日/logDate, ×10, "checkin")`。
- `PlanPatchInput`/`LogInput` 的 `sleepHours` 校验不变（兼容旧调用方）。

## 教练/助手（chat/tools.ts query_fitness_logs）

- 返回体新增 `sleep: [{log_date, hours}]`（与 items 同区间，倒序；表缺失时 catch 空数组不炸工具）。
- description/unitHint 更新：睡眠为独立每日记录看 sleep 数组；items.sleep_h_x10 标注为迁移前历史值。
- 调整协议（「睡眠<6h 降级」）文案不动——`CHAT_FITNESS_COACH_SYSTEM_PROMPT` 与 strategy.adjustProtocol 的规则语义不依赖存储位置。

## 前端（panel.tsx / charts.tsx）

- `PageData.sleep` 随主加载拉近 180 天（与 metrics 同区间）；TodayTab 传给 SleepCard 与 FitnessTrends。
- `SleepCard`（仿 MetricCard）：最近一晚 + 近 7 天均值（提示低于 6h 教练降级）+ 录入 Modal（日期 max=今天、小时数）。
- `CheckInModal`：睡眠输入移除（grid 3 列→2 列）；已打卡卡实际行删「· 睡眠」；panel.tsx 移除不再使用的 `hours` 导入。
- `FitnessTrends` 新增可选 `sleep` prop → 「睡眠趋势」ChartCard（有数据才渲染）。

- 新用例：manual upsert/同日二写更新/整数口径/source、打卡兼容入参覆盖、`query_fitness_logs` 返回 sleep 序列与 unitHint。
