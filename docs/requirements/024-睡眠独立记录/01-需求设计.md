# 024 · 睡眠独立记录 · 需求设计

> 状态：开发中 · 2026-10-16 · 前置：016（健身模块）

## 背景与目标

睡眠此前混在训练打卡里（CheckInModal 睡眠输入 → `session_logs.sleep_h_x10`），语义不对：睡眠是**每日生活指标**而非训练产物，不训练的日子没有录入入口；打卡表单也因此多一项负担。用户明确要求（2026-10-16）：睡眠单独记录，运动教练/拾光助手生成训练计划时参考睡眠情况。

本批把睡眠独立为**每日一条**的记录（健身页独立卡），打卡不再收睡眠；教练调整协议「睡眠<6h 或异常酸痛或静息心率偏高 → 降级课」语义不变，数据源切换到新表。

## 需求清单

| # | 需求 | 验收 |
| --- | --- | --- |
| FR-A1 | 独立睡眠记录：`fitness_sleep_logs` 每用户每日一条（小时×10 整数纪律，source 标 manual/checkin）；健身页新增「😴 睡眠」卡（最近一晚 + 近 7 天均值 + 录入弹窗，同日重录=更新） | 健身页可录昨日睡眠；趋势 tab 出现睡眠曲线 |
| FR-A2 | 训练打卡移除睡眠输入（疲劳/酸痛/备注保留）；已打卡卡片的实际行不再显示睡眠 | 打卡弹窗无睡眠字段 |
| FR-A3 | 打卡 API 的 `sleepHours` 兼容入参保留，落到 sleep_logs（source=checkin，log_date=计划日）；`session_logs` 不再写该列（历史列保留只读） | 旧调用不破；新数据单源 |
| FR-A4 | 存量搬迁：迁移 061 把 session_logs 已有睡眠值搬入 sleep_logs（同日冲突以已有为准） | 老用户的睡眠历史出现在新卡与趋势里 |
| FR-A5 | 教练/助手数据源：`query_fitness_logs` 返回体新增 `sleep: [{log_date, hours}]`（查新表）；调整协议文案不变 | 排课前助手能读到近几日睡眠并执行降级规则 |

## 边界与非目标

- 不做手环/自动导入（二期可经 source 扩展）；不做睡眠提醒。
- `session_logs.sleep_h_x10` 列保留（迁移只增不改），仅停止写入；`GET /api/fitness/logs` 历史行仍返回该列。
- 睡眠录入入口只放健身页（目标&训练的消费场景）；不进首页动态/心情。

## 决策记录

1. **独立表而非并入身体指标**：body_metrics 是每周一晨起口径，睡眠是每日粒度——粒度不同不硬塞一张表。
2. **打卡 sleepHours 兼容入参保留并改道**：训记回读/旧客户端仍可能带该字段，直接丢弃会丢数据；落到 sleep_logs 保持「睡眠只有一个当前源」。
3. **迁移值 source=checkin、同日冲突不覆盖**：搬的是起始历史，手动补录的真实值优先。
