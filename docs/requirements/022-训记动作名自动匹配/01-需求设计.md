# 022 · 训记动作名自动匹配 · 需求设计

> 状态：开发中 · 2026-10-16 · 前置：017（训记同步）/ 020（佳明截图导入）

## 背景与目标

佳明（Garmin）本身没有动作库——截图导入的动作名是视觉模型从截图文字识别出的自由文本，与训记（SynFit）官方动作库名称经常不一致（如佳明「坐姿绳索划船」vs 训记「坐姿划船」）。同步训记时 `makeOfficialResolver` 要求逐字命中官方目录，未命中直接抛「动作不在训记官方动作库」，而前端没有改名入口——导入顺畅、同步卡死。

训记 Open API 已有动作目录接口（`api_movement_catalog_for_llm_v2`，实测 1222 个动作、带肌群分类、别名当前为空），此前只在同步时用于拦截校验。本批把目录变成主动资产：识别/落库前 AI 自动对齐。

## 需求清单

| # | 需求 | 验收 |
| --- | --- | --- |
| FR-A1 | 训记官方动作目录拉取并持久化：单行快照表 `fitness_xunji_catalog`（迁移 059）；分层加载 内存 1h → DB 快照 7 天内直接用 → 外呼刷新并写回 | 7 天内重复解析/同步不再外呼训记；进程重启不丢；训记接口故障时用旧快照继续匹配 |
| FR-A2 | 佳明截图/文本导入、计划落库（含 AI 助手提案确认卡）前，力量动作名自动对齐训记官方名：规则快速通道（实测别名映射 + 目录精确命中）→ 残余批量走一次 GLM 文本匹配（flash 模型） | 识别出的动作名落库时已是训记官方名，同步训记不再报「不在官方动作库」 |
| FR-A3 | 对齐后原名可追溯：name 替换为官方名，原名以「佳易名：xxx」并入该动作备注（解析确认弹窗与计划卡可见） | 计划卡动作行下方展示佳易名备注；同步训记的 movement 名为官方名 |
| FR-A4 | 全链路降级安全：未配 XUNJI_API_KEY / 目录不可得 / AI 失败 / AI 编造目录外名字 / 置信度 < 0.6，一律保留原名不阻塞导入（同步报错为现状兜底） | 无 key 环境行为与本批之前完全一致；AI 返回目录外名字被拦 |

## 边界与非目标

- 只对齐力量动作名；跑步模块映射为训记有氧日（跑步），无名字问题，不涉及。
- 不做动作名人工改名/确认 UI（匹配失败的动作用户可在训记侧自行处理；本批目标是消灭高频报错）。
- 不把目录全量塞进视觉解析 prompt（见决策 1）；不维护 per-user 自定义动作库。
- 目录预筛仅控制 prompt 体积（>800 名时按字符重叠取每名 top-40 候选），不追求召回率最优。

## 决策记录

1. **两阶段而非内联**：视觉解析（识别截图）与动作名匹配（对齐目录）分开两次模型调用——视觉模型聚焦抽取不被 1200+ 名目录分心；匹配用纯文本 flash 模型便宜快速；目录只随残余名单传输。
2. **目录存储选型（用户确认）**：DB 持久化 + 惰性刷新，新鲜阈值 7 天（用户指定）——进程内 1h 快速缓存保留、无常驻定时器（patrol.ts 的 setInterval 先例不复制，官方目录低频变化）。
3. **呈现方式（用户确认）**：name 直接替换为训记官方名 + 原名并入 note 备注——全链路（展示/打卡/同步）名字统一，改动面最小；保留原名/双字段方案否决（类型契约、前端、同步链路改动大）。
4. **防编造三重校验**：AI 返回的 official 必须逐字 ∈ 目录（官方名或别名展开集）、source 必须 ∈ 输入残余名单、confidence ≥ 0.6——任何一条不满足视为未匹配保留原名。
