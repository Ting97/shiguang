## 二、踩坑记录

1. **分层缓存与测试隔离**：loadXunjiCatalog 的 DB 快照行「7 天内新鲜」优先于注入的 stub fetcher——上一轮用例写入的 2 名字目录残留，导致后续运行的 sync 用例读到新鲜 DB 行（目录里没有哑铃酒杯深蹲）→ 不改名 → 同步报错。解法：`freshCatalogState()`（清内存快照 + DB 行 fetched_at 打过期 8 天）作为依赖目录状态的用例前置；fitness.test.ts 顶部 `delete process.env.XUNJI_API_KEY` 防 shell 泄入真实 key 触发真实外呼+改名（该文件断言动作名原文的行动标题）。
2. **ssh 隧道 IPv6 撞 ident**：`-L 15432:localhost:5432` 在服务器侧解析为 ::1，命中 pg_hba 的 ident 规则报「Ident authentication failed」；改 `-L 15432:127.0.0.1:5432` 强制 IPv4 走 md5。另：Bash 会话退出会 HUP 后台 ssh，需 `nohup … & disown` 保活（否则真库用例间歇性整组 skip）。
3. **zod 宽容契约**：`llmConfidence` 越界不拒绝而是 catch 成 0.5——匹配门槛 0.6 下天然安全，契约测试按宽容口径断言。
