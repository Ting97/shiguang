# 022 · 训记动作名自动匹配 · 开发设计

## 数据模型

迁移 `059-xunji-catalog.sql`：单行快照表（目录约 1222 条、15KB 量级，jsonb 整存最简）：

```sql
create table if not exists fitness_xunji_catalog (
  id int primary key default 1 check (id = 1),
  movements jsonb not null default '[]'::jsonb,   -- [{name, type, exetype, aliases}]
  fetched_at timestamptz not null default now()
);
```

repo 层新增 `getXunjiCatalog()` / `upsertXunjiCatalog(movements)`（SQL 集中 repo 惯例）。

## 目录分层加载（service.loadXunjiCatalog）

```
内存快照(1h) ──miss──▶ DB 快照行(<7天 直接用) ──过期/无行──▶ 外呼 fetchCatalogMovements
                                                    │成功：写回 DB(fire-and-forget)+刷内存
                                                    │失败：回退 DB 旧快照 → 再无则空集
```

- `xunji.fetchCatalogMovements(fetcher)`：外呼 + 规范化（trim/type/exetype/aliases，脏行跳过）；原 `fetchCatalogNames` 的 1h 内存缓存上移到 service 层（缓存决策与 DB 层同居一处）。
- `catalogToNameSet(movements)`：官方名 + 别名一起展开（`makeOfficialResolver` 与匹配校验共用口径）。
- `syncPlanToXunji` 改用 loadXunjiCatalog：训记接口故障时还能用旧快照校验（优于旧空集兜底）。

## 匹配编排（service.matchXunjiOfficialNames）

1. `loadXunjiCatalog` 得名字集合；**空集直接返回空映射**（无 key/目录不可得 → 主流程照旧）。
2. `ruleMatchOfficialNames`（xunji.ts 纯函数）：`XUNJI_NAME_ALIAS` 命中且目标在目录 → 映射；目录精确命中 → 视为已消化；残余进 pending。
3. pending 非空 → 一次 `chat()`（纯文本默认模型，maxTokens 1000 / timeout 30s）：`getPromptBundle("xunji_name_match")` system + 注册表模板装配 user（`{names}` `{catalog}` 占位符）。
4. 候选目录控制：≤800 名全量传；超过按「包含 +100 / 二元组重叠 +2」打分预筛，每名 top-40 合并去重（实测目录 1222 名 → 预筛生效，候选行附肌群分类辅助判断）。
5. 三重校验后入映射：source ∈ pending、official ∈ 目录展开集、confidence ≥ 0.6（`llmConfidence` 宽容契约越界 catch 成 0.5，天然低于门槛）。
6. 审计 `stage: "xunji_name_match"`（audit.ts 联合类型新增；成功/失败均记录 model/latency/tokens/matched）。

## 落库接入（attachExerciseIds 扩展）

```
resolveExerciseIds(拾光库挂 exerciseId，原名口径)   ← 先挂 id，肌群/收益展示不受改名影响
  → matchXunjiOfficialNames + renameExercisesToOfficial   ← 再改名：name=官方名，note 并入「佳易名：xxx」
```

- `renameExercisesToOfficial`（xunji.ts 纯函数）：未映射条目原样；官方名超 20 字（拾光动作名上限）跳过——防绕过落库校验导致后续草稿编辑被拒；note 合并后 60 字截断（`[...str]` 按 code point）。
- 三个入口自动覆盖：`parsePlanDraft`（佳明截图/文本导入——解析确认弹窗所见即最终名）、`savePlanDraft`（确认卡保存/手动 API）、`updatePlan` 草稿编辑路径。AI 助手 `propose_fitness_plan` 落 chat_proposals 不改，accept 走 savePlanDraft 兜底。
- 签名加可选 `opts: XunjiNormalizeOptions`（`{ fetcher?, aiMatch? }` 测试注入，生产路由不传）。

## packages/ai（纯包）

- `schema.ts`：`XunjiNameMatchResult`（matches ≤15 条：source/official|null/confidence）。
- `prompt.ts`：`XUNJI_NAME_MATCH_PROMPT`（同一动作异叫法才可配 / 不同动作禁配 / 禁编目录外名 / 宁缺勿错）+ `buildXunjiMatchUserPrompt`。
- 注册表：`ai/prompts.ts` 新 key `xunji_name_match`（PROMPT_KEYS/META/DEFAULTS，DB 热更同款机制）；`ai/ai-inputs.ts` 注册 `{names}` `{catalog}` 占位符（required 注入）。

## 前端（apps/web）

零必改之外一处补齐：`ContentPreview` 力量动作行新增 note 渲染行（`佳易名：xxx` 备注在解析确认弹窗与计划卡可见；此前动作级 note 不展示）。

## 测试注入面

- `XunjiNormalizeOptions.aiMatch`：跳过真实 GLM 调用直接给定匹配结果（编排层校验逻辑照跑）。
- `XunjiNormalizeOptions.fetcher`：stub 目录/读写响应（沿用 xunji.test.ts 的 stubFetcher 模式）。
- `resetXunjiCatalogCache()`（service 导出）：清内存快照；测试里配合「DB 行打过期」强制下一次读取走注入 stub——分层缓存的跨用例残留是测试隔离的关键坑（见 03 文档踩坑）。
