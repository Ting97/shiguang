# 021 · 训练计划多计划与删除 · 开发设计

## 数据模型

迁移 `058-multi-plans-drop-unique.sql`：drop `fitness_daily_plans` 的 `(user_id, plan_date, module_code)` 唯一约束（约束名已在生产库核实为 `fitness_daily_plans_user_id_plan_date_module_code_key`）。其余表零改动——删除语义完全复用 053 的既有 FK：

- `todos.fitness_plan_id → fitness_daily_plans(id) on delete cascade`（联动行动全清）
- `fitness_session_logs.plan_id → fitness_daily_plans(id) on delete set null`（打卡历史转独立记录）

## API 变更

| 端点 | 变更 |
| --- | --- |
| `POST /api/fitness/plans` | create-or-replace → **纯新增**：去掉 findPlan 已存在分支与「生效计划 409」；每次保存新插一条并独立联动行动（syncPlanTodos 逻辑不变，按 plan_id 天然隔离） |
| `DELETE /api/fitness/plans/[id]` | **新增**：planOwned 越权 404 → `delete from fitness_daily_plans`（级联见上）；返回 `{deleted:true}` |
| `GET /api/fitness/plans` | 排序补 `p.created_at`（同日同模块多计划稳定展示） |

repo 层：删 `findPlan`（唯一调用方是旧 replace 分支）、增 `deletePlan`。

## 前端

- `PlanCard` 操作区改为常驻渲染：状态流转按钮（确认/打卡/训记/跳过）仍按状态显隐；「删除」（btn-ghost + text-danger）任意状态可见。
- 删除确认 Modal：按状态差异化文案——已打卡（有 log）提示「执行记录将保留为独立打卡历史」；已同步训记提示「训记不受影响」。
- 今日/计划页列表渲染零改动（本就 map 多条）。

## 兼容性

- 运动空间 TODO·行动栏、首页今日行动：多计划 = 多组联动行动，按 plan_id 各自归属，skipped/删除各自清理，无交叉影响。
- 训记同步（sync-xunji / pull-xunji）：按计划 id 操作，多计划互不干扰。
- 聊天提案工具 propose_fitness_plan：卡片保存走同一条 POST（新增语义），prompt 中「先查当日已有计划避免冲突」降级为生成时机建议，无行为冲突。
