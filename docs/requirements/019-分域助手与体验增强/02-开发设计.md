## A · 训练模块

### A1 休息日语义（三处）

1. `apps/api/src/server/fitness/service.ts` `parsePlanDraft`：入口规则短路——`text.trim()` ≤30 字且 `/无安排|没有(课表|训练|安排)|休息日?|^rest$/i` → `ApiError.badRequest("识别为休息日：今天没有训练安排，无需导入计划")`。
2. `packages/ai/src/schema.ts` `FitnessPlanDraftV2`：module 枚举加 `'rest'`，`rest: z.object({ note: z.string().max(100).optional() })`；superRefine 放行 rest。
3. `packages/ai/src/prompt.ts` `FITNESS_PLAN_PARSE_PROMPT` 判定规则加「用户明确表示当天无训练（休息/无安排）→ module=rest，rest.note 记原话摘要」；service 收到 rest 草稿 → 返回同款 400 文案（note 拼进文案）。
4. 兜底：runOnce 里 `extractJson` 的普通 Error 包装为 `GlmError("badOutput")` 走既有一次修复重问（当前穿透 toApiError 成 500）。

### A2 换算修复

`apps/web/src/app/fitness/kit.ts:32`：`cm = (mm) => Math.round(mm) / 10`（原双重 ÷10）。

### A3 身高/体脂

- service `MetricInput` + `heightCm`（50–250）+ `bodyFatPct`（3–60，×10 存 body_fat_pct_x10）；`saveMetric` 列清单加 height_mm。
- repo `upsertMetric`（insert 与 on conflict update 两处列清单）。
- shared `FitnessBodyMetric` + `height_mm?: number | null`。
- 前端 panel.tsx MetricCard：弹窗加 体脂率(%) / 身高(cm) 输入；「最近」行补展示；charts.tsx 加 身高(cm)（height_mm/10）与 体脂率(%)（x10/10）两趋势图（`m.height_mm != null` 过滤空点）。

### A4 策略档案

- 新端点 `POST /api/fitness/goals/[id]/strategy-optimize`（body `{ instruction?: string ≤200 }`）：service 拉 `get_fitness_goals` 同源数据（goal.strategy/targets + profile + 近 90 天 metrics/plans/logs 摘要）→ PromptKey `fitness_strategy_optimize` → GLM JSON 输出 `{ summary: string, strategy: record }`（宽松 safeParse + 一次修复重问）→ 200 返回 `{summary, strategy}` 不落库；前端确认后走既有 PATCH /api/fitness/goals/[id]。

## C · 助手域

### scope 机制

- shared/chat 类型：`ChatScope = 'global'|'goal'|'time'|'people'|'finance'|'fitness'`。
- `POST /api/chat` body 加 `scope`（默认 global，白名单外 400）；创建会话写列；已有 conversationId 时以库里 scope 为准（body scope 不一致 → 400「会话域不匹配」防串域）。
- `GET /api/chat` 列表加 `?scope=` 过滤（缺省 global 保持旧行为？——**否**：缺省返回全部并带 scope 字段，前端按域过滤传参）。
- ask：读会话 scope → 选 prompt bundle + toAgentTools 子集。消息 DTO 带 scope 供前端展示。

### 工具域标注

tools.ts `ChatTool` 加 `domain: ChatScope`；24 个工具逐一标注（见 01 映射）；`toAgentTools(ctx, scope)`：global 全量；否则 `tools.filter(t => t.domain === scope || t.name === 'get_user_profile')`。`TOOL_LABELS` 不变。

### 人设

- packages/ai/src/prompt.ts 新增 5 常量：`CHAT_GOAL_SYSTEM_PROMPT`（目标管家：空间/todo/行动/阶段目标/感悟）、`CHAT_TIME_SYSTEM_PROMPT`（日程管家：时间块/todo 排程）、`CHAT_PEOPLE_SYSTEM_PROMPT`（人际管家：联系人/互动）、`CHAT_FINANCE_SYSTEM_PROMPT`（财务管家：账户/流水/预算/债务/交易）、`CHAT_FITNESS_COACH_SYSTEM_PROMPT`（运动教练：现全局 prompt 健身段扩成完整人设 + 训记）。共同段：只答本域、越域引导去「拾光助手」、应用使用辅导裁剪到本域。
- prompts.ts：PROMPT_KEYS/META/DEFAULT_PROMPTS 注册 5 个新 key（category「助手」）；service 按 scope 映射 key（global→chat_assistant）。ctxBlock 画像注入沿用 assembleUserPrompt（各 key 共用 context_config 默认）。

### 前端

- `chat-core.tsx`：`AssistantChat({ variant, onMinimize, scope = 'global' })`；SCOPE_META（label/placeholder/quickQuestions/标题）按 scope；发消息 body 带 scope；会话列表请求带 scope 过滤； ProposalCard 逻辑不动（fitness 提案只会出现在 fitness/global）。
- `assistant-dock.tsx`：`AssistantDock({ scope = 'global' })`，悬浮球文案 = SCOPE_META[scope].dockLabel，移动端 Link → `/assistant?scope=${scope}`。
- `app/assistant/page.tsx`：读 `useSearchParams` scope（白名单校验）传 AssistantChat。
- 挂载：spaces/page.tsx `<AssistantDock scope="goal" />`；schedule/page.tsx `scope="time"`；contacts/page.tsx `scope="people"`；finance/page.tsx `scope="finance"`（骨架分支挂载或不挂——**只在主 return 挂**，骨架瞬间无球可接受）；`spaces/[id]/detail.tsx`：`space.kind === 'sport' && <AssistantDock scope="fitness" />`。悬浮球与「今日行动」fixed 弹板无重叠（球在右下，弹板在右上）。
