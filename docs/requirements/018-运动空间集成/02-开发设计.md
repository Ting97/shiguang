# 018 · 运动空间集成 · 开发设计

> 依据 [01-需求设计.md](01-需求设计.md)；既有结构：goal_spaces（022/026 迁移）、space detail 三栏（spaces/[id]/detail*）、健身页（fitness/，016/017）。

## 一、数据模型（迁移 `056-sport-space.sql`）

```sql
alter table goal_spaces add column if not exists kind text;
create unique index if not exists uq_goal_spaces_sport on goal_spaces (user_id) where kind = 'sport';
-- 每用户建内置运动空间（on conflict (user_id) where kind='sport' do nothing）
-- 存量「运动/健身」自建空间：todos/entries/space_reflections 三表 space_id 改指内置空间 → 删除旧空间
```

注意点：
- `on conflict (user_id) where kind = 'sport'` 需要 PostgreSQL 9.5+ 部分索引推断语法（生产 PG16 ✓）。
- 删除旧空间前已完成三表 UPDATE（同一迁移事务内顺序执行）；`kind is null` 守卫保证重跑幂等。
- entries 挂空间是 `set null` 外键、space_reflections 是 `cascade`——都在删除前改指，不触发级联。

## 二、后端

### goal/repo.ts

- `ensureSportSpace(userId)`：`insert into goal_spaces (user_id,name,icon,kind,sort,description) values (…'运动','🏃','sport',-1,…) on conflict (user_id) where kind='sport' do nothing`（绕过 20 空间上限——系统空间不占用户配额）。
- `findSportSpace(userId)`：`select id, name, icon, kind from goal_spaces where user_id=$1 and kind='sport' limit 1`。
- `listWithStats` 排序追加 `(kind = 'sport') desc`（active 之后、sort 之前）。

### goal/service.ts

- `listSpaces`：先 `ensureSportSpace` 再查（新用户惰性建）。
- `updateSpace`：kind='sport' 时拒绝 `name`/`status` 变更（400「内置空间不可改名/归档」）；其余字段照旧。
- `removeSpace`：kind='sport' 时 400「内置空间不可删除」。需要 repo.update/remove 返回 kind（select 带上或先查）。

### fitness/service.ts `syncPlanTodos`

- 解析用户运动空间 id（repo 新增 `sportSpaceId(userId)` 或复用 goal 域导出——跨域只能走 index，goal index 已导出 spaceService/repo 面；采用 fitness/repo 直接查 goal_spaces（只读一行，SQL 在 fitness/repo 内不违反「跨表查询放 repo」）。
- `insertPlanTodo` 增加 `spaceId` 参数写入 todos.space_id；无空间时 null（旧行为）。
