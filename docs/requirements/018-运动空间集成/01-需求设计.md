# 018 · 运动空间集成：健身功能并入内置置顶「运动」目标空间

> 状态：开发中 · 版本 v1.0 · 2026-10-15
>
> 背景：016 健身模块独立成页（/fitness + 顶部导航），017 接入训记。用户决定把健身功能收进目标空间体系：目标空间引入**内置置顶模板**机制（首发「运动」），健身四区（今日/计划/趋势/目标&档案）与空间标准三栏（TODO·行动/感悟/动态）合为一处。

## 一、用户故事

- US1 作为用户，我打开目标空间列表，第一个就是系统内置的「运动」空间（置顶、带「内置」标识、不可误删）。
- US2 进入运动空间：默认看到训练面板（今日/计划/趋势/目标&档案四个子区），也能切到 TODO·行动/感悟/动态三个标准栏——训练与目标经营在同一容器。
- US3 我以前自建过「运动」（或「健身」）空间：里面的待办行动、感悟、动态在升级后自动出现在新的内置运动空间里，旧空间消失（数据无感迁移）。
- US4 训练计划联动的今日行动，同时挂到运动空间——在空间的 TODO·行动栏能看到「哑铃卧推 40kg×3×8-12」这类训练行动。

## 二、功能需求（FR）

### FR-A 内置置顶运动空间

- A1 goal_spaces 增加 `kind` 列（null=用户自建；'sport'=内置运动模板）；每用户至多一个（partial unique）。
- A2 置顶：空间列表排序内置空间在最前（active 优先级之后）；列表页显示「内置」徽标。
- A3 每用户自动拥有：存量用户由迁移 056 创建；新用户在首次拉取空间列表时惰性创建（ensure，幂等）。
- A4 保护：内置空间不可删除、不可改名、不可归档（防误操作破坏模板入口）；描述/图标/起止日期/排序仍可编辑。

### FR-B 健身功能并入

- B1 空间详情：kind='sport' 时顶级栏为 **训练 / TODO·行动 / 感悟 / 动态**；训练栏渲染健身面板（四子区），其余三栏与普通空间完全一致。
- B2 普通空间不受影响（仍是三栏）。
- B3 `/fitness` 旧地址客户端跳转到内置运动空间（`?tab=fitness`），无死链。
- B4 顶部导航删除「健身」项（入口只留目标空间）。

### FR-C 数据迁移（存量「运动/健身」空间）

- C1 迁移 056：名为「运动」或「健身」的自建空间，其 todos / entries / space_reflections 的 space_id 全量改指内置空间，随后删除旧空间（硬删，数据已迁走）。
- C2 幂等：迁移重复执行无副作用（kind 守卫 + on conflict）。
- C3 训练联动行动挂运动空间（syncPlanTodos 写 space_id）；无内置空间时保持旧行为（null）。

## 三、验收标准（AC）

1. 任意用户的空间列表第一个是「运动」内置空间，带徽标；删除/改名/归档操作被 400 拒绝并提示。
2. 运动空间四栏可用：训练面板全流程（粘贴导入/助手卡片/打卡/训记同步）不回退；TODO·行动栏能看到训练联动行动。
3. 预置旧「运动」空间（含三类数据）跑迁移后：数据 space_id 指向内置空间、旧空间已删；二次执行迁移无变化。
4. `/fitness` 与顶部旧收藏/跳转均落到运动空间训练栏；导航无「健身」项。
5. 全门禁绿 + 生产部署后线上验证。

## 四、非目标

内置模板的多模板扩展 UI（kind 已预留）、运动空间成员/权限、miniapp、空间 kind 的开放自定义。
