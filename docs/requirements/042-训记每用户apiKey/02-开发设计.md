# 042 · 训记 apiKey 每用户绑定 · 开发设计

## 数据模型（迁移 `068-user-integration-keys.sql`，只增不改）

```sql
create table if not exists public.user_integration_keys (
  user_id     uuid not null references public.profiles(id) on delete cascade,
  provider    text not null,          -- 首用 'xunji'；openGym 等后续集成复用
  api_key_enc text not null,          -- AES-256-GCM（EXCHANGE_ENC_KEY）：iv12+tag16+密文 base64
  updated_at  timestamptz not null default now(),
  primary key (user_id, provider)
);
```

## 后端

- **`fitness/xunji-keys.ts`（新）**：`getXunjiKey/getXunjiKeyInfo/saveXunjiKey/removeXunjiKey`。加密格式与 `finance/trading/bitget.ts` 同款（密钥同 `EXCHANGE_ENC_KEY`，不新增 env）；绑定先 `validateXunjiKey` 即时校验；掩码 `前3***后3`；解密失败抛 503 提示重绑（密钥换了不静默当未绑定）。
- **`xunji.ts`**：
  - `xunjiPost` 增 `keyOverride?` 参数（缺省回落 env——目录拉取/测试沿用）；
  - `readTrains/upsertTrains` 增尾参 `key?`；**读缓存键改 `sha256(key).slice(0,8):datestr`**（每用户分桶，防跨账号串数据）；`xunjiCacheInvalidate` 按后缀清全部账号该日条目；
  - 新增 `validateXunjiKey(key, fetcher)`：读哨兵日期 `2000-01-01`——key 无效得 `apikey invalid` 抛 502，有效返回空数据；
  - `apikey invalid` 文案改指【我的 → 训记同步】。
- **`service.ts`**：`requireUserXunjiKey(userId)` 统一拦截（未绑定 403 + 引导文案）；`syncPlanToXunji`/`pullXunjiCompletion` 取本人 key 透传到 upsert/read（先 planOwned/状态校验后 key 校验——越权 404 语义不变）；`xunjiEnabled(userId)` 每用户化（`{enabled=bound, bound, apiKeyMasked?, updatedAt}`，enabled 字段名兼容前端）；`fitnessService` 增 `xunjiKeyInfo/xunjiKeySave/xunjiKeyRemove/getXunjiKey` 出口。
- **路由**：新 `GET/PUT/DELETE /api/fitness/xunji-key`（withModule fitness；PUT 校验非空≤128 字符）；`xunji-status` 去掉 admin 收口改每用户；`sync-xunji`/`pull-xunji` 去掉 admin 收口（各归各账号）。
- **chat/tools.ts `query_xunji_trains`**：admin 门禁改为每用户 key 门禁（有绑定任何用户可查自己的实练；无绑定返回 hint）。

## 前端

- `components/xunji-key-section.tsx`（新，挂 profile 页功能管理之后）：未绑定态输入框+「绑定」；绑定态显示掩码+更新时间+「更换/解绑」（解绑两步确认 useArmConfirm）；绑定中「校验中…」。
