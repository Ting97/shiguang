## 模块注册表（`packages/shared/src/modules.ts` 新增）

纯数据、无依赖（与 `types.ts` 同级，按子路径导出惯例），shared 为单一事实源，两端以 `@shiguangri/shared/modules` 引入（api 已有同款先例：`@shiguangri/shared/bearer`、`/date`）；模块 key 合法性从此由代码约束（替代 031 的 DB CHECK）。

```ts
export interface ModuleDef {
  key: string;
  level: "domain" | "submodule";
  parent?: string;                    // 子模块必填；级联：父关则子关
  name: string;                       // 展示名（后台矩阵/功能管理区共用）
  icon?: string;
  core?: boolean;                     // core=任何层不可关（当前仅 timeline）
  defaultOn: boolean;                 // 无任何状态时的默认有效态
  userToggleableDefault: boolean;     // 「允许用户自开关」的全局默认（管理员可在 module_states 覆盖）
  nav?: { href: string; label: string };   // 顶部导航项（域级才有）
  apiPrefixes?: string[];             // 受控路由前缀（门禁清单与 smoke 断言依据）
  assistantScopes?: ChatScope[];      // 关联助手 scope（联动过滤）
}
export const MODULE_REGISTRY: ModuleDef[];
export type ModuleKey = string;
export const getModule = (key: string) => MODULE_REGISTRY.find(m => m.key === key);
export const childModules = (key: string) => MODULE_REGISTRY.filter(m => m.parent === key);
```

## 数据模型（迁移 `063-module-switch.sql`）

```sql
-- 063: 功能插件化三层模块开关（REQ-028）
-- 全局层：管理员维护每模块全局开关与「允许用户自开关」默认覆盖
create table if not exists public.module_states (
  module          text primary key,
  enabled         boolean not null,
  user_toggleable boolean not null,
  updated_by      uuid references public.profiles(id),
  updated_at      timestamptz not null default now()
);

-- 按用户层：管理员强制态 + 该用户开关可见性（均可空=跟随上层）
create table if not exists public.user_module_controls (
  user_id        uuid not null references public.profiles(id) on delete cascade,
  module         text not null,
  force_state    text check (force_state in ('on','off')),
  switch_visible boolean,
  updated_by     uuid references public.profiles(id),
  updated_at     timestamptz not null default now(),
  primary key (user_id, module)
);

-- 用户自选层：【我的】→功能管理 的开关值
create table if not exists public.user_module_prefs (
  user_id    uuid not null references public.profiles(id) on delete cascade,
  module     text not null,
  enabled    boolean not null,
  updated_at timestamptz not null default now(),
  primary key (user_id, module)
);

-- 存量搬迁：031/037 既有授权 → 按用户强制开（幂等，可重放）
insert into public.user_module_controls (user_id, module, force_state, switch_visible, updated_by)
select g.user_id, g.module, 'on', null, g.granted_by
from public.user_module_grants g
on conflict (user_id, module) do nothing;
```

要点：

- **`user_module_grants` 保留停写**：读取/写入全部改走 `user_module_controls`，旧表不再触碰（满足「迁移只增不改」，无需动其 CHECK）；`/api/admin/grants` 保留端点做兼容外壳。
- module 列**不设值域 CHECK、不 FK**：注册表在代码，新模块演进零迁移；写入路径一律先过 zod（key ∈ registry）。
- `module_states` 允许为空：读取层以注册表 `defaultOn`/`userToggleableDefault` 兜底（`states[m] ?? registry`）。

## 有效态计算（`apps/api/src/server/platform/modules.ts` 重写）

```ts
resolveUserModules(user): Promise<{
  modules: string[];        // 有效开启的 key 全量（admin 直通=全部）
  prefs: ModulePrefView[];  // 每模块明细，供 me() 与功能管理区
}>

// 单模块有效态（自上而下短路）：
// 1. core                                    → on（不可关）
// 2. 显式 global.enabled === false           → off（管理员下线；无行=未配置，不在此短路——
//                                              否则 defaultOn=false 被当作全局关，按用户强制开
//                                              永远压不过默认关，031 搬迁语义回归，v1.1 修复）
// 3. 任一 parent 祖先链 effective 为 off     → off（级联，不写子状态）
// 4. controls.force_state === 'off'          → off
// 5. controls.force_state === 'on'           → on
// 6. prefs.enabled ?? registry.defaultOn     → 终值（defaultOn 仅此处兜底）

// 开关可见性（【我的】里是否展示该项的拨动开关，独立于当前态）：
// visible(m) = !core && globalEnabled(m) && controls.force_state 为空
//           && (controls.switch_visible ?? global.user_toggleable)
// 父域当前 off 时子模块开关渲染为禁用态（提示先开父域），不算隐藏。

getModuleUser(module)  // 签名与三态语义不变（user/"unauthenticated"/null），内部改走 resolveUserModules
listUserModules(...)   // 同上，me() 继续消费
```

- **admin 直通**：`role === 'admin'` 全模块 on（现状保留，后台自身不被关掉）。
- **缓存**：`resolveUserModules` 结果按 userId 进程内缓存 TTL 60s（Map + 时间戳；单实例 systemd 部署成立）。写路径主动失效：`invalidateModuleCache(userId?)`——用户 prefs/grants 变更失效单人，`module_states` 变更全清。多实例未来再升级为 app_config 版本号方案。
- **依赖方向**：维持现 Modules.ts → `identity/auth`（getCurrentUser）现状，经 index 门面，不新增反向依赖。

## API

### 会话侧

- **`GET /api/auth/me`**（`apps/api/src/server/identity/service.ts` `me()`）：字段不变追加 `modulePrefs: { key, name, level, parent, effective, controllable, value }[]`（controllable=开关可见且可拨，value=用户自选值 null=未写过跟随默认）。`modules` 语义升级为全量有效 key（存量消费方 `finance-tabs.tsx` 的 `includes('debt')` 判断天然兼容）。
- **`PATCH /api/auth/module-prefs`**（新增 `apps/api/src/app/api/auth/module-prefs/route.ts`）：body `{ module, enabled }`（zod）。校验链（任一不过 403）：key ∈ registry → 非 core → 全局开 → 无强制 → `(switch_visible ?? user_toggleable)` 为真 → 父域链有效开。upsert `user_module_prefs` → 失效缓存 → 返回新 `me()`（前端直接 `setUser`）。

### 管理侧

- **`GET /api/admin/modules`**（新增，`withAdmin`）：注册表 + `module_states` 合并视图（每模块 enabled/user_toggleable 生效值 + 按用户覆盖计数）。
- **`PATCH /api/admin/modules`**（新增，`withAdmin` + zod）：`{ module, enabled?, user_toggleable? }` → upsert `module_states` → 全清缓存 → `audit_logs` 记录。
- **`/api/admin/grants`**（扩展 `apps/api/src/app/api/admin/grants/route.ts`）：POST body 追加 `force_state?: 'on'|'off'|null`、`switch_visible?: boolean|null`；全空维度=清除该覆盖（删除行或清列），落 `user_module_controls` upsert/delete → 失效该用户缓存 → 审计。DELETE 保留（=清除全部覆盖）。现 marketing-panel 的 POST/DELETE 调用改造后端到端兼容。

### 路由门禁补齐（`withModule` 推广）

`withModule/withModuleParams`（`apps/api/src/server/platform/http/route.ts`）签名不变，`ModuleKey` 放宽为注册表 key。包裹清单以注册表 `apiPrefixes` 为准，实施时逐条核对 `apps/api/src/app/api/` 目录（Phase 1 先试点）：

| 模块 | 已确认前缀（其余核对补齐） |
| --- | --- |
| people | `/api/contacts`、`/api/interactions`、`/api/reminders` |
| fitness | `/api/fitness`（其中 `/api/fitness/sleep` 叠加 `withModule('sleep')`） |
| finance | `/api/transactions`、`/api/accounts`、`/api/budgets`、`/api/finance-stats`（基础部分） |
| debt / trading | 现有 18 个 `withModule` 路由保持不变 |
| trade_review | 复盘页实际调用端点，实施时核对 |

**不门禁**：`/api/today`、`/api/feed`（聚合端点改为按模块过滤返回内容，见前端联动）、`/api/export`（保留全量导出，用户可取回关闭模块的数据）、`/api/auth/*`、`/api/admin/*`。
