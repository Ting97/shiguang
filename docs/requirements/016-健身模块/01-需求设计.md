# 016 · 健身模块:01 需求设计(2026-10-14)

## 一、背景与动机

用户在 `life/fitness` 维护健身调研与实践笔记(珠海半马破 2 · 2026-12-27 + 薄肌减脂增肌 · 2027-03),核心循环是「每日计划(佳明课表 + 力量安排)→ 执行 → 汇报 → 调整」。拾光作为个人经营系统(时间·目标·人际·财务 + AI 内核),目前只有时间块分类里的 'fitness' 活动标签,没有任何健身数据结构与 AI 能力。

本批新增**健身模块(fitness)**:以「计划」为中心,跑步/力量两个训练模块先行(可扩展),每模块挂目标与策略档案;每日计划经三种来源产生(粘贴导入 AI 解析 / 聊天助手生成(确认卡落地) / 手动);计划自动联动「今日行动」;执行后打卡记录实际与身体指标;助手获得健身只读查询工具成为「训练教练」。

## 二、用户故事

1. 我把佳明当日课表文字粘进 /fitness,AI 解析成结构化跑步计划,确认入库。
2. 我问助手「今天有间歇课,力量怎么排?」——助手查我的目标策略(调整协议)、近期执行、身体指标后按协议回答,并生成力量计划卡片(每个动作附练哪里/有什么好处);我点「保存」才落库。
3. 我选「明天练力量」,让助手生成明天的计划,卡片确认后保存。
4. 保存的计划自动出现在首页「今日行动」:力量课是父任务 + 每个动作一条子行动,跑步课单条;练完在 /fitness 打卡,行动自动完成。
5. 周一我录入晨重/腰围,趋势页看到体重/腰围曲线、配速趋势、训练热力格。
6. 助手能点评我的训练:「点评昨天训练」「本周跑量怎么样」「体重降得快不快」。

## 三、功能需求(FR)

### FR-A 训练模块与目标档案
- A1 模块目录:跑步(run)/力量(strength)先行,数据驱动可扩展(加行即扩)。
- A2 每模块至多一条活跃目标:标题、目标日、结构化 targets、基线、**strategy(阶段划分/周模板/动态调整协议/饮食目标与调整规则/监测口径)**。
- A3 基本情况档案:身高、基线体重/体脂、经验、器械、每周可练天数、约束。

### FR-B 每日计划
- B1 一天 × 一模块一条计划,状态机 draft → confirmed → done/partial/skipped。
- B2 来源三通道:**粘贴导入(AI 解析成结构化草稿)** / **助手生成(经确认卡)** / 手动建。
- B3 跑步计划结构:课型(间歇/节奏/长距离/轻松/恢复)+ 分段(距离/配速/心率区间)+ 备注;力量计划结构:动作引用动作库 + 组×次 + 重量 + RIR。
- B4 create-or-replace 草稿语义;与已 confirmed 及之后的计划冲突 409。

### FR-C 聊天助手:查询 + 生成闭环
- C1 只读工具 5 个:日计划、执行记录、身体指标(序列+周均变化)、目标策略、动作库(肌群+收益)。
- C2 提案工具 `propose_fitness_plan`:助手把结构化计划以**提案卡片**呈现(仅限今天/明天),不直接写业务表——**REQ-015 规划的 A.5「操作意图确认卡」机制首个落地**。
- C3 卡片交互:保存 → 调 fitness 域既有 POST /api/fitness/plans 落草稿(触发今日行动联动);放弃 → dismiss;冲突如实展示。
- C4 系统提示词补「健身教练」节:先查工具、按 strategy 调整协议安排、建议克制。

### FR-D 今日行动联动
- D1 单一规则:**计划存在且未 skipped → 行动始终与计划同步**。
- D2 力量课=父任务 + 每动作一条子行动;跑步课=单条行动;due_at=计划日,与首页今日行动同口径;活动分类挂「健身」。
- D3 打卡 done/partial → 关联行动自动完成;计划编辑 → 未完成行动按最新内容重建;skipped → 清理未完成行动。

### FR-E 执行打卡与身体指标
- E1 计划卡上标记完成 + 填实际(跑步:距离/时长/配速/心率;力量:各动作实际组次;通用:疲劳 1-10/睡眠/酸痛/备注)。
- E2 身体指标按日录入(体重/腰围/体脂/静息心率),一周一条(周一晨起口径)。

### FR-F 动作库
- F1 全局种子动作库(~35):力量动作(课 A/B/C 全套 + 渐进变式)+ 跑步课型;每条含主/副肌群、器械、难度、**benefit(练哪里/有什么好处)**、默认组次模板。
- F2 /fitness 动作库页浏览(按模块筛选);助手可检索用于推荐展示。

### FR-G 趋势回看
- 体重/腰围折线、配速趋势(越低越好)、训练热力格;计划 vs 实际对照的日志视图。手写 SVG,零新依赖。

## 四、验收标准(AC)

1. 粘贴佳明课表文本 → 解析出的草稿结构与原文一致(课型/分段/配速),确认后入库且首页今日行动出现对应行动。
2. 聊天「今天有间歇课,力量怎么排?」→ 助手回答引用目标策略与近期执行;生成的计划卡片含动作肌群收益;点保存后 GET /api/fitness/plans 可见、今日行动联动;点放弃则无任何业务数据写入。
3. 打卡 done 后关联行动自动完成(首页今日行动打勾)。
4. 助手在未确认前不能写任何 fitness 业务表(propose 工具只写 chat_proposals)。
5. 越权隔离:用户 A 的计划/记录/指标/提案用户 B 一律不可见。
6. 单位换算正确:距离米、配速秒/公里、体重克、腰围毫米、体脂×10。
