### 3. 冒烟中暴露并修复的问题（6 轮实调迭代，均已回归）

1. **chatAgent 空回复**：AI SDK `res.text` 只含最后一步，模型在发起工具调用同一步写完说明后末步无文本 → 改为累积各步非空文本（packages/ai/glm.ts）。
2. **propose 工具 500**：AI SDK 按 `parameters` 预校验实参，嵌套/条件必填结构 glm-4-flash 极易写错（漏传明细/`reps` 简写），`InvalidToolArgumentsError` 直接打穿循环 → 参数**扁平化**（exercises/segments 顶层数组）+ 严格校验挪进 execute（错误经 chatAgent 包装成 `{error}` 回传模型自纠，实测被拒后模型重调成功）。
3. **字段别名归一**：`reps→repsText`、`weight→weightKg`、`pace→paceText`、课型中文（节奏/间歇…）→ 枚举，归一后再校验。
4. **maxSteps 5→7**：查目标→查动作库→提案→被拒重调→总结 的链路 5 步会截断。
5. **空回复兜底**：sendMessage 对整轮空文本落一条可读提示，避免前端空气泡。
6. **rangeOf 止界差一天（存量 bug，全区间工具受益）**：`nextStr` 用 UTC 切片违反「北京时间 +8h 再取日期」纪律，`to` 当天永远漏查 → 改 `bjAddDays`；健身三工具去掉 SQL 内重复 `+1` 并回传真实 from/to；流水汇总 `::bigint`→Number。
7. **chat-tools 种子幂等 + 日期方向**（存量）：多语句 DELETE 拆 for 循环（node-pg 预编译不支持多命令）；`now-8h` 方向写反改 `+8h`。
