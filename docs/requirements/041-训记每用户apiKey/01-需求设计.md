# 041 · 训记 apiKey 每用户绑定 · 需求设计

> 状态：开发中 · 2026-10-23 · 前置：017（训记同步）、022/023（动作名对齐）、041 前部署级 key 语义

## 背景与目标

训记 Open API 的 key 是**账号级**凭据——谁的 key 就读写谁的训记账号。此前拾光只配部署级唯一 `XUNJI_API_KEY`（.env，运营者 15091587905 的账号）：其他用户点同步会把训练写进运营者账号，助手查询读的也是运营者实练（因此 sync/pull/查询全部 admin 收口）。

用户要求（2026-10-23）：训记同步功能需要**用户自己配置自己的训记 apiKey** 才可使用；配置入口放【我的】；线上现有 key 直接配到 15091587905 名下。

## 需求清单

| # | 需求 | 验收 |
| --- | --- | --- |
| FR-A1 | 【我的 → 训记同步】配置卡：绑定/更换/解绑自己的训记 apiKey；绑定前即时远端校验（坏 key 当场报训记原因不落库）；key AES-256-GCM 加密存储、界面只显脱敏形式 | 假 key 绑定报「apikey 无效」；绑定后显示 `xjl***888` 类掩码 |
| FR-A2 | 用户数据操作严格走本人 key：同步计划/回读打卡/助手查询训记，未绑定一律拒绝并提示去【我的】配置；解除 sync/pull/查询的 admin 限制（数据各归各账号，无泄露面） | 普通用户绑定后可同步；未绑定得 403 文案引导 |
| FR-A3 | 部署级 `XUNJI_API_KEY` 降位为**目录快照专用**（公共参考数据，动作名对齐照常）+ 测试兜底；不再作为用户数据操作的凭据回落 | 未绑定用户保存计划时动作名对齐不受影响 |
| FR-A4 | 线上存量 key 迁移：部署后把现 env key 以加密形态 seed 到 15091587905 用户名下，其既有使用体验不变 | 该用户同步/回读无需再手动绑定 |

## 边界与非目标

- 不做多 key/多训记账号（一用户一把，后绑覆盖前绑）。
- 目录快照（REQ-022 分层缓存）维持部署级：公共动作库与个人账号无关，避免每用户各拉一份 1222 条目录。
- 不改动训记侧任何语义（别名表/确认映射/幂等 localid 逻辑不变）。

## 决策记录

1. **严格模式（不回落 env key）**：回落会造成「未绑定用户静默写入运营者账号」——正是本批要消灭的语义。
2. **新表 `user_integration_keys` 而非复用 `user_exchange_keys`**：后者 secret/passphrase 非空不适配；新表 `(user_id, provider)` 主键为后续集成留位（openGym 配对 token 见 docs/16 调研报告 §四）。
3. **加密复用 `EXCHANGE_ENC_KEY`**：与交易所凭据同一密钥同一格式（iv12+tag16+密文 base64），不新增 env；key 整体视为秘密（连明文形态都不落库）。
4. **读缓存按 key 指纹分桶**：训记 90s 按日读缓存原以 datestr 为键——多账号后必须隔离，缓存键改 `sha256(key)前8位:datestr`，防 A 账号数据串给 B。
