# 需求管理（Requirements）

> 本目录是「拾光」需求管理的唯一入口。自 2026-09 起，所有新功能统一走以下流程。

## 流程

```
需求设计 ──► 开发设计 ──► 开发 ──► 测试与部署
(01-需求设计.md)  (02-开发设计.md)   (按 02 实施)   (03-测试与部署.md)
```

每个需求包一个目录 `NNN-名称/`，按阶段依次产出文档：

| 文件 | 阶段 | 何时创建 | 内容 |
|---|---|---|---|
| `01-需求设计.md` | 需求设计 | 需求提出时 | 背景、用户故事、功能需求（FR）、边界、验收标准（AC）、非目标 |
| `02-开发设计.md` | 开发设计 | 开工前 | 数据模型、API 契约、AI 管线改造、前端方案、迁移清单、分批计划、风险（必须基于仓库真实文件路径） |
| `03-测试与部署.md` | 测试与部署 | 进入测试阶段时 | 测试记录、回归结果、部署批次记录、线上验证 |

约定：

- **先设计后动手**：`01`、`02` 完成并确认后才开始写代码；开发中发现设计偏差，先回写设计文档再改代码。
- 文档头部必须有「状态」标记（草稿 / 已确认 / 开发中 / 已部署 / 已归档）与版本日期。
- 数据库变更必须落 `packages/db/migrations/`，迁移编号在设计文档中预分配，实际以合并后顺延为准。
- 需求包内的阶段状态同步更新到下方索引表。
