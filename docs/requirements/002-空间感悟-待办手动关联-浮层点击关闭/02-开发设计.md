create table if not exists public.space_reflections (

## 4. N2 空间感悟

### 4.1 API

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/spaces/[id]/reflections` | GET | `?limit=20&offset=0` 倒序列表。返回 `{ items: [{ id, preview, chars, created_at, updated_at, edited }], total }`——`preview = left(content, 300)`、`chars = char_length(content)`、`edited = updated_at > created_at`；**不返回全文**（长列表性能） |
| `/api/spaces/[id]/reflections/[rid]` | GET | 全文 `{ id, content, created_at, updated_at }`（编辑/展开时拉取） |

| `/api/spaces/[id]/reflections/[rid]` | PATCH | `{ content }` 同校验；`updated_at = now()`；属主校验（404） |
| `/api/spaces/[id]/reflections/[rid]` | DELETE | 属主校验后硬删 |

- 5 万字 JSON body ≈ 150~200KB UTF-8，Next Route Handler 无默认 body 限制（现状 asr 路由 15MB 自管上限先例），不需要额外配置。

## 5. N3 浮层点击空白关闭

### 5.1 公共实现（新建 `apps/web/src/components/dismissable.tsx`）

```tsx
// 钩子：挂载后生效，监听 pointerdown（浮层外）与 Escape
export function useDismiss(onClose: () => void, active = true) {
  const ref = useRef<HTMLDivElement | null>(null);
  useEffect(() => {
    if (!active) return;
    const onDown = (e: PointerEvent) => {
      if (ref.current && !ref.current.contains(e.target as Node)) onClose();
    };
    const onKey = (e: KeyboardEvent) => { if (e.key === "Escape") onClose(); };
    document.addEventListener("pointerdown", onDown);
    document.addEventListener("keydown", onKey);
    return () => { document.removeEventListener("pointerdown", onDown);
                   document.removeEventListener("keydown", onKey); };
  }, [onClose, active]);
  return ref;
}

// 组件包装：<Dismissable onClose={...} className="...">浮层内容</Dismissable>
export function Dismissable({ onClose, className, children }: {...}) { ... }
```

实现约定：

- **时序安全**：effect 在打开事件的渲染提交后挂载，打开浮层的那次 pointerdown 已派发完毕，不会误关；统一用 `pointerdown`（比 click 早，手感更快）。
- **嵌套浮层**：子浮层必须渲染在父浮层 DOM 子树内（`contains` 自然豁免）；无法同子树时（如 fixed 独立层）由打开方在打开 B 时先关闭 A——同层互斥，全站一次只开一个同级浮层。
- **取消语义回调**：`onClose` 由调用方定义——编辑器传「收起 + 有改动则 toast」，菜单传纯关闭，确认框传取消分支。
- **抽屉类**（publish-sheet / reflection-editor）：Dismissable 包裹抽屉本体，点击遮罩区域即命中浮层外 → 关闭，语义统一。
- body 滚动锁定沿用各抽屉现状（已有则不动）。

## 8. N6 设计：行动解耦与今日行动直接添加

### 8.1 模型变更（`packages/db/migrations/027-action-kind.sql`）

现状：行动 = 有父的子待办（`parent_todo_id` 非空），不能独立存在；首页今日清单只读。目标：行动成为一等公民——可无父独立存在，todo 与行动的父子关系变为**可选**。

```sql
alter table public.todos add column if not exists kind text not null default 'todo'
  check (kind in ('todo','action'));
-- 存量回填：现有子待办即行动（幂等）
update public.todos set kind = 'action'
 where parent_todo_id is not null and kind <> 'action';
create index if not exists idx_todos_user_kind on public.todos (user_id, kind);
```

| 行形态 | kind | parent_todo_id | 说明 |
|---|---|---|---|
| 顶层 todo | `'todo'` | null | 现状不变 |
| todo 的行动 | `'action'` | 非空 | 现状不变，可多个（FR-N6.3） |
| **独立行动（新增）** | `'action'` | null | 无父；**天然继承"顶层行"的既有全部能力**（⭐重要/☀️今日标记、due、每日重复 + 计数、完成、AI 拆解），无需任何新列 |

关键取舍：独立行动走"顶层行 + kind 标识"而非新表——现有"标记仅限顶层"约束、06:00 惰性恢复、同记录日计数去重、remind_at、note 全部按行级逻辑自动覆盖。

### 8.2 API 变更

- **POST /api/todos**：body 增 `kind?: 'action'`（缺省 `'todo'`）。`kind='action'` 时不传 parentId；首页创建由客户端显式传 `today: true`（服务端不隐式默认，保持 API 语义单一）。
- **parentId 校验收紧**：父必须顶层**且 `kind='todo'`**（禁止把行动挂到独立行动下——"行动之下不再有行动"继续成立）；pending 校验沿用。
- **GET /api/todos**：
  - `all/important/today/done`：顶层行查询从"顶层 todo"扩展为**全部顶层行**（todo + 独立行动），行数据带 `kind`；四视图计数徽标 SQL 同步改为计顶层行。看板中独立行动带「行动」徽标，其余交互一致。
  - `today-actions`：见 §8.3。
- **PATCH**：无结构变更（独立行动是顶层行，⭐/☀️/due/repeatDaily/done 全部沿用；done 计数与 06:00 恢复均按行级 repeat_daily 生效）。
- **POST /api/todos/[id]/decompose**：节点类型判定由 `parent_todo_id` 改为 `kind`——

  | 节点 | 行为 | 插入位置 |
  |---|---|---|
  | 顶层 todo | ≤10 个行动挂其下（尾部追加/重新生成，mode 机制不变） | 子行动 `sort = max+1..` |
  | 行动（有父） | ≤3 个同父行动插入其后 | 兄弟行动 sort 平移（001 §5.4 算法） |
  | **独立行动（无父）** | ≤3 个**独立行动**插入其后 | 平移范围圈定 `parent_todo_id is null and kind='action' and sort > S` |

  prompt 不变（"行动细化为更小行动"语义一致，产出与锚点同形态）。
- **空间**：独立行动可 `PATCH spaceId`（§3.1 已同步）；AI 识别产物仍 `kind='todo'`，AI 不直接产生独立行动。
- **删除**：独立行动物理删除（现有 DELETE 沿用）；todo 级联删行动不变。

### 8.3 今日行动清单 v2

```sql
select a.*, p.title as parent_title, p.due_at as parent_due
  from todos a left join todos p on p.id = a.parent_todo_id
 where a.user_id = $me and a.kind = 'action'
   and ( a.repeat_daily                                             -- ① 重复行动（有父/独立）
      or a.today_tag_date = BJ_TODAY                                -- ② 独立行动标记今日
      or (a.due_at at time zone 'Asia/Shanghai')::date = BJ_TODAY   -- ② 独立行动今日到期
      or p.today_tag_date = BJ_TODAY                                -- ③ 父待办标记今日（现状）
      or (p.due_at at time zone 'Asia/Shanghai')::date = BJ_TODAY ) -- ③ 父待办今日到期（现状）
 order by p.due_at nulls last, a.sort, a.created_at
 limit 200;
```

`left join` 后独立行动 `parent_title/parent_due` 为空——出参结构不变，`TodayActionItem.parentTitle` 改可空，前端不渲染父上下文行即可。

### 8.4 前端

- **`actions-today.tsx`**：
  ① 顶部加「添加行动」行（复用 todo-board 添加行视觉：假空心圆 + 输入 + 回车保存），提交 `POST {title, kind:'action', today:true}` 后乐观插入列表；空输入不提交；
  ② 行渲染：独立行动不显示父上下文行，勾选圆圈/×N 次数/🔁 徽标/dueTag 与有父行动一致；
  ③ 行 hover 操作组（`row-actions` + `hover:none` 常显）补：✏️ 编辑（复用行内编辑器 + Dismissable）、🗑 删除（confirm）、🔁 重复开关。
- **`todo-board.tsx`**：顶层行按 `kind` 渲染「行动」徽标（`TagChip` slate，位于标题前）；独立行动行无"添加行动"入口（服务端同拒）；✨ 拆解按钮对独立行动即"拆解行动"（现有按节点分流的调用不变）。
- **`packages/shared/src/types.ts`**：`TodoRow` 增 `kind: 'todo' | 'action'`；`TodayActionItem.parentTitle?: string | null`。
- **Expo**：不动（动态卡片 `{n} todo` 徽标语义不变）。

### 8.5 与既有规则的兼容核对

| 既有规则 | N6 后 |
|---|---|
| 行动之下不再有行动 | parentId 校验"父必须 kind='todo'" + 看板独立行动行无添加入口，继续成立 |
| ⭐/☀️ 仅限顶层 | 独立行动 = 顶层行，可标记；有父行动仍随父，不变 |
| 每日重复 06:00 惰性恢复 | 按 repeat_daily 行级生效，独立行动自动覆盖 |
| 同记录日完成计数去重 | 行级逻辑，不变 |
| 删除 todo 级联删行动 | 不变；独立行动直接删 |
| AI 拆解插入式 sort | 独立行动锚点插入平移仅圈定"无父且 kind='action'"，顶层 todo sort 恒 0 不受扰动 |
| N1 空间关联 | 有父行动 409、独立行动允许（§3.1 已同步） |
