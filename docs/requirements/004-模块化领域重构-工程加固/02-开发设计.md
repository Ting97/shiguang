## 1. 现状架构分析

### 1.3 结构性问题（重构靶点）

1. **无边界**：`lib/` 是公共下水道——`analyze.ts` 同时懂 SQL、识别编排、审计；`debts.ts` 与 route 内 SQL 混排；跨域写（confirm）与跨域读（review-ctx 读 8+ 张表）无声明。
2. **无分层**：route = controller + service + repository 三合一，测试只能整链路打。
3. **重复见 01 §11**：95 处鉴权模板等。
4. **前端无数据层抽象**：双轨 fetch、无会话 hook、巨型组件自管一切。

**依赖规则**（新增 ESLint `no-restricted-imports` 强制）：

1. `app/api/**` 只准 import `server/<domain>/index` 与 `server/platform/*`。
2. 域间只准 import 对方 `index.ts`（service 面）；违者 lint 报错。
3. `repo.ts` 是 SQL 唯一发生地；`service.ts` 是事务唯一发生地（用 `withTx`）。
4. `insight/repo.ts` 允许跨域 SELECT，但表清单集中写在 `insight/reads.ts` 顶部声明，评审一目了然。
5. `packages/ai` 保持纯包（无 DB 感知），DB 编排仍在 `server/ai`。

## 3. API 基座设计（FR-A1/A2）

### 3.1 高阶路由封装

```ts
// server/platform/http/route.ts（骨架）
type Handler<C> = (req: NextRequest, ctx: C & { user: AuthUser; log: Logger }) => Promise<Response>;

export function withRoute(handler)            // try/catch → ApiError 映射 + 请求日志(含 requestId/userId/耗时/status)
export function withAuth(handler)             // getCurrentUser 失败统一 401 {error:"未登录"}，成功注入 ctx.user
export function withAdmin(handler)            // withAuth + role!=="admin" → 403
export function withAiQuota(cap: Capability)  // 包裹 AI 类 handler：统一 checkAiQuota + 402 升级话术 + audit 上下文
export function withSchema<T>(schema: ZodType<T>, pick: "body"|"query")  // 400 {error, code:"invalid_input", detail: z.flatten}
```

迁移示例（`PATCH /api/todos/[id]`，现状 238 行的 todos/route.ts 同族）：

```ts
// app/api/todos/[id]/route.ts（目标形态，≈15 行）
export const PATCH = withAuth(withSchema(todoPatchSchema, "body"), async (req, { user, params }) =>
  todoService.update(user.id, params.id, req.valid));
```

### 3.2 错误规范

```ts
class ApiError extends Error {           // status + code + detail
  static badRequest / unauthorized / forbidden / notFound / conflict / quota / upstream
}
```

- 现有 19 处手写 500 → `ApiError.upstream("依赖不可用", cause)`；SQL 错误统一映射 500 且日志带 cause（不外泄细节）。
- 响应体：错误统一 `{ error: string, code?: string }`——**与现状字段名兼容**（NFR-1），`code` 为新增字段。

### 3.3 配置集中（FR-A2）

`server/platform/config.ts` 启动期校验：必需 env 清单（DATABASE_URL、ZHIPUAI_API_KEY[若启用 AI]、SMS/SMTP[若启用通道]、JEV 相关）；生产拦截 `AUTH_DISABLED` 与弱口令默认连接串；导出类型化 `config` 单例，全仓禁止散读 `process.env`（lint 规则圈禁白名单文件）。

## 4. 逐域设计要点（FR-B1）

各域均为「schemas(zod) + service(事务/编排) + repo(SQL) + index(导出面)」同构四件套。仅列非显然决策：

**identity**
- `CodeChannel` 接口：`send(target) / verify(target, code) / throttleKey(target)`；`SmsChannel`、`EmailChannel` 两实现收敛 143+107 行同构逻辑（限流 60s/日 10 条入接口默认实现）。
- 新增：登录限流/锁定（读 §5.2 的 034 表）、`logoutAll(userId)`、会话列表查询（为全端登出 UI）。
- setup 走 platform 颁发的一次性令牌（§5.4）。

**timeline（核心域）**
- `parseService.ingest(user, text, images)`：先落 entries 秒回；识别后台任务从「内存 Promise」改为「识别登记（entry_recognitions 状态机 pending→done/failed）+ 启动/定时巡检补跑 failed」（消除进程重启丢失，FR-C2.4）。
- `recognitionService.confirm(entryId, domain, payload)`：编排器，事务内依次调 `time/timeBlock.confirm`、`goal/todo.confirm`、`finance/transaction.confirm`、`people/interaction.confirm`——各域 service 提供 `confirmXxx` 幂等接口，失败各自回滚（整体一个事务，由编排器 `withTx` 持有）。
- 图片/voice_logs/饮食记录归本域 repo；文件字节存取调 platform/storage。

**time / goal / finance / people（支撑域）**
- 四域以 CRUD + 少量领域规则为主（blocks 重叠检测、todos 日切恢复、spaces 上限 20、负债模拟纯函数）。负债模拟 `debts-sim.ts` 为纯函数直接随 finance/debt 迁移并补单测。
- `finance` 下分 `finance/transaction/`、`finance/debt/` 两子目录，对外仍是同一 service 面。
- CSV 导入（shared/csv-import 已纯函数化）留在 finance service。

**insight（CQRS 读侧）**
- `reads.ts` 顶部集中声明可读表清单（entries/time_blocks/todos/transactions/contacts/interactions/goal_spaces…），repo 查询不得越清单。
- review 四档装配（review-ctx/review-input 拆为 `assembler.ts` + `quota.ts`）；`today/reminders` 是纯读模型聚合。
- 依赖 ai 域的 `generate(capability, input)`，不直接碰 packages/ai。

**ai（内核编排域）**
- `capability 注册表`：17 个 PromptKey + 输入装配（ai-inputs）+ 传输调用三合一——service 面对外只暴露 `run(capability, ctx)`（内部完成 prompt 解析 → 输入装配 → provider 调用 → audit）。
- jev-shadow、ai-mode、admin prompts 三个管理面挂在本域；audit_logs 写入改为「重试一次 + 结构化错误日志」（FR-C3.1）。

**platform**
- invites/grants/billing/files/export/静态托管收口；新增 `health.ts`（§8.3）；`modules.ts`(模块授权) 归此。

### 5.2 迁移 034（预分配 `034-login-guard.sql`）

```sql
create table if not exists public.login_attempts (
  id bigserial primary key,
  identity text not null,            -- 手机号或邮箱（小写归一）
  ip inet, success boolean not null, created_at timestamptz not null default now()
);
create index if not exists idx_login_attempts_identity_time
  on public.login_attempts (identity, created_at desc);
```

锁定状态查 `count(*) where success=false and created_at > now()-interval '30 minutes'`；达到 20 次则 423/429 拒绝并通知（复用 identity 的通道抽象发信）。IP 维度用进程内滑动窗口（单机部署成立；多实例时换 pg 实现，注释注明假设）。

### 5.3 CSRF 决策记录

不引入 double-submit token（需改全部写路由与前端，收益/成本差）；采用 **Origin + Sec-Fetch-Site 硬校验**：现代浏览器 100% 带 Sec-Fetch-Site；老 UA 回退 Origin 白名单（与 shared/cors 同源配置）；两者皆缺 → 拒绝写请求。与现有 SameSite=Lax 叠加后满足 ASVS 对 CSRF 的要求。

### 5.4 迁移 035（`035-schema-migrations.sql`，runner 自举）

```sql
create table if not exists public.schema_migrations (
  filename text primary key, applied_at timestamptz not null default now(), checksum text
);
-- runner 启动时把已存在的 001~033 按 mtime 序回填（标记 backfilled），此后增量执行
```

`npm run db:migrate`（tsx 脚本 `packages/db/runner.ts`）：读目录 → 对比记录表 → 事务执行未跑文件 → 写记录；`--dry-run` 与 `status` 子命令；checksum 变更即报错（防手改已上线迁移）。

### 6.2 迁移要点

- `chat()` → `generateText({ model, system, messages, maxTokens })`：`onUsage` → SDK 的 `usage` 返回字段；`reasoning_effort=low` 经 provider 参数透传。
- `extractJson()` + 「带错误清单重问一次」→ `generateObject({ schema })` + 应用层 repair-reask（保留现有 v2 契约重问逻辑，只换底层）；`analyze.ts` 的 `extractJsonLoose` 删除，统一走 `extract()`。
- **等价性验证**：`npm run poc`（poc-20.json）与 testset 对照基线 `poc-glm-baseline.json`，一致率不降才切；迁移批次内保留 `GLM_TRANSPORT=legacy` 环境开关一个版本周期（旧 glm.ts 暂存 `_legacy/`），出问题改 env 即回退，下批次删除。
- 429/限流判定：以 SDK 抛出的结构化错误（APICallError.status）替代 `String(e).includes("HTTP 429")`。
- 熔断 `quotaTrippedAt` 提取为 `CircuitBreaker` 可注入实例（单进程默认内存实现；接口留给未来 Redis 实现）。
- ASR：`transcribeAudio` 保留自研 multipart（SDK 不覆盖 GLM-ASR），补 2 次重试 + 30s 总预算 + 失败计入 audit（stage=asr 已有口径）。
- 时区：`jev-shadow` 的 `nowCst`/`hourBucket` 统一改用 `packages/shared/src/date.ts` 的北京时区纯函数（消除"本地 getter 二次 +8"），新增跨时区单测（`TZ=UTC` 与 `TZ=Asia/Shanghai` 各跑）。
- 规则引擎：`PEOPLE_RE` 演示人名移除；兜底改为「调用方传入 contacts 名单」（analyze 已有 contactList 装配，直接复用），空名单时规则引擎不产人物。
- zod 版本对齐：AI SDK 经 Standard Schema 兼容 zod 3/4；若所选 SDK 大版本要求 zod 4，`schema.ts` 随批次一次性升级（monorepo 内 zod 仅 packages/ai 在用，影响面可控）。

apps/web/src/shared/
  api/hooks.ts     # useApi(key, fetcher)：loading/error/refresh + 竞态防护；实现不引库（40 行内），
                   #   若批次中发现 5+ 页面需要缓存/重验证，再评估 SWR（决策点写入 03 文档）
  session.tsx      # SessionProvider + useSession()：me 拉取/401 统一跳转/登出清理（唯一跳转点）
  ui/              # Toast、Banner、Modal、ErrorBoundary、Skeleton（收编 15 处横幅模式）
```

- 112 处裸 fetch → `api()`：机械迁移（保留同域相对路径语义）；`client-api.ts` 的 `api<T = any>` 默认泛型收紧为 `unknown`，调用点补类型（来自 packages/shared types 或新 zod 推导）。
- 根布局挂 `ErrorBoundary` + `SessionProvider`；401 只在 `api()` 拦截器与 `useSession` 两处出现。

### 7.2 巨型组件拆分（4-G）

统一手法：**按视觉区块拆组件 + 按数据域拆 hooks**，每文件 ≤300 行。以 `spaces/[id]/detail.tsx`(1258) 为例：

  use-space-detail.ts      # 取数+状态机（进度/待办/行动/动态流四组）
  progress-panel.tsx  todo-section.tsx  action-section.tsx
  reflection-list.tsx  moment-section.tsx  edit-dialog.tsx
```

其余按同法：`finance/page.tsx`(952) → accounts/transactions/budget 三区；`moment-feed.tsx`(922) → feed-list + moment-card + group-divider + conflict-banner；`todo-board.tsx`(875) → board/列/卡片/就地编辑；`page.tsx`(753) → workbench(日环/今日行动/提醒) + publish-box(文字/语音/拍照状态机)；`admin-ai-panel.tsx`(691) → prompt-list/editor/version-history/optimize-panel；`finance/debt/page.tsx`(650) → maturity-wall/archive/simulator/curve。

- 回归基线：`docs/experience/shots` 现有截图 + 每批新增关键页截图；行为断言靠 4-F 建立的路由冒烟（前端路由参数 `?tab=` 直达等）。
- 目录迁移：`src/components` 业务组件随域迁 `src/features/<域>/`，仅通用件留 `shared/ui`。
