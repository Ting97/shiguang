## 1. 现状基线

- **已上线的 prompt 管架**（001 R4，migrations/025）：`ai_prompts(key, content, enabled, remark, updated_by, updated_at)` + `ai_prompt_versions(id, key, content, restored_from, created_by, created_at)`；读取在 `apps/api/src/lib/prompts.ts`——`getPrompt(key)` 按 `ai_prompts(enabled) → 代码默认` 回落，60s 进程缓存、PUT 保存即失效；16 个 key 注册（extract_full / 六单域 / review 四档 / profile_merge / space_classify / todo_decompose / action_decompose / prompt_optimizer）。
- **user 侧装配现状**（全部硬编码）：`packages/ai/src/prompt.ts` 的 `buildExtractUserPrompt(text, nowCst, contactNames?)`（当前时间+分类对照+联系人名单+话术）、review 四路由自行拼 facts/明细（`withCap` 截断）/小结链（`fetchChainSummaries`）/画像块（`review-input.ts` 的 `loadProfileBlock`）、decompose 与 space_classify 的上下文注入（002 上线后位于 `apps/api/src/app/api/todos/[id]/decompose/route.ts` 与 `apps/api/src/lib/analyze.ts`）。
- packages/ai 为纯包（无 DB 依赖），DB 感知全部在 apps/api 层注入——本设计延续该边界。
- 迁移编号：022~028 已占用（028 = `028-child-kind-repair.sql`，002 遗留修复），A 部分用 **029**；B 部分（Jev）**零迁移**（audit_logs.stage 为自由 text，无 DB 约束；配额口径改代码）。

## 2. 数据模型（A 部分：`packages/db/migrations/029-ai-input-config.sql`，扩展已上线的 025 两表）

```sql
-- ai_prompts 加两列：user 模板覆盖 + 注入配置（均 null = 代码默认，向后兼容存量行）
alter table public.ai_prompts add column if not exists user_template text;
alter table public.ai_prompts add column if not exists context_config jsonb;
-- context_config 形态：{ "inject": { "catList": false, "profile": true, ... },
--                        "caps":   { "entryLines": 40, "contactNames": 50, ... } }
```

纯加列、幂等；上线即刻零行为变化（新列为 null → 代码默认）。

## 3. 输入注册表（新建 `apps/api/src/lib/ai-inputs.ts`）

代码内注册表定义每个 key 的**可调面**，后台只开放注册表内的项：

```ts
export interface InputSpec {
  userTemplate: string;        // 代码默认 user 模板（含占位符，如 {nowCst} {catList} {text}）
  placeholders: string[];      // 该 key 合法占位符全集（保存校验用）
  injects: Array<{ key: string; label: string; desc: string; source: string;
                   required?: boolean; default: boolean }>;
  caps: Array<{ key: string; label: string; min: number; max: number; default: number }>;
}
export const AI_INPUT_REGISTRY: Record<PromptKey, InputSpec>;
```

**各能力注入项注册表（首版盘点，基于已上线实现）**：

| key | user 输入构成 | 可调注入（默认开/必需） | 可调参数（默认） |
|---|---|---|---|
| extract_full | 当前时间 + 分类对照 + 联系人名单 + 用户话术 | 分类对照（开）、联系人名单（开）；时间/话术**必需** | 分类对照条数（50）、联系人条数（100） |
| extract_domain_schedule/todo/finance/mood/diet | 当前时间 + 用户话术 | —（仅 people 有名单）；时间/话术**必需** | — |
| extract_domain_people | 当前时间 + 联系人名单 + 用户话术 | 联系人名单（开） | 联系人条数（100） |
| review_day | 日事实聚合（必需）+ 动态明细 + 日程块明细 + 完成 todo 明细 + 画像块 | 三类明细各自开关（开）、画像（开） | 各明细行上限（现状 withCap 值） |
| review_week/month/year | 期事实聚合（必需）+ 各明细 + **下层小结链**（周←日/月←周/年←月）+ 画像块 | 明细开关、**小结链开关**（开）、画像（开） | 各明细行上限 |
| profile_merge | 旧画像 + 本月事实 + 本月复盘（全**必需**） | — | 画像条数上限（40） |
| space_classify | 候选空间列表 + 动态原文（全**必需**） | — | 候选空间上限（20） |
| todo_decompose | todo 标题+note（必需）+ 空间上下文 + 画像块 + 已有行动清单 | 空间上下文（开）、画像（开）、已有行动清单（开，去重依据） | 已有行动条数（30） |
| action_decompose | 行动+父 todo 上下文（必需）+ 空间上下文 + 画像 + 已有行动清单 | 同上 | 同上 |
| prompt_optimizer | key 用途+契约（必需）+ 当前内容（必需）+ 优化意图 | — | — |

## 4. 读取与装配（扩展现有 `apps/api/src/lib/prompts.ts`）

```ts
// 三件套读取：ai_prompts(enabled) 覆盖 → 代码默认；60s 进程缓存，PUT 主动失效（沿用既有机制）
export async function getPromptBundle(key): Promise<{
  system: string; userTemplate: string;
  config: { inject: Record<string, boolean>; caps: Record<string, number> };  // 合并默认值
}>

// 统一装配器：占位符替换 + 按开关/参数裁剪数据块
export function assembleUserPrompt(key, bundle, ctx: Record<string, unknown>): string
```

- **调用点接入**（替换硬编码 build 调用）：`apps/api/src/lib/analyze.ts`（extract_full / space_classify / decompose）、`entries/[id]/recognize`（单域）、review 四路由（明细 withCap 改读 caps）、`review-input.ts`（profile_merge；`loadProfileBlock` 受 inject.profile 控制）、decompose 路由。
- packages/ai 保持纯包：包内 `buildXxxPrompt` 保留为代码默认装配实现；apps/api 拿 bundle 后传入或覆盖。
- 关闭注入项：装配器按 `inject[key]` 跳过对应 ctx 块；明细类上限在 SQL LIMIT 生效（查询前读 caps，省 token 而非只截字符串）。

## 5. admin API（扩展现有 `/api/admin/prompts`）

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/admin/prompts` | GET | 清单响应扩展：`{ ..., userTemplate, userTemplateDefault, contextConfig, registry: InputSpec }`（注册表全文下发：占位符/注入项/参数范围，前端据此渲染） |
| `/api/admin/prompts/[key]` | PUT | body 扩展 `{ userTemplate?, contextConfig? }`；校验：模板占位符完整性（缺失/未知 → 400 列明）、caps 范围（min/max）、required 注入项不可为 false；保存写三件套快照 + 清缓存 |
| `/api/admin/prompts/[key]/restore` | POST | 回滚逻辑升级：优先取版本 `payload`（三件套），老版本（无 payload）仅回滚 system content |
| `/api/admin/prompts/[key]/preview` | POST | **装配预览**：body `{ sample?: string, period?: string }`（样例话术/复盘期段，缺省取管理员最近真实数据）→ 按**当前 bundle** 走与线上同一条 `assembleUserPrompt` → 返回 `{ userPrompt }`；**不调 LLM、零 token**；不落库，audit 仅记 `stage='prompt_preview'` 计数不记内容 |
| `/api/admin/prompts/[key]/optimize` | POST | 001 已上线，不变（优化的是 system；后续可扩展优化 user 模板，二期） |

## 6. /admin 前端（AI 管理详情页改三段）

1. **System prompt**：现状编辑器不变。
2. **输入装配**（新）：user 模板编辑器（等宽 textarea + 占位符高亮提示：注册表列全部合法占位符、当前模板缺失项标红 + 「一键补齐」）+ 注入项开关列表（label/desc/来源/required 锁定态）+ 参数数字输入（min/max 校验）+ **「装配预览」**：输入样例 → 右侧等宽面板展示最终 user 输入全文（与线上同构）。
3. **版本历史**：快照三件套展示（system/user/配置摘要），回滚整体恢复；启用开关关闭 = 整 key 回退代码默认。

保存一次提交三段（未改字段原样回传），走同一 PUT；沿用既有 403 门禁（`getAdminUser`）与 N3 浮层交互（002 已上线 Dismissable）。

## 7. B 部分：Jev 接入设计（三段式）

### 7.1 客户端（新建 `packages/ai/src/jev.ts`，保持纯包）

```ts
// 环境变量：TYPESAFE_API_KEY / TYPESAFE_BASE_URL(默认 https://api.typesafe.ai) / JEV_MODEL(默认 jev-latest) / JEV_MODE(off|shadow|on，默认 off)
export function jevEnabled(): boolean            // key 存在且 MODE≠off
export function jevMode(): "off" | "shadow" | "on"

// 三原语问题构造 helper（criteria 即闭集契约）
export const qChoice = (instructions: string, criteria: Record<string, string>) => ({ type: "choice", instructions, criteria })
export const qScore  = (instructions: string, criteria: string[]) => ({ type: "score", instructions, criteria })
export const qNoul   = (instructions: string) => ({ type: "noul", instructions })

// 一次调用并行问多题：POST {base}/v1/systemone，Bearer，5s 超时、2 次重试（网络/5xx）
// 响应 zod 契约：{ model, answers: Record<key, {choice?|score?|noul?, confidence?, probabilities?}>, usage }
export async function jevAsk(state: string, questions: Record<string, Question>): Promise<JevAnswers>
// 失败抛 JevError（network/timeout/auth/rate）——调用方决定降级，不内置熔断（Jev 位可随时回落）
```

审计约定：Jev 调用 `writeAuditRecord({ stage: 原stage 或 'jev_shadow', model: 'jev-latest', engine: 'jev', ... })`；`stage` 为自由 text 无需迁移。

### 7.2 问题组定义（闭集字段 → 三原语映射）

| 字段 | 问题 key | 原语 | criteria / 映射 |
|---|---|---|---|
| 日程适用 | `sched_applicable` | Noul | "这句话记录了带具体时间的日程/时间块安排" |
| todo 适用 | `todo_applicable` | Noul | "这句话包含已经做完或计划要做的待办" |
| 财务适用 | `fin_applicable` | Noul | "这句话包含花钱或收钱的行为" |
| 心情适用 | `mood_applicable` | Noul | "这句话表达了情绪或心情" |
| 饮食适用 | `diet_applicable` | Noul | "这句话提到了吃了什么" |
| 人物适用 | `people_applicable` | Noul | "这句话提到了具体的人"（人名本身由 GLM 抽） |
| 活动分类 | `activity` | Choice | criteria = 用户 activities 表动态生成（id→"名称+icon+一句描述"）——天然支持自定义分类 |
| 过去/未来 | `record_type` | Choice | `{ past: "描述已经发生的事", future: "描述计划/将要发生的事" }` |
| 时段 | `period` | Choice | 早晨/上午/下午/傍晚/晚上/凌晨（对齐现有 periodHint 枚举） |
| 心情强度 | `mood_intensity` | Score | ["很平静", "一般", "比较强烈", "非常强烈"] → 映射 mood_score 区间 |
| 财务方向 | `fin_direction` | Choice | `{ expense: "花钱/支出", income: "收钱/收入" }` |
| 财务分类 | `fin_category` | Choice | 财务分类枚举（餐饮/交通/购物…，与 GLM 同一映射） |
| 饮食餐次 | `diet_meal` | Choice | 早餐/午餐/晚餐/加餐/未知 |
| 空间归属 | `space_belongs` / `space_which` | Noul + Choice | "这条记录服务于某个长期目标吗"；Choice criteria = 候选空间 `{id: "名称：描述"}` + `__none__` 兜底项 |

金额数值、时间解析、日期锚定、kcal 求和——**维持确定性引擎**（duration.ts / time-infer.ts），不进 Jev。

### 7.3 三段式编排

**B1 PoC（`packages/ai/src/run-jev-poc.ts`）**：读 `testset/poc-20.json`（46 句）→ 逐句 `jevAsk` 问题组 → 与 GLM 基准（`npm run poc:live` 输出）逐闭集字段对照 → 输出报告（markdown：总准确率、分字段准确率、分歧样本清单）。达标线见 FR-B1。**产物报告存入本需求包目录**。

**B2 shadow**：`analyze.ts` 在 classifySpace / analyzeAndPersist 完成后（MODE=shadow）`void jevShadowCompare(...)` fire-and-forget——同题调 Jev、与已落库结果比对、`writeAuditRecord({ stage:'jev_shadow', ok: 一致, error: 差异摘要 })`。主流程零改动零阻塞。

**B3 接管（MODE=on）**：
- 空间分类：`classifySpace` 改走 `jevAsk`（`space_belongs.noul ≥0.5 && space_which.choice ≠ __none__ && confidence ≥0.7` → 写入；失败/不满足 → 现行静默跳过）。
- 五域混合引擎：`parseInput` 前置 Jev 问题组（闭集字段 + 各域 confidence=probabilities）→ GLM 走**瘦身 prompt**（新增 key `extract_open_vocab`：只输出 title/人名/饮食条目/时间原文等开放词汇）→ 合并层把两者拼成 FullExtractionV2 → 现行 mapAiResult/落库链路不变。Jev 失败 → 整体回落现行全量 GLM 路径（engine="llm"）→ 再失败 rules。`ParseResult.engine` 扩枚举 `"jev-hybrid"`（schema.ts zod + 前端 ⚠ 离线识别判断兼容——仅 "rules" 显示警告，新值无影响）。
- 瘦身 prompt 的启用与调优走 A 部分 /admin（版本管理可回滚），故 3-D 建议排在 3-A 后。

### 7.4 配额与成本口径（实现关键坑）

- 现状 `checkAiQuota` 统计 audit_logs **30 天全部行数不分 stage**——shadow 双跑会让每次识别记 2 行，直接烧穿 30 次/月配额。
- 修正：统计 SQL 加 `and model not like 'jev%'`（一行改动，向后兼容存量数据——存量无 jev 行）；`tokens/usage` 的 GLM 成本统计同样排除。

### 7.5 降级链（总览）

```
MODE=on：  Jev 问题组 ─失败→ GLM 全量(现行路径) ─失败→ rulesPipeline   （用户无感）
MODE=shadow：GLM 行为不变 + Jev 影子对比（仅审计）
MODE=off： 完全现状
空间分类：  Jev 失败 → 静默跳过（现行行为）
```

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 配置调错导致识别/复盘劣化 | 三件套整体回滚 + 启用开关秒切默认；预览零成本验证；required 锁定；cap 在 SQL LIMIT 层生效 |
| 代码占位符演进 vs DB 旧覆盖模板脱节 | 保存时完整性校验拦截 + 一键补齐；注册表为唯一事实源 |
| 逐能力接入的回归面大 | 接入顺序分小步，每步全量回归该能力；audit_logs 对比改造前后 token 用量 |
| 预览接口泄露个人数据 | 仅 admin 会话；结果不落库；日志只记计数 |
| Jev 中文判别力未验证 | B1 PoC 前置门 + B2 shadow 双门槛，任一不达标即止步归档 |
| Jev 厂商极新/价格变动 | 仅承担可降级的闭集判断位；GLM 全量路径永久兜底；`JEV_MODE=off` 秒退；月成本 ¥0.5 级 |
| key 泄露（已出现在聊天记录） | 接入前 console.typesafe.ai 轮换；仅服务器 .env；仓库 grep 验收 |
| 校准概率在中文上失效 | shadow 期统计"Jev 高置信但 GLM 不一致"比例，>5% 视为校准失效信号，不进接管 |
