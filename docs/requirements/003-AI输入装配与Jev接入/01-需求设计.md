## 1. 背景（A 部分：AI 输入装配管理）

一次 AI 调用的完整输入 = **system prompt**（001 R4 已可在 /admin 在线编辑、版本回滚）+ **user 输入**（模板 + 注入数据）。当前 user 侧全部硬编码在代码里，管理员看不到"每次调用到底把哪些数据给了模型"，更无法调整：

- 识别类（extract_full / 六个单域）：当前时间、分类对照表、已有联系人名单、用户话术；
- 复盘类（day/week/month/year）：当期事实聚合、动态/日程/完成 todo 明细行（有截断上限）、下层小结链（周←日、月←周、年←月）、用户画像块；
- 拆解类（todo/action_decompose）：todo/行动上下文、空间名称与描述、画像块、已有行动清单（去重依据）；
- 其他：profile_merge（旧画像+本月事实+本月复盘）、space_classify（候选空间+动态原文）、prompt_optimizer。

这些注入项直接决定**识别质量、token 成本与隐私面**（给模型多少个人数据）。本需求把它们在后台**透明化 + 可调**，并配零成本的"装配预览"验证手段。

## 2. 用户故事

- 作为管理员，我想知道"发一条动态后模型实际收到了什么"——在后台看到该能力完整的 user 输入构成，而不是猜。
- 作为管理员，我觉得复盘注入的明细行太多、token 花费大，我想把明细上限调小，或关掉画像注入试试效果。
- 作为管理员，我改完配置想先验证拼出来的输入长什么样，**不花 token** 地预览一次装配结果。

## 4. 功能需求（A 部分）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1.1 | 输入构成展示 | /admin AI 管理的每个 prompt key 详情扩展三段：**System prompt**（现状）/ **输入装配**（user 模板 + 注入项清单 + 参数）/ **版本历史**。注入项逐条展示：名称、作用说明、数据来源、当前开关、参数值、是否必需（必需不可关） |
| FR-1.2 | user 模板可编辑 | 每个能力的 user prompt 模板在线编辑（默认值 = 代码内置）；保存校验**占位符完整性**：必须包含该能力全部占位符、不得引入未知占位符，违规保存拒绝并提示缺失/多余项（前端提供"一键补齐缺失占位符"） |
| FR-1.3 | 注入开关可调 | 非必需注入项可开关：分类对照、联系人名单、画像注入、下层小结链、已有行动清单、空间上下文等（按能力注册表定义）；关闭后线上装配即不含该块 |
| FR-1.4 | 注入参数可调 | 数值参数在线调整：明细行截断上限（各复盘档）、名单条数上限、候选空间上限、已有行动条数上限等；min/max 范围校验；明细类上限在 SQL LIMIT 层生效（真正省 token） |
| FR-1.5 | 装配预览 | 详情页「装配预览」：可选粘贴样例（动态原文/todo 标题/复盘期段，缺省取管理员最近真实数据）→ 服务端按**当前配置**走与线上同一条装配逻辑 → 返回完整 user 输入展示；**不调用 LLM、零 token**；预览即所见即所得 |
| FR-1.6 | 生效与版本 | 三件套（system/user 模板/配置）同机制：保存即生效（≤60s 缓存、保存主动失效）；每次保存进版本快照，回滚整体回滚；关闭启用开关 = 整 key 回退代码默认 |
| FR-1.7 | 注册表约束 | 可调范围由代码内注册表定义（每 key 声明：默认模板、占位符清单、注入项及必需性、参数范围）；后台只开放注册表内的项，不支持自由增删注入源 |

## 5. 边界与异常（A 部分）

- 必需注入项（识别类"当前时间/用户话术"、画像合并三要素等）锁定不可关——关闭会破坏功能语义。
- 参数下限由注册表声明（多数为 0 = 不注入该块，或 1）；不设奇点默认值。
- 装配预览使用管理员自己的真实数据（分类、联系人、空间、最近明细），结果仅当前 admin 会话可见，不落库、日志不记内容。
- 028 为纯加列扩展（ai_prompts / ai_prompt_versions），存量行为空 = 代码默认，**上线即刻零行为变化**。
- 代码注册表将来新增占位符时，DB 中已覆盖的旧模板在下次保存时被校验拦截并提示缺失项——按提示"一键补齐"或回滚默认。
- 本需求不改各能力的 system prompt 现状能力（001 R4 已上线部分原样保留），仅在其上扩展。

## 6. 验收标准（A 部分）

- [ ] 每个 key 详情页可见 user 模板、注入项清单（说明/来源/开关/参数/必需性）
- [ ] user 模板可编辑；删占位符/加未知占位符的保存被拒绝并明确提示；一键补齐后可保存
- [ ] 关闭某注入项、调小某参数后：装配预览对应块消失/截断变化，且线上同口径生效
- [ ] 装配预览不产生 token 消耗（audit_logs 无新 LLM 调用记录）
- [ ] 保存后 ≤60s 生效；版本快照含三件套，回滚整体恢复；关闭启用开关整 key 回退代码默认
- [ ] 存量（未配置的 key）行为与当前线上一致（逐能力回归：识别/单域/复盘四档/拆解/空间分类）

## 7. B 部分·调研结论：Jev 是什么、能用在哪里

> 首轮调研见 [docs/10-技术调研-Jev决策模型详解](../../10-技术调研-Jev决策模型详解.html)（2026-09-19，结论"暂不接入、列观察清单"）。本轮（2026-09-22）已获取 API key、在线核实 API 形态，并按滚动吸收规则启动接入。

### 7.1 Jev 能力与 API（2026-09-22 在线核实）

- TypeSafe AI 公司的首个「System One 模型」（`jev-latest`）：**不生成任何文本**，只对输入 state 回答**闭集问题**，返回类型化答案 + **校准概率分布**（官方 RLCD 训练，宣称概率可信可设阈值）。
- API：`POST https://api.typesafe.ai/v1/systemone`，`Authorization: Bearer <key>`；请求 = `{ state, model, questions }`，三种问题原语——`choice`（选项选择）、`score`（有序等级评分）、`noul`（是非概率）；响应每问带 `confidence` 与全选项 `probabilities`；同一 state 的多问题**一次调用并行评估**（加问不增延迟）。
- 价格：输入 $0.042/M token、**输出免费**；官方口径单次判断约 $0.0004，比 LLM 快两个数量级（193.6×/444.6× 为厂商自测）。
- 限制：**无文本生成**（标题/摘要/复盘/追问全不能）；**开放词汇抽取不能**（抽不出"王智聪"这样的人名）；**多语言/中文支持官方未声明**——中文口语判别力无任何公开实测，这正是 B1 PoC 要回答的问题。

### 7.2 产品 AI 调用点适配矩阵（11 个调用点逐一判定）

| 调用点 | 现状（GLM） | Jev 适配度 | 结论 |
|---|---|---|---|
| **空间分类**（`analyze.ts` classifySpace，每次发布后一次 chat） | Choice 型判断 + 自报 confidence ≥0.7 才写入 | **完美**：Noul（是否归属某空间）+ Choice（候选空间列表）一次调用；校准概率直接当 0.7 阈值 | ✅ 首批接管 |
| **五域提取**（extract_full，发动态主链路） | 一次大 prompt 全字段输出 | **约六成字段完美**：各域适用性=Noul、活动分类=Choice（criteria 动态注入用户自定义分类）、过去/未来=Choice、时段=Choice、心情有无+强度=Noul+Score、财务方向/分类=Choice（金额数值本就由确定性引擎解析）、饮食餐次=Choice；**人名/标题/饮食条目等开放词汇=不能**（保留 GLM） | ✅ 混合引擎（Jev 闭集 + GLM 开放词汇） |
| 置信度来源（0.6 阈值 gating） | LLM 自报 confidence（不可靠） | Jev probabilities 校准，可整体替换置信度来源 | ✅ 随五域接管 |
| 单域重识别（entries/recognize） | chat 单域 prompt | 闭集部分同上（依赖混合引擎基建） | ✅ 随五域接管 |
| 规则兜底（rulesPipeline） | GLM 失败时的正则引擎 | 可作 GLM 与 rules 之间的第二降级层 | ⚪ 可选，暂不做 |
| 复盘四档（review day/week/month/year） | 生成 summary/highlights/suggestions | ❌ 生成任务 | 维持 GLM |
| 画像合并（profile_merge） | 生成 | ❌ | 维持 GLM |
| AI 拆解（todo/action_decompose） | 生成行动标题 | ❌ | 维持 GLM |
| prompt 优化（prompt_optimizer） | 生成优化稿 | ❌ | 维持 GLM |
| 联系人 AI 画像（ai-profile） | 生成 | ❌ | 维持 GLM |
| ASR（语音转写） | 专用模型 | ❌ | 维持 GLM-ASR |

### 7.3 价值与成本

- 直击两大既有痛点：**免费档晚高峰拥塞**（429 熔断时有发生，Jev 分流高频闭集判断）与 **LLM 自报置信度不可靠**（校准概率让 0.6/0.7 阈值真正有意义）。
- 成本：按 docs/10 估算月 1.7M 输入 token ≈ **¥0.5/月**，输出免费；双引擎不增加用户侧配额负担（配额口径见 FR-B3）。

### 7.4 docs/10「暂不接入」四条理由的复核

| 当时理由 | 现状 |
|---|---|
| ① 中文能力无实测佐证 | **仍未解决** → B1 PoC 作为前置门，不达标即止步归档 |
| ② 上线仅数日、依赖风险高 | 仍未消除 → 三段式 + GLM 降级链全保留 + `JEV_MODE` 一键关 |
| ③ 只覆盖六成字段、引入双引擎复杂度 | 接受复杂度（用户已选首批即含混合引擎），用编排层收敛 |
| ④ 拥塞痛点可用 GLM 付费档解决 | 付费档仍要钱、且置信度问题付费解决不了 → Jev 两者兼顾 |

## 8. 功能需求（B 部分：Jev 接入，三段式）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-B1 | **PoC 对照评测（前置门）** | 复用 `packages/ai/testset` 46 句真实测试集，把五域闭集字段改写为 Jev 问题组离线跑批，与 GLM 结果（poc:live 基准）逐字段对照。**达标线：闭集字段整体准确率 ≥ GLM×95%，且活动分类单独 ≥80%**；不达标则止步，结论归档进本包（不算失败，是复评结论落档） |
| FR-B2 | **shadow 影子模式** | 服务器 `JEV_MODE=shadow`：线上每次空间分类/五域识别后，fire-and-forget 用同题调 Jev，结果只写 `audit_logs`（stage='jev_shadow'，记一致/不一致），**用户行为零变化**；持续 ≥1 周统计一致率，**空间分类一致率 ≥90% 且五域闭集 ≥85%** 才进入接管 |
| FR-B3 | **接管（首批范围：空间分类 + 五域闭集）** | `JEV_MODE=on`：① 空间分类整切 Jev（Noul+Choice 一次调用，probabilities ≥0.7 写入）；② 五域提取改混合引擎——Jev 问题组出闭集字段与各域 confidence，GLM 瘦身 prompt 只生成开放词汇（标题/人名/饮食条目/时间原文），确定性引擎（时长/金额/日期锚定）不动；③ **checkAiQuota 口径修正：排除 model 为 jev\* 的审计行**（Jev 极廉不计用户配额，也防 shadow 双跑把 30 次/月配额烧穿）；④ 降级链保留：Jev 失败 → 现行 GLM 全量路径 → rules，用户无感；⑤ `ParseResult.engine` 新增 "jev-hybrid" 枚举，前端 ⚠ 离线识别 UI 兼容 |
| FR-B4 | 配置与安全 | env：`TYPESAFE_API_KEY`（仅服务器 `.env`，**永不入库**）/`TYPESAFE_BASE_URL`/`JEV_MODEL`/`JEV_MODE`（off/shadow/on，默认 off）；key 已在聊天记录中出现过，**接入前先在 console.typesafe.ai 轮换** |

## 9. 边界与异常（B 部分）

- Jev 无中文声明：PoC/shadow 两道门都是为此设的；任一门不达标即停，已上线部分可 `JEV_MODE=off` 秒退。
- 混合引擎下 GLM prompt 需瘦身改版（不再输出闭集字段）——prompt 变更走 A 部分的 /admin 版本管理，可回滚。
- Jev 调用超时 5s/重试 2 次后即降级 GLM，不阻塞发布主链路（空间分类本就异步静默）。
- 审计：Jev 行 `model='jev-latest'`，shadow 行不计配额也不计入 tokens/usage 的 GLM 成本统计口径。

## 10. 验收标准（B 部分）

- [ ] PoC 报告产出：46 句逐字段对照表 + 准确率汇总，达标线判定结论明确（达标/止步两出口均算验收通过）
- [ ] shadow 期间用户行为零变化（抽查动态归属与五域产物与 GLM 版一致）；audit 可统计一致率
- [ ] 接管后：空间归属抽检与 GLM 版一致率达标；五域闭集字段来自 Jev、开放词汇来自 GLM、confidence=probabilities
- [ ] Jev 不可用时自动回落 GLM 全量路径（断网/错 key 模拟），用户无感，audit 有降级记录
- [ ] 用户 AI 配额消耗不因 Jev 双跑/接管而增加（口径修正验证）
- [ ] `JEV_MODE=off` 一键回退全 GLM 行为
- [ ] 仓库任何文件 grep 不到 API key 明文

## 12. 风险

| 风险 | 对策 |
|---|---|
| 配置调错导致识别/复盘劣化 | 三件套整体版本回滚 + 启用开关秒切默认；装配预览零成本验证；必需项锁定 |
