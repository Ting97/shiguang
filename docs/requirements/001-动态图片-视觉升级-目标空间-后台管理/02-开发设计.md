## 2. 总体设计原则

1. **复用现有管线**：动态"先落库秒回 + 后台识别"、zod 严格契约 + repair 重问、`chat()` 容错链（重试/熔断/降级）、`audit_logs` 审计、`checkAiQuota` 配额——新能力全部挂靠，不另起炉灶。
2. **客户端做重活**：图片压缩在前端完成，服务端零图像依赖（不引 sharp）。
3. **packages/ai 保持纯包**：不依赖 DB；prompt 覆盖由 apps/api 层读取后注入。
4. **惰性日切**：每日重复的恢复在列表读取时触发（一条 UPDATE），与 session/套餐/今日标记的既有惯例一致，不引入定时任务。
5. **DB 变更全部走 migrations**，幂等可重复执行；编号预分配 022~025（021 尚未提交，实际以合并后顺延为准）。
6. **UI 不引第三方图标库**：emoji + 语义色 tinted chip；样式一律走 globals.css 既有令牌与 Tailwind 色板，深浅主题双验。

## 3. R1 图片上传设计

### 3.1 数据模型（`packages/db/migrations/023-entry-images.sql`）

```sql
create table if not exists public.entry_images (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references public.profiles(id) on delete cascade,
  entry_id    uuid not null references public.entries(id) on delete cascade,
  storage_key text not null unique,          -- "2026/09/<uuid>.jpg"
  mime        text not null,                 -- image/jpeg | image/png | image/webp | image/gif
  bytes       int not null,
  width       int,
  height      int,
  sort        int not null default 0,        -- 卡片内顺序
  created_at  timestamptz not null default now()
);
create index if not exists idx_entry_images_entry on public.entry_images (entry_id, sort);
```

`entries` 表不加列（避免 jsonb 行膨胀），图片走独立表。

### 3.2 存储与目录

| 环境 | 目录 | 配置 |
|---|---|---|
| 生产 | `/opt/shiguangri_data/uploads` | 服务器 `.env` 加 `UPLOAD_DIR=/opt/shiguangri_data/uploads` |
| 开发 | `apps/api/.uploads/`（gitignore） | 本地 `.env` 加 `UPLOAD_DIR`，缺省回落 `join(process.cwd(), ".uploads")` |

- key 规则：`{yyyy}/{mm}/{uuid}.{ext}`，写入 `mkdir recursive` + `0644`。
- **关键约束：目录必须在 `/opt/shiguangri` 之外**——双 tar 发布会整目录替换应用目录；`/opt/shiguangri_data` 不参与交换，`.env` 每次发布从旧目录复制，`UPLOAD_DIR` 天然延续。

### 3.3 API 契约

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/entries/[id]/images` | POST | `formData`，字段 `files`（多文件）。校验：`getCurrentUser` → entry 属主 → 单条含已有 ≤9 张 → 单张 ≤5MB → 魔数白名单（`FFD8FF`/`89504E47`/`RIFF..WEBP`/`GIF8`，参照 asr 路由 `sniffFormat`）。写盘 + 落库，返回 `{ images: [{id, storageKey, mime, width, height, sort}] }` |
| `/api/entries/[id]/images/[imageId]` | DELETE | 属主校验 → 删行 → 盘上文件 `void unlink`（异步，失败仅记日志） |
| `/api/files/[...key]` | GET | `getCurrentUser` → 按 `storage_key` 查 `entry_images`（无记录 404，`user_id` 不符 403）→ `fs.readFile` 流式返回：`Content-Type` 白名单映射、`Cache-Control: private, max-age=31536000, immutable`（uuid key 不可变）、ETag 走 304 |
| `/api/feed` | GET | 大 SQL 增加 lateral 聚合 `images jsonb`（id/storage_key/sort/width/height，按 sort 排序）；query 增加空间过滤（见 §5.2） |
| `/api/feed/[id]` | DELETE | 现有事务内追加：查 `entry_images` 删行，盘文件收集后异步 unlink |

前端图片 URL 统一 `/api/files/{storage_key}`；`packages/shared/src/types.ts` 的 `FeedMoment` 增加 `images?: FeedImage[]`。

### 3.4 客户端压缩与上传

- **Web**（新建 `apps/web/src/lib/image.ts`）：`compressImage(file)` —— `<canvas>` 重绘，长边 >1920 等比缩小，输出 `image/jpeg` quality 0.85（png 且含透明时保留 `image/png`）；返回 `{blob, width, height}`。无新依赖。
- **上传时序**：`publish()` → `POST /api/parse` 得 `entry.id` → `Promise.allSettled(images.map(f => uploadImage(entryId, f)))`；publish-sheet 保留失败项缩略图 + 重试按钮。文字动态不等图片。
- **Web UI**：桌面输入区与 publish-sheet 各加图片按钮 → 隐藏 `<input type="file" accept="image/*" multiple>`；移动端（`window.matchMedia('(pointer: coarse)')` 判定）额外提供"拍照"入口（`capture="environment"`）。已选图缩略条（可移除）。
- **Expo**：`npx expo install expo-image-picker expo-image-manipulator expo-image`；`src/api.ts` 加 `apiUploadImages(entryId, uris)`（复用 `apiUpload` 的 FormData 模式）；App.tsx 输入面板加「图片」「拍照」按钮（`launchImageLibraryAsync({ allowsMultipleSelection: true, quality: 0.85 })` / `launchCameraAsync`）；`expo-image-manipulator` resize 长边 1920；MomentCard 加 `expo-image` 九宫格。
- **展示**（`moment-feed.tsx`）：新建 `components/image-grid.tsx`（1 张 `max-w-[65%]` 大图 / 2-3 张横排 / 4-9 张 3 列网格，`<img loading="lazy">` + 失败占位）与 `components/image-lightbox.tsx`（fixed 全屏层 + 左右切换 + Esc/点击关闭，不引库）。

### 3.5 配套修改

- `[[...p]]/route.ts` MIME 表补 `.jpeg/.webp/.gif/.avif`（页面静态资源兜底）。
- `middleware.ts` 不动：`/api/files` 走既有 `/api` 401 逻辑，页面门禁不涉及。
- **部署增补（docs/08）**：① 创建 `/opt/shiguangri_data/uploads` 并 `chown` 运行用户；② 备份 cron 追加 `tar czf /root/backup/uploads-$(date +%F).tgz /opt/shiguangri_data/uploads`；③ `.env.example` 加 `UPLOAD_DIR` 注释。
- **Expo 发版注意**：expo-image-picker 属原生能力变更，**必须走 EAS build 出 v1.1.4**（Android 13+ 相册走 photo picker 无需权限声明；拍照需 CAMERA 权限，app.json 配置），OTA 无法覆盖。

## 5. R3 目标空间设计

### 5.1 数据模型（`packages/db/migrations/022-goal-spaces.sql`）

```sql
create table if not exists public.goal_spaces (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references public.profiles(id) on delete cascade,
  name        text not null check (char_length(name) between 1 and 40),
  description text,
  icon        text not null default '🎯',
  color       text not null default '#38bdf8',
  status      text not null default 'active' check (status in ('active','archived')),
  started_at  date,
  target_date date,
  sort        int not null default 0,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now()
);
create index if not exists idx_goal_spaces_user on public.goal_spaces (user_id, status, sort);

alter table public.entries add column if not exists space_id uuid references public.goal_spaces(id) on delete set null;
alter table public.todos  add column if not exists space_id uuid references public.goal_spaces(id) on delete set null;
create index if not exists idx_entries_user_space on public.entries (user_id, space_id, created_at desc);
create index if not exists idx_todos_user_space  on public.todos  (user_id, space_id);

-- todos.source 增加 'ai'（AI 拆解产物）
alter table public.todos drop constraint todos_source_check;
alter table public.todos add  constraint todos_source_check
  check (source in ('voice','keyboard','manual','ai'));

-- v1.1：行动有序排列 + 每日重复 + 已完成次数
alter table public.todos add column if not exists sort              int  not null default 0;
alter table public.todos add column if not exists repeat_daily      boolean not null default false;
alter table public.todos add column if not exists repeat_done_count int  not null default 0;
alter table public.todos add column if not exists last_done_date    date;
create index if not exists idx_todos_parent_sort on public.todos (parent_todo_id, sort);

-- 排序回填：存量子任务按创建顺序编号（幂等：仅处理 sort=0 的旧数据需注意，简单做法直接全量重排一次）
update todos t set sort = s.rn
from (select id, row_number() over (partition by parent_todo_id order by created_at) as rn
      from todos where parent_todo_id is not null) s
where t.id = s.id;
```

- 子待敷新增描述即现有 `note` 列（021 迁移已加，应用层 ≤1000 字校验沿用）；
- `repeat_daily/repeat_done_count/last_done_date` 三列支撑每日重复（仅对行动生效，见 §5.6）。

### 5.3 AI 空间归属与拆解（挂靠现有识别管线）

- `packages/ai/src/schema.ts` 新增契约：

```ts

// 拆解输出（待办/行动两档共用，条数上限由调用方 zod 变体区分）

ActionList3  = { actions: ActionDraft[] }.extend(max 3)    // 拆行动
```

- `packages/ai/src/prompt.ts` 新增构建函数（硬编码默认值，key 注册进 R4 纳管）：
  - `buildSpaceClassifyPrompt(spaces, text)`：候选空间 id+名称+描述 → 判断动态内容是否服务于某空间；不相关/不确定 → `null`；输出严格 JSON。
  - `buildTodoDecomposePrompt(todo, space, profileBlock, existingTitles)`：把**待办**拆为 ≤10 个行动。
  - `buildActionDecomposePrompt(action, todoContext, space, profileBlock, existingTitles)`：把**一个行动**细化为 ≤3 个**同级的更小行动**。
- **prompt 调优要点**（拆解质量核心，R4 后台可继续调）：
  1. 行动定义：**以动词开头、单一产出、一次专注（25 分钟~2 小时）内可完成、完成与否可判定**；
  2. 数量语义：上限不是目标——拆待办通常 3~6 个足够，宁缺毋滥；覆盖"准备→执行→收尾"闭环；
  3. **拆行动**的语义：原行动偏大时细化为"下一步就能动手"的更小步骤，**与原行动同级、按执行顺序排列**（服务端插入到原行动之后）；若原行动已足够小，允许返回 1 项甚至更少；
  4. 去重：已有行动清单（含锚点前后邻居）注入 prompt，禁止生成语义重复项；
  5. 上下文注入：待办标题+note（或行动标题+其父待办标题+note）、所属空间名称与描述、`user_ai_profiles` 画像块（复用 `loadProfileBlock`）；
  6. 先思考后输出、严格 JSON、title ≤30 字（沿用现有 reasoning + zod + repair 重问一次机制）。
- `apps/api/src/lib/analyze.ts` 扩展：`analyzeAndPersist` 五域落库完成后 → `loadActiveSpaces(userId)`；若 ≥1 个且本次产生了任意产物 → 调 `chat()` 做空间分类（temperature 0，maxTokens 256，45s 超时）→ `confidence ≥ 0.7` 且 spaceId 在候选内 → `update entries set space_id`。**失败静默**（try/catch 记 `audit_logs` stage='space_classify'），不影响主识别流程。
- **待办继承**：`analyze.ts` todo 落库、`entries/[id]/confirm`、`entries/[id]/manual` 三处 insert todos 时带 `entry.space_id`。
- 配额：拆解与分类走 `checkAiQuota`（与 parse 同池）+ `writeAuditRecord`。

### 5.4 统一拆解路由（插入式）

```
POST /api/todos/[id]/decompose   body: { mode?: 'append' | 'replace' }   // mode 仅"拆待办"时有效
```

按 id 节点类型分流：

| id 节点 | 行为 | 条数 | 位置 |
|---|---|---|---|
| 顶层待办 | 生成行动 | ≤10 | **追加到该待办行动列表尾部**（`sort = max+1..`）；已有未完成行动且未传 mode → 409 `{needMode:true, existing:n}`，前端弹选择（追加 / 重新生成）；`mode=replace` 仅删未完成行动（已完成行动与重复计数保留） |
| 行动（有 parent） | 生成更小同级行动 | ≤3 | **插入到该行动之后**（原行动保留，后续行动 sort 平移）；无 mode 概念 |
| 不存在/非属主 | 404/403 | — | — |

**sort 插入算法**（列表极小，整数平移即可，无需分数排序）：

```sql
-- 在锚点行动 a(sort=S, parent=P) 之后插入 k 条：
update todos set sort = sort + k
 where parent_todo_id = P and user_id = $me and sort > S;
-- 新行动 sort = S+1 .. S+k
-- 追加（拆待办）：S* = coalesce(max(sort), 0)，新行动 S*+1 ..
```

### 5.6 首页「今日行动清单」与每日重复

**视图定义**：`GET /api/todos?view=today-actions`，返回**行动级**扁平列表：

```sql
-- ① 惰性恢复（所有 todos GET 视图前执行一次）
update todos set status = 'pending', done_at = null
 where user_id = $me and repeat_daily and status = 'done'
   and last_done_date < EFF_TODAY;

-- EFF_TODAY = "((now() at time zone 'Asia/Shanghai') - interval '6 hours')::date"
--   06:00 为记录日界：00:00–05:59 仍算前一记录日（与全局凌晨回填口径一致）

-- ② 今日行动清单
select a.*, p.title as parent_title, p.due_at as parent_due
  from todos a join todos p on p.id = a.parent_todo_id
 where a.user_id = $me
   and ( a.repeat_daily                                        -- 重复行动每天出现
      or p.today_tag_date = BJ_TODAY                           -- 父待办标记今日
      or (p.due_at at time zone 'Asia/Shanghai')::date = BJ_TODAY )  -- 父待办今日到期
 order by p.due_at nulls last, p.created_at, a.sort
 limit 200;
```

- 出参 `{ items: (TodoRow & { parentTitle, parentDue })[] }`；`packages/shared/src/types.ts` 的 `TodoRow` 增 `sort/repeatDaily/repeatDoneCount`，`TodoItem.children` 改按 `sort` 排序。
- **完成计数**（PATCH done 内，与置 done_at 同一条 UPDATE）：

```sql
repeat_done_count = repeat_done_count
  + case when repeat_daily and coalesce(last_done_date, 'epoch'::date) < EFF_TODAY then 1 else 0 end,
last_done_date = case when repeat_daily then EFF_TODAY else last_done_date end
-- 同一记录日反复 勾→取消→再勾 只计 1 次；undone 不回退计数
```

- **恢复语义**：恢复是"读时惰性"（系统惯例，无 cron）：06:00 日切后用户首次打开任一 todos 列表即恢复为未完成；00:00–05:59 保持昨日完成态（凌晨勾掉算前一记录日的完成，不立刻被恢复）。若后续想改为 0 点整恢复，只需去掉 `interval '6 hours'` 一处常量。
- **前端**：`today-todos.tsx` 改造为「今日行动清单」（组件 TodayActions，文件更名 `actions-today.tsx`）：行动行 = TodoCircle（勾选）+ 标题 + 小字父待办名（`text-ink-faint`，点击跳 /schedule）+ 🔁 徽标 + `×N` 次数 chip + due/描述指示；空态文案「今天还没有行动，去待办里拆解一个吧」；勾选完成后行内立即显示 ×N+1。
- **/schedule 看板**：☀️今日视图维持顶层待办粒度（`view=today` 语义不变），与首页行动清单互不影响。
