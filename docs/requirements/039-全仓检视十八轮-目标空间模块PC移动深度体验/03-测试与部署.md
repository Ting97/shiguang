### P3（10 项全修）

- **time `assertDateRange` 查询区间无跨度上限**（blocks/range、stats/range 两路由）：`from=0001-01-01&to=9999-12-31` 合法通过，listBlocksInRange 回全量历史块、dailyMinsByActivity 对每块开 generate_series，单请求可拉爆响应体/聚合 → 对齐 fitness rangeGuard 补 366 天上限（前端最大跨度为年视图 365 天差，不误伤）
- **transactions POST occurredAt 非字符串被静默接受为 epoch**：`new Date(body.occurredAt)` 对 JSON number 产出合法 Date，仅有的 isNaN 守卫拦不住，错误日期流水直接入库（同文件 PATCH 早有 `typeof !== "string" || !isParsableMoment` 双守卫）→ POST 补同款守卫
- **chat tools 模块开关只覆盖 debt/trading，域级模块与 trade_review 周报可绕过**：`query_transactions/goals/todos/time_blocks/contacts/fitness` 等全部无模块态检查，`get_review(kind=trade_week)` 可直读 trade_review 子模块（商业门禁）生成的收支周报——模块「插件化关闭」只在路由层生效，助手成为旁路 → `toAgentTools` execute 包装层按 TOOL_DOMAIN 统一过 `moduleAllowed`（debt/trading 子模块仍有各自更细粒度校验）；get_review trade_week 分支补 `moduleAllowed(ctx, "trade_review")`
- **push/daily 每日提醒推送完全不校验模块有效态**：contacts 生日/纪念日/久未联系（people 域）与 todos 到期（goal 域）不过滤 `resolveUserModules`，而同源数据的 `/api/reminders` 路由门禁在 withModule——用户关闭模块后横幅不显示却仍每天收到推送 → 投递前按用户模块态归零对应计数（goal 关→待办、people 关→生日/纪念日/久未联系），按模块 Map 缓存避免多设备重复解析
- **todos/[id]/decompose 拆解审计 ok:true 写在落库事务之前**：LLM 成功后 writeAuditRecord(ok:true) 先行，其后事务失败返回 500 或 needMode 询问返回 409 都未交付产物，但已计入 30 天免费额度（「配额只扣成功调用」口径）→ ok:true 移到 commit 之后（失败路径原有 ok:false 分支不变）
- **billing/plan Pro 再发放是「重置」而非「续期」**：`expires = now + months*30d` 直接覆盖 plan_expires_at，对剩余有效期的 Pro 再发放会缩短到期日（支付回调重复回调会越续越少）→ 现到期日仍在未来时按 `max(now, 现到期日) + months` 续期
- **billing/plan GET 套餐页 token 明细未排除 jev% 影子行**：byModel 聚合无 `not like 'jev%'` 过滤（同仓 tokens/usage、quota、billing/users 均排除），JEV_MODE=shadow 期间用户看到的消耗被影子调用虚增 → 补同一过滤
