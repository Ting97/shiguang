## 二、踩坑记录

1. **xunji.test.ts 全量跑挂、单跑过的真凶 = pg Pool 连接串冻结竞态**：该文件顶层 `const svcP = import(service)` 触发 service→repo→platform/db 模块链加载，`platform/db.ts` 在模块加载期用**当时**的 `DATABASE_URL` 构建 Pool（连接串之后不可变）。原顶层先把 DATABASE_URL 落 placeholder、等 ensureLoaded 再改 env——两条 import 链谁先到达 platform/db 谁定连接串：单跑短链常赢，全量套件下时序反转稳定落在 placeholder（ECONNREFUSED 127.0.0.1:5432），且 ensureLoaded 的 `import(platform/db)` 命中缓存改不回来。修复：顶层 `??=` 直接优先取 `SHIGUANGRI_TEST_DB`，消灭竞态。附带症状：该文件 dbReady=false 导致 6 个真库门禁用例静默 skip（23→29）。
2. `listXunjiAliases`（023 新增）在 matchXunjiOfficialNames 里无降级，池坏时异常逃逸直接打挂非门禁用例——已加 try/catch 按无别名降级（与 loadXunjiCatalog 同口径）。
3. 调试环境变量问题时在文件顶层 `console.error` 打 env 快照 + 只 grep 关注行，一次全量跑（约 1 分钟）即可同时拿到「env 有没有传进来」与「池用的哪个串」两个关键事实。
