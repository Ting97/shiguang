# 025 · 睡眠感受与 App 得分 · 需求设计

> 状态：开发中 · 2026-10-16 · 前置：024（睡眠独立记录）

## 背景与目标

024 把睡眠独立成每日一条记录，但只有时长一个维度。用户要求（2026-10-16）：睡眠记录新增**主观感受**（睡醒后状态）与**App 睡眠得分**（手环/手机睡眠算法给的 0–100 分），两者都是运动教练排课的重要参考——时长正常但得分低/感受疲惫时同样应触发降级。

## 需求清单

| # | 需求 | 验收 |
| --- | --- | --- |
| FR-A1 | 睡眠记录支持可选字段：感受（good 饱满 / ok 一般 / bad 疲惫）与得分（0–100 整数）；两字段均可空 | 录入弹窗可填可空；只填时长不破坏已有感受/得分 |
| FR-A2 | 健身页「😴 睡眠」卡展示最近一晚的感受与得分；录入弹窗同日重录时预填已有值 | 卡面显示「饱满 · 82分」类摘要 |
| FR-A3 | 教练/助手数据源：`query_fitness_logs` 的 sleep 序列带上 feeling/score | 助手排课时能读到近几日睡眠质量 |

## 边界与非目标

- 不做手环自动同步（得分由用户照抄 App 数值）；不改动 024 的时长口径与降级协议文案。
- 感受/得分更新走同日 upsert 的**部分更新语义**：只传小时数时保留已有感受/得分（coalesce），传 null 不清空。
- 打卡兼容入参（sleepHours）不带感受/得分——打卡路径只补时长。

## 决策记录

1. **三档枚举而非自由文本**：good/ok/bad 足够排课判断，自由文本无法聚合也无法稳定进入 prompt。
2. **coalesce 部分更新**：用户常只补时长（App 得分懒得天天抄），二写不能把已录的感受/得分抹掉。
