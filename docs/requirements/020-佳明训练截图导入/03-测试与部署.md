## 四、后记：Android 壳截图上传无反应修复（2026-10-16）

- **现象**：Android 壳内训练页点「📷 佳明截图识别」无反应/选不到图片。
- **根因**：壳 `MainActivity.onShowFileChooser` 为 CSV 账单导入定制，忽略网页 `accept="image/*"`，固定弹 CSV/Excel 过滤的文档选择器——图片不可见，部分 ROM 直接无可解析界面。
- **验证**：桌面 Chromium 自动化实测 web 侧链路完整（按钮无遮挡、`input.click()` 正常触发）——纯壳层问题，浏览器端不受影响。
- **修复**：`onShowFileChooser` 按网页 accept 分流——含 `image` → `image/*` 图片选择器（「选择课表截图」）；其余沿用 CSV 放宽 mime 逻辑。javac 语法校验通过（本机无 Android SDK，实机构建在 Windows 机）。
- **发布**：壳为独立 APK（`apps/android`，assembleRelease，debug 签名侧载），需重新出包装机；网站本身无需发版。
## 五、追加记录

### v1.1（2026-10-18）：移动端选图弹窗慢修复

- **现象**：移动 web 端点「📷 佳明截图识别」后数秒才弹选择窗口。
- **根因**：初版用 `accept="image/*"` + 按钮程序化 `input.click()`。`image/*` 在移动端触发系统相册全量枚举（大相册/微信内置浏览器明显卡顿）；程序化 click 在部分国产 WebView 响应慢。点击到弹窗之间的页面 JS 仅一行同步调用，非代码耗时。
- **修复**：对齐 publish-sheet 成熟模式——隐藏 input 包进 `<label>` 原生触发 + `accept="image/jpeg,image/png,image/webp,image/gif"` 具体 MIME 列表（不走相册枚举路径）；删除 fileInputRef（onChange 内即取即清）。压缩/解析流程不变。accept 仍含 `image`，与四节 Android 壳的 accept 分流逻辑兼容。
- 验证：typecheck/lint/build 通过（rebase 到 864906d 后全绿）；无迁移。
- 发布：2026-10-18 `node scripts/deploy.mjs` 全流程通过（b330214 上线，冒烟 health/login/me 全绿）；手机端需刷新一次让 Service Worker 换到新 CACHE_VERSION 后生效。次要因素（冷加载水合未完成时首点无响应）为 SSG+水合固有，SW 缓存命中后无感。
