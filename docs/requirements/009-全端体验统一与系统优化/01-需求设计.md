## 1. 背景

### 1.1 一句话

项目已经过 004（架构重构）与 006~008（三轮检视）收敛，架构与工程纪律良好；本包一次性解决剩余六类欠账：**设计系统靠人肉同步、web 交互层粗糙、小程序与 web 仅色板对齐、移动端功能截断、AI 成本无闭环、运维不可重建**——用户要求"不计成本，视觉交互体验做到最好，小程序端与 web 端完全统一"。

### 1.3 用户故事

1. 作为用户，我在 web/小程序/手机 App 上看到**一模一样的视觉与反馈**——同一套颜色、同一套动效节奏、同一套成功/失败提示。
2. 作为触屏用户，我按任何按钮都有按压反馈，小图标不会按不准，加载时不看白屏。
3. 作为键盘用户，我能看到焦点在哪，Esc 能关掉任何弹窗。
4. 作为重度用户，我说一句话产生多条记录、花最少的 AI 额度；我的语音、拆解调用都被公平计量。
5. 作为开发者（+ZCode），我改一处 token，三端同时生效，CI 会抓住任何漂移；服务器挂了我能用 repo 重建一切。

## 4. 功能需求明细

### 4.1 批次 9-A：设计系统单一真源

- **FR-A1 令牌源**：新建 `packages/design-tokens`，`src/tokens.ts` 以 TS 对象定义全部设计令牌：现有 52 色板×双主题（web globals.css 为基准值）+ **新增维度**——type scale（6 档：11/12/13/15/17/20px 基准 + 徽标特例 10px，消灭 9px）、radius 刻度（sm/md/lg/xl/full）、spacing 语义刻度、shadow 刻度、motion（duration 150/200/350/500 + 标准 easing + reduced-motion 约定）、z-index 刻度（base/sticky/overlay/modal/toast/max）。
- **FR-A2 四端生成**：构建脚本从 tokens.ts 生成：① web `globals.css` 变量段（GENERATED 标记块内）；② miniapp `app.scss` 变量段（同上）；③ mobile `THEMES` 常量文件（App.tsx 改为 import）；④ 微信 `theme.json`（配合 `darkmode:true`）。生成产物入 git（各端无构建依赖也可用）。
- **FR-A3 漂移校验**：脚本 `verify` 子命令比对生成物与令牌源，接入 CI/测试；手改 GENERATED 块即红。
- **FR-A4 现存漂移修复**：miniapp 骨架屏浅色翻转 bug、mobile THEMES 8-10 处数值回漂 + 死常量 C 清除、miniapp `darkmode:true` + theme.json（system 主题档修复）、miniapp README 铁律 1 改写（变量段=生成物禁手改，语义类仍冻结）。

- **FR-B1 反馈系统统一**：激活 `shared/ui/toast.tsx`（补队列/进出场/危险语义）；替换全部 msg state 页面与三种横幅方言为 toast（保留页内 banner 用于表单行内错误）；危险操作统一 useArmConfirm，清除 4 处 window.confirm。

## 5. 非功能需求

- **NFR-1 API 兼容**：除新增端点外不破坏现有 API 契约；小程序/移动端旧版本可继续运行。

- **NFR-6 兼容目标**：web=近两年主流浏览器+微信内置浏览器；小程序=微信基础库 ≥3.0；mobile=Android 8+。

## 6. 验收标准

- **AC-1 统一性**：`design-tokens verify` 通过；三端（web/miniapp/mobile）运行时截色对比无人工色值残留于 GENERATED 块；小程序 12 页与 web 对照走查差异清单归零。
- **AC-2 体验**：全站 0 处 window.confirm、0 处 9px 字号、0 处文本"加载中…"、toast 覆盖全部操作反馈、全部弹层 Esc 可关且焦点归还、`active` 按压反馈覆盖全部可点元素、PWA 可安装且断网可打开缓存壳。
- **AC-3 经济与健壮**：audit_logs 无 0 token 漏记路径；超额用户调 ASR 返回 402/429；deploy 全流程（含失败回滚）演练通过；备份脚本在干净目录恢复演练通过。
- **AC-4 移动端**：手机端可浏览全部历史动态（翻页）；推送端到端到达；同设备三 APK 可共存安装。
- **AC-5 回归**：PoC 46 句通过率不低于基线；现有 node:test 全绿；构建零错误。

## 7. 非目标

- 不推翻现有视觉基调重做设计稿（在现有深色科技风上做深度）。
- 不新增业务功能域（推送为既有"主动消息"主线的通道补全，不扩业务）。
- 不做原生 iOS 功能开发（Capacitor 壳仅做归档决策）。
- 不引入重型状态管理/动画框架（framer-motion 等），动效用 CSS + 少量 JS 编排。
- 小程序 admin 后台不迁移（沿用现状）。
