# 023 · 训记动作映射确认 · 需求设计

> 状态：开发中 · 2026-10-16 · 前置：017（训记同步）/ 022（训记动作名自动匹配）

## 背景与目标

022 上线后实测暴露盲区：佳明全身循环类截图的自重动作（臀桥/登山者/自行车卷腹）在训记目录里**没有光杆同名项**（只有杠铃臀桥、弹力带-登山者等带器械变体）。AI 按「宁缺勿错」正确拒绝错误映射，但同步训记沿用 017 的硬拦截（「不在训记官方动作库——请改名」），而系统没有改名入口——用户被彻底堵死（实测 2026-10-16 臀桥案例）。

本批把官方规则「不确定时让用户确认」落成产品流程：同步遇目录外动作名时，前端弹窗列出候选官方名，用户逐个确认（或跳过）；确认映射持久化到**每用户别名表**，此后保存/同步自动套用，不再重复询问。

## 需求清单

| # | 需求 | 验收 |
| --- | --- | --- |
| FR-A1 | 同步训记遇目录外动作名 → 返回结构化 `needsConfirmation`（未匹配名单 + 每名 top-8 候选官方名带分类），不再抛错 | 点「同步训记」弹出确认 Modal 而非报错 toast；候选来自目录字符重叠预筛 |
| FR-A2 | 确认 Modal：每动作一个下拉（候选官方名 / 「跳过——不写入训记」）；确认后映射写入每用户别名表（迁移 060），本次同步生效 | 同步载荷用确认后的官方名；别名表落库；跳过动作不进训记 |
| FR-A3 | 确认后回写计划内容：映射名替换 + 「佳易名：xxx」备注（与 022 保存路径同管线） | 计划卡与训记两端名字一致；再次同步不再询问 |
| FR-A4 | 别名表在保存/解析路径生效：`matchXunjiOfficialNames` 规则通道优先查用户别名，命中不再耗 AI | 确认过一次的动作，后续导入/保存自动对齐 |
| FR-A5 | 目录不可得（未配 key/接口故障）时退回旧拦截文案（无候选可确认）；全部动作被跳过 → 400 | 降级路径不弹空确认窗 |

## 边界与非目标

- 跳过只影响**本次同步载荷**，不删计划里的动作（拾光计划保持完整）。
- 不做别名管理 UI（增删改查）：确认弹窗即入口，改选同名动作覆盖旧映射。
- 训记 API 对目录外名字的真实行为仍未实测（无删除接口，不拿用户账户冒险）——本方案绕开该未知，只写目录内名字。
- 运行分支（有氧日）无动作名问题，不涉及确认流。

## 决策记录

1. **用户选择「同步前确认映射」而非「未知名原样写入」**（2026-10-16 当面确认）：宁可在确认弹窗里挑相对最近的官方名/跳过，也不往训记写目录外名字——无删除接口，垃圾记录清不掉。
2. **映射持久化在每用户表而非全局 XUNJI_NAME_ALIAS**：映射语义是「该用户认可的对齐」，不同用户可能不同；全局表仍保留给实测过的通用别名（高脚杯深蹲等）。
3. **候选生成零 AI**：目录字符重叠预筛（复用 022 的 prefilterCandidates）足够把「臀桥→后倾臀桥/杠铃臀桥」这类同族动作排上来，选择权在用户，不需要再烧一次模型。
