# 038 · 睡眠数据自动同步日程块 —— 开发设计

## 一、数据模型（迁移 067）

```sql
alter table public.time_blocks
  add column if not exists sleep_log_id uuid
  references public.fitness_sleep_logs (id) on delete cascade;

create unique index if not exists time_blocks_sleep_log_id_uq
  on public.time_blocks (sleep_log_id) where sleep_log_id is not null;
```

- 链接范式与 `syncPlanTodos`（`todos.fitness_plan_id on delete cascade`）一致：睡眠日志按 `(user_id, log_date)` 稳定 upsert、行 id 不变，FK 天然维持一致性；删除睡眠行级联清同步块。
- **唯一部分索引**保证一条睡眠至多一个同步块（运行时替换式先删后插 + per-user advisory lock 已串行化，索引兜底并发与回填重跑）。

### 存量回填（同迁移内，幂等可重跑）

```sql
insert into public.time_blocks (user_id, activity_id, title, start_at, end_at, time_mode, source, sleep_log_id)
select l.user_id, 'sleep', '睡眠',
       ((l.log_date::timestamp + interval '07:00') - interval '1 hour' * (l.sleep_h_x10 / 10.0)) at time zone 'Asia/Shanghai',
       (l.log_date::timestamp + interval '07:00') at time zone 'Asia/Shanghai',
       'manual', 'manual', l.id
from public.fitness_sleep_logs l
where l.sleep_h_x10 > 0
  and not exists (select 1 from public.time_blocks b where b.sleep_log_id = l.id)
  and exists (select 1 from public.activities a where a.id = 'sleep' and a.user_id = l.user_id)
  and not exists ( … 与既有块 tstzrange && 重叠者排除 … );
```

- `at time zone 'Asia/Shanghai'` 显式锚定北京墙钟（PG 容器为 UTC，裸 timestamp 会按会话时区解释）。
- 相邻两天的睡眠区间天然不相交（锚点恒定 07:00、时长 ≤ 16h < 24h 间隔），重叠只可能来自其他日程。

## 二、time 域：`syncSleepBlock`（apps/api/src/server/time/service.ts）

```
syncSleepBlock(userId, { sleepLogId, logDate, sleepHX10 }, exec?) →
  { ok: true, blockId: string | null }   // blockId=null = 0h 撤销
| { ok: false, reason: string }          // 冲突/缺分类，reason 用户可读
```

流程（`syncSleepBlockInner`）：

1. 取 `pg_advisory_xact_lock(hashtext('timeblocks:'+userId))`——与 createBlock/updateBlock 同一把锁，重叠预检与落库串行化。
2. **缺「睡眠」分类守卫**：`activities` 无 `(sleep, user)` 行 → `{ok:false, reason:'缺少「睡眠」分类…'}`。预设分类注册即播种且不可删，正常恒在；兜底避免 23503 炸掉 fitness 打卡事务（与 067 回填守卫同口径）。
3. `sleepHX10 <= 0` → 删旧同步块（`removeBySleepLog` returning 起止）、按新旧起止失效复盘缓存、返回 `blockId:null`。
4. 计算区间（起床锚点）：`endAt = ${logDate}T07:00:00+08:00`（显式偏移），`startAt = endAt − 时长`。
5. **先预检再删旧**：`findOverlap(userId, start, end, excludeId=现有同步块id)`——冲突时保留旧同步段不丢，返回 `overlapError` 文案。
6. 无冲突：删旧 → `blocksRepo.insert(..., sleepLogId)`（insert 增加可选第 7 参写入 `sleep_log_id`）→ 新旧区间各起止日 `invalidateReviewCachesForOccurrence`（跨天块双日口径，与 createBlock/deleteBlock 一致）。

事务边界：传 `exec`（事务 client）时在调用方事务内执行；不传时自开事务（saveSleep 路径）。

### 锁序与死锁面

- fitness 打卡路径：计划行锁（`for update`）→ advisory；addLog 路径：advisory；建块/改块路径：仅 advisory。advisory 恒为第二把/唯一锁，无环。
- timeline 域同锁路径只触碰 entries/time_blocks，不反向依赖 fitness 行锁。

## 三、fitness 域接入（apps/api/src/server/fitness/）

| 入口 | 改动 |
| --- | --- |
| `repo.upsertSleep` | `returning` 补 `id`（链接键；行 id 稳定是 FK 范式的前提） |
| `service.saveSleep`（POST /api/fitness/sleep） | upsert 后调 `syncSleepBlock`（自开事务）；响应追加 `sync` 字段；冲突不抛错、睡眠照常返回 |
| `service.updatePlan` 打卡分支（sleepHours） | 同事务内：`upsertSleep(…, client)` → `syncSleepBlock(…, client)`；冲突静默跳过（`ok:false` 不影响打卡），睡眠照常落库 |
| `service.addLog` 独立补录（sleepHours） | 同上（该事务无计划行锁，advisory 为第一把锁，无环） |

导入：`import { syncSleepBlock } from "@/server/time"`（跨域只准走域 index；已核实 insight/time 不反向依赖 fitness，无循环导入）。

## 四、time 域编辑解绑（updateBlock）

`timesOf` 补读 `sleep_log_id`；`updateBlock` 在锁内读到 `cur.sleep_log_id != null` 时给 fields 追加 `("sleep_log_id", null)`——**任何**成功编辑（含仅改标题）即解绑：修改保留为普通块、该日再存生成独立新块。删除路径无需处理（行删除即无链接；再存自然新建）。

## 五、web SleepCard（apps/web/src/app/fitness/panel.tsx）

- 保存响应按 `sync` 分支 toast：
  - `sync.ok === false` → `😴 睡眠已记录；日程同步跳过：${reason}`（err 色，reason 为服务端冲突文案）
  - `sync.blockId` 存在 → `😴 已记录睡眠，并同步到日程`
  - 其余（0h 撤销/旧响应兜底）→ `✅ 已记录睡眠`
- 表单底部补说明行：「保存后自动按起床 07:00 生成日程睡眠段（如 8 小时 → 前夜 23:00–07:00），与已有日程重叠时跳过。」
- 小程序不改：同接口返回多一个 `sync` 字段向后兼容，日程页自动展示同步块。

## 六、回归测试（apps/api/test/sleep-sync.test.ts，真库门禁）

| # | 用例 | 断言要点 |
| --- | --- | --- |
| ① | 保存 8h | 块存在、activity='sleep'、time_mode/source='manual'、`sleep_log_id` 正确、北京 10-14 23:00 → 10-15 07:00 |
| ② | 同日改 6h 重存 | 仍 1 块、id 不变、区间 01:00–07:00（替换式幂等） |
| ③ | 改 0h 重存 | 同步块删除、睡眠记录保留（sleep_h_x10=0） |
| ④ | 预置重叠手动块（SQL 直插）改 5h | `sync.ok=false` + reason 含「一个时刻只能做一件事」、睡眠照常落库、**旧 8h 同步段保留不丢**（先预检再删旧） |
| ⑤ | PATCH 同步块挪到白天再存 8h | PATCH 后 `sleep_log_id=null`；再存生成独立新块（2 块并存：编辑块无链接 + 新块带链接） |
| ⑥ | 用户无 activities | `sync.ok=false` 优雅跳过、睡眠照常保存、不产生块（不炸事务） |

用例 ④ 的重叠块走 SQL 直插：应用层 `createBlock` 的重叠预检会拦下与既有同步块重叠的创建，构造不出「手动块已占、同步让位」场景（AI 识别/历史导入路径确实可能留下此类块）。
