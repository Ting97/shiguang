### P2（20 项全修摘录）

- **请求体上限全线缺失**：70 路由裸 `await req.json()`，超大 body 直接打满内存 → `readJsonCapped(req)` 统一 1MB 上限（platform/http/route.ts），transactions/import 因附件截图放宽 9MB（codemod 脚本 `scripts/qa/cap-req-json*.cjs` 入库可复现）
- **timeline/feed 排序不稳定**：`order by created_at desc` 无 tie-breaker，同秒记录翻页错乱/重复 → 补 `e.id desc`；goal/repo、trades 同口径
- **setEntryAudio 孤儿文件**：更新 0 行仍先落盘音频 → `rowCount===0` 时删文件并 404
- **appendManual people occurred_at 恒 now()**：补录昨天动态的「遇到谁」记到今天 → 用 entry.created_at
- **people listWithStats N+1**：礼金净额逐人子查询 → 预聚合 subquery + counterparty join（种子实测 +260/−880 双向正确）
- **daily push 幂等**：进程重启同日重复推送 → `app_config` 持久化 `daily_push:last_date`（投递前置位、清扫失败回滚）
- **wechat access_token**：并发刷新互相覆盖 → single-flight；msgSecCheck 40001 缓存失效后强制刷新重试
- **email transporter 每次新建**：SMTP 握手反复开销 → getTransporter() 进程级缓存
- **patrol 保留期清扫每 tick 全表扫** → 12 tick（≈1h）节流 + `timer.unref()`
- **fitness saveMetric 竞态**：同指标并发写乱序 → advisory-lock 事务（`fitness-metrics:userId`）
- **债务导入逐行 INSERT**：千行级慢 → 500 行多值批量
- **sw.js 缓存无界**：/api/* 200 永久驻留、旧账号数据可离线回放 → 24h TTL + 300 条 LRU + q/keyword 易变参数不缓存 + 401 全清 + 换账号清缓存（session.tsx）
- **MT5 时间解析固定 +2**：欧盟 3 月末/10 月末夏令时切换错 1 小时 → offsetHours 按日线规则推断（显式参数可覆盖），7 个单测锁行为
- **finance 首页 confirmedPaged 只拉 1 页**：>50 条确认流水静默截断 → 循环分块合并
- **wechat isBusinessEmpty 漏 7 表**：新模块有数据仍判「空闲」误推周末汇总 → 补 chat_proposals/space_milestones/user_exchange_keys/trade_imports/trade_reserve_banks/debt_reserve_checks/debt_reserve_sources
- **billing plan 改套餐无审计** → writeAuditRecord stage module_admin
- **time/repo dailyMinsByActivity 边界**：块跨日只按 start_at 过滤漏算跨入块 → 半开区间 sargable 条件
- **debts/overview month 边界**：`to_char(paid_at)` 会话时区依赖 → timestamptz 半开区间
- **feed/[id] mood 无上限**：任意长心情串入库 → z.string().max(20).nullish()
- **admin 营销面板**：用户列表失败永远「加载中」→ 错误终态 + 重试；写操作无重入锁 → mutatingRef
