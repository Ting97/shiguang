## 2. 调研结论

### 2.1 参考页 trade.ting97.cn/xau/交易复盘.html（2026-09-23 SSH 核查，1505 行）

「XAUUSD 逐笔交易复盘 · 导入版」，功能栈：

1. **导入**：拖拽/选择 `ReportHistory-*.xlsx`（MT5 报表导出，含「持仓」区块）或同列结构 CSV；页面内置 xlsx 解析（unzip/sharedStrings/sheetToRows）与 CSV 解析；
2. **逐笔开/关仓图** + **每日盈亏** + **累计权益曲线**（峰值/回撤段标注、回撤拆解点名日期与金额）；
3. **逐单走势归类**（Classification/category 维度）+ **每日明细** + **逐仓明细列表**（profit+comm+swap 净盈亏、手数、胜率、交易频率）；
4. **复盘结论**：规则引擎生成（权益峰值前后两阶段对比、频率与胜率变化等），非 LLM。

### 2.2 参考页 每月备付追踪（/opt/aitrade/资产/备付核心.js）

- **需还矩阵**：每笔负债 priority → 逐月规则（基准月供 monthly、月供跳变 steps、到期月追加本金 extras、终止月 until）；
- **monthPlan(ym)**：当月各账户应还 = 月供 + 到期追加，过滤 0；**按银行合并**（同银行多笔合一格，还款日合并显示）；
- **勾选备付**：逐笔/逐行勾选"已备付"，localStorage 持久化；储蓄账户余额参与覆盖度统计（仅余额，不计入达标）。

### 2.3 本地现状（根因盘点）

- **感悟保存后不刷新（bug 根因）**：列表 state 在子组件 `SpaceReflections` 内部，保存动作在 `saveReflection`（成功后只重拉空间统计/待办/动态接口——不含感悟列表）；子组件仅 mount 时 `load(0)`。删除路径正确（自刷+`onChanged`）。**全库检视结论：其余模块均遵循"列表 state 谁持有谁刷新"，感悟是孤例**。（004 拆分后锚点：`apps/web/src/app/spaces/[id]/detail.tsx` 172 行，saveReflection 在 `detail/use-reflection.ts`，列表组件布线经 `detail/reflection-section.tsx`。）
- **日程子导航**：schedule 页 pill 容器 `bg-bg/50 p-0.5` 挂在 header 内；finance-tabs 为独立居中 `<nav>`（`bg-surface/70 p-1`，Link 路由）；spaces 详情为裸 board chip 横滑行——三种形态不统一。
- **可复用基建**：`bill-import.tsx` 的 dryRun 预览→确认导入范式；`withModule` 模块门禁（031 授权表，枚举现仅 debt/trade_review）；`/api/export`（9 表 JSON 全量备份，不含 liabilities）。
- **移动端**：Expo 单屏（无导航库），已有 Bearer 鉴权与交易 chip 只读渲染先例。

## 4. R1 MT5/CFD 投资交易模块

### 4.1 定位与边界

- **独立模块**（module key `trading`）：与账户流水（transactions）、负债（liabilities）零耦合——投资交易数据不进 accounts/transactions，净资产口径**不含**交易账户（后续如需再议）。
- 本期只做 **MT5 平台的 XAU/CFD** 数据导入与分析；其他平台（券商/交易所）后续按同一导入框架扩展。
- PC 端（Web 桌面）负责导入与管理；**移动端（PWA + Expo）只读查看**。

### 4.2 用户故事

- 作为用户，我在 PC 上把 MT5 导出的 ReportHistory xlsx（或同列 CSV）拖进拾光，立刻看到逐笔明细、每日盈亏与累计权益曲线。
- 作为用户，我多次导入同一账号的新报表，已存在的单子不重复。
- 作为用户，我在手机上随时看今天的账号盈亏和最近曲线，但不能（也不需要）在手机上导入。
- 作为用户，页面底部自动给我一份 **AI 复盘**（回撤点名、行为特征、改进建议），不需要我自己算；AI 不可用时也至少有规则统计结论兜底。

### 4.3 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1.1 | 导入（PC） | 拖拽/选择文件：`ReportHistory-*.xlsx`（含「持仓」区块）或同列结构 CSV；**客户端解析**（沿用参考页已验证的解析逻辑）→ dryRun 预览（识别账号/时间范围/笔数/去重情况）→ 确认入库；单文件 ≤10MB；仅 PC（coarse pointer/窄屏隐藏导入入口） |
| FR-1.2 | 数据持久化 | 导入批次 + 逐笔交易落库；**ticket 去重**（同账号已存在 ticket 跳过并计数）；金额保留原币种（CFD=USD，numeric），不做汇率换算 |
| FR-1.3 | 账号管理 | 按 MT5 账号（导入时识别/可命名备注）分组；多账号并存；账号级汇总（总盈亏/胜率/笔数/手数） |
| FR-1.4 | 每日账号盈利 | 按日聚合净盈亏（profit+commission+swap）：日历/列表视图、日环比、连亏连赢标记 |
| FR-1.5 | 权益曲线 | 累计净盈亏曲线：峰值标注、**回撤段拆解**（点名日期与金额）、阶段对比（峰值前后两段：频率/胜率/盈亏） |
| FR-1.6 | 逐笔明细与归类 | 逐仓明细列表（开平仓时间/方向/手数/开平价/净盈亏/持仓时长）+ 归类统计维度：开仓时段、方向、持仓时长档、盈亏档；筛选与排序 |
| FR-1.7 | **AI 复盘**（v1.1 升级） | 账号级 AI 复盘卡片：LLM 生成 {summary, highlights, suggestions}，**素材 = 服务端规则统计**（权益概况/回撤段点名/峰值两阶段对比/归类聚合/典型逐笔样例）；走既有复盘管线模式——review_caches 缓存（kind 扩展）+ 配额门禁 + prompt key `trading_review` 纳入 /admin 可调优；生成失败/额度不足**回落规则版结论**展示（移植参考页 buildDigest/rulesSummary，零 token 兜底） |
| FR-1.8 | 移动端只读 | PWA：/finance/trading 在触屏/窄屏隐藏导入与编辑入口只留查看；Expo App 新增「交易」只读屏（日盈亏卡 + 曲线 + 明细列表，复用现有主题与卡片风格） |
| FR-1.9 | 模块授权 | `trading` 进模块授权体系（admin 默认可用，可授权指定用户）；未授权 tab 不渲染、API 403 |

### 4.4 边界与异常

- 解析失败（非 MT5 格式/列结构不符）：预览阶段明确报错，不入库。
- 同 ticket 不同账号视为不同单；重复导入同文件 = 全部命中去重，返回"0 新增"。
- 出金/入金（balance 变动）本期不建模——权益曲线为**累计净盈亏口径**，页面标注。
- K 线/行情联动（参考页的 updateKlBar 逐单走势）不搬运（需行情数据源），归类维度用时段/时长/方向替代。
- 时区：MT5 报表时间通常为服务器时区，导入时按 UTC+2/+3（MT5 默认）→ 北京时间转换并在预览中标注口径，用户确认。
- AI 复盘消耗 AI 配额（与既有复盘同池，admin 不限）；缓存期内重复打开不重复生成；规则统计部分（权益/回撤/归类）始终零 token 即时可见。

### 4.5 验收标准

- [ ] PC 导入 xlsx 与 CSV 双通道：预览（账号/范围/笔数/去重）→ 确认 → 落库；重复导入 0 新增
- [ ] 非法文件在预览期被拒且提示明确
- [ ] 每日盈亏、权益曲线（峰值/回撤段/两阶段对比）、逐笔明细与四维归类全部可用
- [ ] **AI 复盘**：生成成功展示 {summary, highlights, suggestions}；缓存期内二次打开不重复扣配额；额度不足/LLM 失败回落规则版结论（有降级标识）；`trading_review` prompt 在 /admin 可调优
- [ ] 多账号分组与汇总正确
- [ ] PWA 触屏无导入入口；Expo「交易」屏可看日盈亏/曲线/明细
- [ ] 未授权用户不可见 tab、API 403
- [ ] 大文件（近万笔）列表与曲线不卡顿（分页 + 采样渲染）

## 6. R3 每月备付追踪

### 6.1 概念

**备付**：每月为各笔负债应还款项（月供 + 当月到期本金）提前留存的资金动作。功能 = 当月应还清单（按账户/还款日合并）+ 逐项勾选已备付 + 储蓄余额覆盖提示。

### 6.2 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-3.1 | 月度应还清单 | 选月（默认当月）：各 active 负债应还 = 月供 + 当月到期本金（due_date 落在本月 → 追加当前余额）；按**账户（负债名称）合并**展示还款日与合计；月总计 |
| FR-3.2 | 勾选备付 | 逐项/一键勾选"已备付"，持久化；勾选状态按月独立；月进度（已备付/总额 x%） |
| FR-3.3 | 储蓄覆盖提示 | 只读展示：资产账户（可勾选参与统计的储蓄账户）余额合计 vs 当月应还总额 → 覆盖率与缺口提示；不计入达标判定 |
| FR-3.4 | 入口 | 负债页内「备付」区块（月切换 + 清单 + 勾选 + 覆盖条）；与还款记录联动：某笔已记还款 ≥ 当月应还时自动勾选（可手动改） |

### 6.3 边界

- 月供跳变（trade 的 steps）与 extras 到期追加已由 FR-3.1 的"当月到期本金"自然覆盖（到期月 balance 计入）；**月供随时间变化**（如 11 月跳升）拾光负债模型不建模，按当前 monthly 计算，用户改档案即更新。
- 已结清/归档负债不出清单。

### 6.4 验收标准

- [ ] 选月清单正确（月供 + 当月到期本金、按账户合并、月合计）
- [ ] 勾选持久化且按月独立；一键勾选/取消；进度正确
- [ ] 记还款后自动勾选联动
- [ ] 储蓄覆盖率/缺口显示正确（勾选参与账户）

## 8. R5 后台数据接口（AI 调优数据面）

### 8.1 背景与用户故事

调优 AI 识别（改 prompt / 调 Jev）时，需要把真实数据喂给模型或离线评测。作为管理员，我想：

- 一次看到**系统有哪些类别**（活动分类/交易分类/联系人分组/空间/负债类型……）；
- 按**时间范围 + 类别**拉某类用户数据（如"最近一个月 餐饮 类流水"）；
- 看到一张**数据目录**：每类数据是什么、时间字段、类别维度，以及**哪些数据当前正被哪些 AI prompt 注入**（智能关联），一眼知道"调这个 prompt 能用到什么数据"。

### 8.2 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|

### 8.3 数据集清单（首版）

行为数据型：entries（含 mood）、time_blocks、todos、transactions、diet_records、interactions、entry_images（仅元数据）、trades（R1 新增）、liability_payments；类别型：activities、contacts、goal_spaces、accounts、liabilities；AI 衍生型：user_ai_profiles、review_caches、entry_recognitions、audit_logs（AI 用量视角）。

### 8.4 验收标准

- [ ] categories 返回全部类别域且与定义位置一致（activities 为 DB 实时值）
- [ ] 任一行为数据集：时间范围+类别过滤正确（与各域现有口径对账抽样）；92 天/1000 条上限生效
- [ ] catalog 三分类正确；promptRefs 与 ai-inputs 注册表一致（改动注入项后目录同步）
- [ ] /admin「数据」tab 三块可用；未登录/非 admin 403；audit 有计数
- [ ] 试查大数据集不拖垮服务（强制分页）
- [ ] **个性化注入**：勾选数据集并保存后，该能力线上调用的 user prompt 含对应数据块（装配预览同构可见）；时间窗/条数/总字符上限生效；取消勾选即恢复；未配置的 key 行为零变化（回归）

## 10. 风险

| 风险 | 对策 |
|---|---|
| MT5 报表列结构变体解析失败 | 客户端解析复用参考页已验证逻辑；预览期拦截 + 报错样例指引；CSV 通道兜底 |
| 时区口径（MT5 UTC+2/3） | 预览明示转换口径，用户确认后入库 |
| 大数据量导入/渲染 | 分批 insert；明细分页、曲线按日聚合服务端算好 |
| 迁移数据对不上 | dryRun 逐行预览 + 迁移前后总额对账摘要 |
| 数据接口拉全表 | 强制时间范围（≤92 天）+ limit 上限 + 分页 |
| 交易数据敏感 | trading 模块授权门禁复用 031 体系 |
| AI 复盘 token 成本 / 个性化注入撑爆上下文 | 缓存+配额+admin 不限口径沿用；个性化注入总字符上限硬顶 + 装配预览所见即所得（超限标红禁存） |
