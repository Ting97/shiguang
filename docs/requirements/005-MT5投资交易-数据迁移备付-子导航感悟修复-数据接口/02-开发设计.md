## 2. 数据模型

### 2.1 R1 交易（`packages/db/migrations/037-trading.sql`）

```sql
create table if not exists public.trade_accounts (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null references public.profiles(id) on delete cascade,
  login      text not null,                       -- MT5 账号
  nickname   text,                                -- 用户备注名
  currency   text not null default 'USD',
  created_at timestamptz not null default now(),
  unique (user_id, login)
);

create table if not exists public.trade_imports (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null references public.profiles(id) on delete cascade,
  account_id uuid not null references public.trade_accounts(id) on delete cascade,
  file_name  text not null,
  source     text not null check (source in ('mt5_xlsx','csv')),
  rows_total int not null default 0,
  rows_new   int not null default 0,
  rows_dup   int not null default 0,
  first_at   timestamptz, last_at timestamptz,
  created_at timestamptz not null default now()
);

create table if not exists public.trades (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references public.profiles(id) on delete cascade,
  account_id  uuid not null references public.trade_accounts(id) on delete cascade,
  import_id   uuid references public.trade_imports(id) on delete set null,
  ticket      bigint not null,
  symbol      text not null default 'XAUUSD',
  direction   text not null check (direction in ('buy','sell')),
  open_time   timestamptz not null,
  close_time  timestamptz not null,
  lots        numeric(10,2) not null,
  open_price  numeric(12,5), close_price numeric(12,5),
  profit      numeric(12,2) not null default 0,
  commission  numeric(12,2) not null default 0,
  swap        numeric(12,2) not null default 0,
  net_profit  numeric(12,2) generated always as (profit + commission + swap) stored,
  unique (user_id, account_id, ticket)            -- 去重键
);
create index if not exists idx_trades_acct_close on public.trades (account_id, close_time desc);
create index if not exists idx_trades_user_close on public.trades (user_id, close_time desc);

-- 模块枚举扩展
alter table public.user_module_grants drop constraint user_module_grants_module_check;
alter table public.user_module_grants add constraint user_module_grants_module_check
  check (module in ('debt','trade_review','trading'));

-- AI 复盘：review 缓存/配额 kind 扩展（v1.1；约束名以 033 实际为准，drop+add 同 033 模式）
alter table public.review_caches     drop constraint review_caches_kind_check;

  check (kind in ('day','week','month','year','trade_week','trading'));
alter table public.review_gen_quotas drop constraint review_gen_quotas_kind_check;
alter table public.review_gen_quotas add constraint review_gen_quotas_kind_check
  check (kind in ('day','week','month','year','trade_week','trading'));
```

## 3. R1 投资交易模块设计

### 3.1 客户端解析器（新建 `apps/web/src/lib/mt5-parse.ts`）

移植参考页已验证逻辑（零服务端依赖、避免引入 xlsx 库）：

- xlsx 通道：`unzipEntries`（自实现 zip 目录解析 + `inflateRaw`）→ `parseSharedStrings` + `sheetToRows` → `extractFromGrid` 定位「持仓」区块列（Ticket/Type/Volume/Price/Open Time/Close Time/Profit/Commission/Swap 等，列序容错）；
- CSV 通道：`parseCSVText` 同列结构；
- 时间：按参考页 `toMs` 口径解析（MT5 服务器时区，标注 UTC+2/+3 与北京换算，预览明示）；产出 `TradeRow[]`（原始字符串→类型化）；
- 文件 ≤10MB 前置校验；解析失败抛带样例的结构化错误（首行内容回显）。

### 3.2 API（全部 `withModule("trading")`）

| 路由 | 说明 |
|---|---|
| `POST /api/trading/import` | body `{dryRun, login, nickname?, fileName, source, rows[]}`：dryRun → 查 `(user,account,ticket)` 已存集合，返回 `{rowsTotal, rowsNew, rowsDup, firstAt, lastAt, sample[]}`；commit → upsert trade_accounts + 建 trade_imports + 批量 insert（1000/批），返回 `{account, importId, rowsNew, rowsDup}` |
| `GET /api/trading/accounts` | 账号列表 + 汇总（笔数/手数/总净盈亏/胜率/时间范围） |
| `GET /api/trading/daily?accountId&from&to` | 按日聚合（北京时区切日）：`{ymd, net, count, lots, winRate}` + 日环比与连亏连赢标记 |
| `GET /api/trading/equity?accountId` | 累计净盈亏曲线（日粒度）+ 峰值 + 回撤段数组（起止/深度/金额）+ 峰值前后两阶段统计（频率/胜率/盈亏）——**服务端算好**，前端只画 |
| `GET /api/trading/trades?accountId&from&to&dir&period&durBand&page` | 逐笔明细分页（20/页）；归类筛选参数（时段/方向/时长档/盈亏档）SQL 内过滤 |
| `GET /api/trading/digest?accountId` | **规则统计素材**（AI 复盘的输入 + 兜底展示）：移植 `buildDigest/rulesSummary`（回撤点名日期金额、加频/加仓行为特征、两阶段对比）+ 归类聚合 + 典型逐笔样例（最大盈/最大亏/最长持仓各 N 笔）——纯计算零 LLM，页面"统计"卡常显 |
| `GET/POST /api/trading/review?accountId` | **AI 复盘**（v1.1）：GET 读缓存（review_caches kind='trading'）；POST 生成——user prompt 经 `getPromptBundle('trading_review')` 装配（素材块=digest 输出，注入项走 ai-inputs 注册表可配）→ `chatReviewJson` → {summary, highlights, suggestions}；配额 review_gen_quotas kind='trading'（周 5 次，admin 不限）；LLM 失败/额度不足返回 `{fallback:true, digest}` 前端展示规则版并标注降级 |

归类维度 SQL：时段 = `(close_time at time zone 'Asia/Shanghai')::hour` 分桶（morning/afternoon/evening/lateNight）；时长档 = `close_time-open_time`（<15m/15-60m/1-4h/>4h）；盈亏档 = net_profit 符号与分位。

## 4. R2 数据迁移设计

### 4.1 导出脚本（新建 `scripts/trade-export.mjs`，node ≥18 直跑）

- 读 `/opt/aitrade/资产/data.js`（IIFE 挂 window.DB → `vm.runInNewContext` + window shim）与 `贷款配置.js`（LOANCFG overrides 合并）；
- 输出 `shiguang-import.json`：`{ exportedAt, liabilities: [...], accounts: [...] }`。

**字段映射表**（loans → liabilities 行）：

| data.js 字段 | 目标列 | 转换 |
|---|---|---|
| bank | name | 直取 |
| group（balloon/amort/card/family）+ method | type | balloon→`mortgage`/`consumer_loan`（按 bank 含"信用卡"判 credit_card）、card→`credit_card`、family→`family`；映射表内置兜底 `consumer_loan` |
| principalWan | principal_cents | ×10000×100 |
| （当前余额） | balance_cents | 首次导入=principal（用户导入预览可改） |
| ratePct | rate_pct | 直取 |
| monthlyVal | monthly_cents | ×100（0/空→null） |
| payDay（"20日"/"7/23日"） | pay_day | 取首个数字 |
| balloon / clearDate（'2028-05'） | due_date | 取最早到期 → 月首日 |
| priority（'C3'） | priority | 序号映射（A=1…E=5 + 原字母备注入 note 前缀） |
| note（含 HTML） | note | 剥 HTML 标签 |

assets → accounts：bankWan→现金/银行卡期初、securitiesWan→新建「证券」账户行（预览呈现，勾选导入）；family 不导 accounts。

### 4.2 拾光导入（`POST /api/debts/import`，withModule("debt")）

- body `{dryRun, data}`（data=上述 JSON）：dryRun → 逐行判重（name+type 已存在）→ 返回预览行 `{name,type,principal,monthly,action: create|skip|update-balance,exists}` + accounts 对照行 + 前后总额对账摘要；
- commit → 事务插入 liabilities / 更新 accounts 期初（仅勾选项）→ 返回创建/跳过计数与对账。
- 负债页「📥 导入」入口：抽屉粘贴 JSON / 上传文件 → 预览表格（可勾选）→ 确认（复用 bill-import 范式）。

## 7. R5 后台数据接口设计

### 7.1 数据集注册表（新建 `apps/api/src/lib/admin-data.ts`）

```ts
interface DatasetSpec {
  key: string; name: string; partition: "category" | "behavior" | "derived";
  desc: string; timeCol: string;        // SQL 列（白名单）
  categoryCol?: string;                 // 类别维度列
  columns: string[];                    // 返回字段白名单
  promptRefs?: string[];                // 被哪些 prompt key 注入（与 ai-inputs injects.source 对应，静态映射+注释同步约定）
}
```

首版数据集（behavior）：entries、time_blocks、todos、transactions、diet_records、interactions、trades、liability_payments；（category）：activities、contacts、goal_spaces、accounts、liabilities；（derived）：user_ai_profiles、review_caches、entry_recognitions、audit_logs。

### 7.2 API（getAdminUser 门禁，全只读）

| 路由 | 说明 |
|---|---|
| `GET /api/admin/data/categories` | 类别域分组：activities（DB 实时）、TX_CATEGORIES、CONTACT_GROUPS、spaces（DB）、DEBT_TYPE_META、mood 档位、时段枚举——含定义位置注释 |
| `GET /api/admin/data/catalog` | DATASETS 元数据全量 + promptRefs；`_meta: { note: "promptRefs 与 ai-inputs 注册表人工同步" }` |
| `GET /api/admin/data/[dataset]?from&to&category&limit&offset` | 强制 from/to（≤92 天）；列白名单拼 SQL（参数化，category 为等值/IN）；limit 默认 200 上限 1000；返回 `{total, items}`；audit `stage='admin_data'` 计数 |

### 7.3 /admin「数据」tab（`components/admin-data-panel.tsx`）

三块：类别清单（分组折叠）→ 数据目录表（partition 徽标 + promptRefs 徽标 → 链到 AI 管理对应 key）→ 在线试查（选数据集 + 日期区间 + 类别下拉 → 表格预览前 50 行 + total）。静态导出无风险（门禁在 API）。

### 7.4 个性化数据注入（FR-5.6，v1.1 新增）

打通 R5 数据目录与 003 A 部分输入装配——**AI 管理每个 prompt key 可勾选注入用户个性化数据**：

- **存储**：`ai_prompts.context_config` 增 `userData` 字段（029 加列时 context_config 为 jsonb，天然容纳，**零新迁移**）：

```jsonc
// context_config.userData: [
//   { "dataset": "entries",  "days": 14, "limit": 20 },   // 近 14 天动态 ≤20 条
//   { "dataset": "todos",    "days": 7,  "limit": 10 },   // 近 7 天 todo 完成情况
//   { "dataset": "user_ai_profiles" }                     // 用户画像（无时间窗）
// ]
```

- **装配**（`prompts.ts assembleUserPrompt` 扩展）：注册表每 key 新增**可选占位符 `{userData}`**（不在 placeholders 必需集，缺省不注入）；装配时按 userData 配置逐项调用 `admin-data.ts` 的**同源查询函数**（服务端内部直调，非 HTTP；按当前请求用户取数）→ 每数据集生成一段文本块（标题 + 逐行摘要，与 FR-5.2 返回同构）拼接注入 `{userData}`；未配置 = 无该块（现状不变）。
- **护栏**：每数据集条数上限（≤50）+ 时间窗（≤92 天）+ **注入总字符硬顶（默认 8000 字符，caps 可调）**——超限保存 400 拒绝并列明哪个数据集超了；装配预览实时展示注入块与字符数（所见即所得）。
- **UI**（admin-ai-panel「输入装配」段扩展）：「个性化注入」区——数据集多选（来自 catalog，behavior/derived 分区可选，category 分区置灰）+ 每项 days/limit 输入 + 底部实时总字符统计条；保存走既有 PUT 三件套（随 context_config 版本快照与回滚）。
- **默认关闭**：全部 key 初始 userData 为空，零行为变化；典型用法示例写进 UI 提示（如 extract_full 注入近 7 天动态提升指代消解、todo_decompose 注入最近完成 todo 避免重复建议）。
- **promptRefs 联动**：catalog 的 promptRefs 计算**包含 userData 勾选**（某数据集被某 key 个性化注入也算引用），目录页双向可见。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| MT5 报表列结构变体 | 解析层列序容错 + 预览期拦截；CSV 兜底通道；保留原始文件名入 imports 便于排查 |
| MT5 时区（UTC+2/3 DST）误判 | 预览明示换算口径由用户确认；解析口径集中在 toMs 一处可调 |
| 大批量导入 | 1000/批 insert + 单事务；导入页 loading 态；明细/曲线全部服务端聚合 |
| 迁移映射边界（group→type 歧义） | 映射表兜底 consumer_loan + 预览行可改（用户在确认前修正类型） |
| 数据接口注入/全表拉取 | 列/数据集双白名单 + 参数化 + 强制时间窗与 limit；只读 |
| promptRefs 漂移 | catalog `_meta` 注明人工同步约定；review checklist 增加"改 ai-inputs 时同步 admin-data" |
| 个性化注入撑爆上下文/泄漏过多个人数据 | 总字符硬顶 + 预览所见即所得；数据块只进 user prompt 不落库；默认全关；装配审计记字符数 |
| Expo 屏新增后包体/OTA | 纯 JS 层无新原生依赖，OTA 可推 |
