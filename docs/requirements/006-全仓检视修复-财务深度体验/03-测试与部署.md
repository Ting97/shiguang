## 二、财务模块深度体验（GUI 实测）

**环境**：本地 3100 standalone 真实链路（dev 库 + AUTH_DISABLED=1）；PC 1440×900、移动 390×844 视口。

**PC 实测通过**：记一笔全链路（空金额禁用记入 → 填单提交 → 关表单 → 列表/账户/分类联动刷新，微信账户出现 ¥-88.50 ⚠ 透支警示）；预算设置（¥2000 保存 → 进度条 74.4%）；待确认流水确认（✓ → 展开记入账户选择器 → 选现金 → 待确认 6→5、支出 +¥18 正确入账并带账户标）；快速切月竞态（连点 ››‹› 头部与数据一致、无上月残留）；负债页备付勾选（勾房贷 → 已备付 ¥3000/¥3400·88%，API 逐项校验）；交易页（账号 chips/汇总/每日盈亏柱/权益曲线——两点 218→65 陡降经 API 核对为真实比例）；收支复盘周视图（日趋势/分类/账户分布/Top 对方与流水一致）。

**移动端实测通过**：底部抽屉式记账弹层布局、负债页 2×2 统计与备付清单、账户卡双列、导航（重载后完整无截断——此前截图为浏览器合成伪影）。

**体验中发现并修复的 bug（2 个）**：

1. **备付「储蓄覆盖」账户金额全部显示 ¥NaN**（PC+移动）：`/api/accounts` 返回 snake_case `balance_cents` 而 reserve-section 读 camelCase `balanceCents` → undefined；且该接口漏返回 `reserve_tracked`（参与勾选状态永远丢失）。修复：两个接口（accounts、finance/overview accounts）统一 camelCase 规范字段（snake_case 兼容一版），web 侧三个消费方（reserve-section/finance kit/finance forms/accounts-card）对齐。GUI 复测 NaN 清零、勾选状态可写。
2. **移动端结余 `-¥1506.50` 断行成「-」+「¥1506.50」两行**：结余数字加 `whitespace-nowrap`。复测单行。
