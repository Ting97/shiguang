## 一、训记 Open API 速查（实测确认）

| 用途 | 端点（POST） | body 要点 |
| --- | --- | --- |
| 读训练 | `https://trains.xunjiapp.cn/api_trains_for_llm_v2` | `{"schema_version":"train_open_api_v2","datestr":"YYYY-MM-DD","include_full_data":bool}` |
| 写/建训练 | `https://trains.xunjiapp.cn/api_upsert_trains_for_llm_v2` | `{"schema_version":"train_open_api_v2","client_request_id":"唯一","res":[<train>...]}` |
| 动作目录 | `https://trains.xunjiapp.cn/api_movement_catalog_for_llm_v2` | 259 常用动作，做官方名校验表 |

- 认证 `Authorization: Bearer <key>`（key 格式 `xjllm_...`，只支持 header）。
- **响应为 gzip**（Node fetch 自动解压；curl 探测需 --compressed）。
- 成功判定：HTTP 200 + `res` 为**对象/数组**；失败时 `res` 是错误文案字符串（实测 `{"success":false,"res":"too frequent, retry after 20s"}`），或 `error` 字段。
- 读响应形状（实测）：`{res:{schema:"train_open_api_v2", datestr, limits:{...}, trains:[...]}}`——**trains 在 res.trains**，不是 res 直接是数组。
- 错误：`apikey missing/invalid`→回 App 重申请；`仅VIP可用`→提醒会员；`too frequent`→解析 retry after Ns 提示等待。
- 限频（读响应 limits 实测）：读 full 30s / 写 45s——客户端 90s 按日缓存天然满足读限。

### train 对象（写入形态；实测补全 2026-10-14）

- **train 必带 `datestr`（北京日）与 `title`**——缺一分别报 `datestr invalid` / `title missing`。
- `localid` 为**数字**；`start/end` 为 **epoch 毫秒**；新建可不带 start/end，更新必须原样保留 localid/start/end。
- 力量：`{"datestr":"2026-10-15","title":"课A·推+轻腿","movements":[{"name":"官方中文名","restTime":90,"difficulty":"normal","sets":[{"done":false,"weight":"8","unit":"kg","reps":"10"}]}]}`（计时动作组用 `"time":"45"`，动作 `exetype:"record"`）。
- 有氧日：单 movement `"cardio":true, "recordPreset":"running"` + `"metrics":{...}`，不传 sets。
- catalog 响应形状（实测）：`{res:{schema:"movement_catalog_v1", movements:[{name, type, exetype, aliases:[...]}]}}`——动作名+别名一并入校验集合。
- 上限（读响应 limits）：写 15 动作/训练、20 组/动作、4 训练/日、payload 128KB。

## 三、后端

### `apps/api/src/server/platform/config.ts`

getter `xunjiApiKey(): string | null`（`XUNJI_API_KEY`）；`.env`/`.env.example` 补条目。key 值从 `../life/.xunji_api_key` 注入本地 .env，不打印。

### `apps/api/src/server/fitness/xunji.ts`（新文件；SQL 仍在 repo.ts，本文件纯客户端+映射）

- `xunjiPost(path, body)`：Bearer + FetchLike 注入（仿 bitget-client）+ 15s 超时；错误分类成 `ApiError`（503 upstream，msg 带官方提示语义）。
- 读缓存：`Map<datestr, {at:number, data:unknown}>`，TTL 90s；`readTrains(datestr, full)` 命中即返；写成功后以响应 `res` 覆盖缓存（官方踩坑 3）。
- `fetchMovementCatalog()`：目录名集合，进程内缓存 1h。
- **纯函数（单测主战场）**：
  - `planToTrains(plan)`：StrengthPlanContent→1 条 train（movements 从 exercises 映射：官方名（`XUNJI_NAME_ALIAS` 双向表 + catalog 校验）、`sets` 数=sets、reps=**repsText 解析出的次数上限**（"8-12"→"12"，双递进语义）、weight=weightG→kg 一位小数字符串；`TIME_LIKE` 动作（平板支撑等）→`exetype:"record"`+`time`=repsText 秒数）；RunPlanContent→有氧日 train。超上限（>15 动作/>20 组）抛错。
  - `trainsToActual(trains, plan)`：只取 `done:true` 组 → 每动作聚合实际 `{name(反查回拾光名), sets, repsText, weightG}`；返回 `{exercises, completion}`（完成组/计划组比例 → done|partial 判定参考）。
- 名称映射表（拾光种子名 ↔ 训记官方名，已知：高脚杯深蹲↔哑铃酒杯深蹲、哑铃肩推↔哑铃推肩；侧平举/平板支撑/哑铃卧推同名）；未匹配→抛错列名。

### 端点（`apps/api/src/app/api/fitness/plans/[id]/…`，全 withAuth + assertUuidParam）

- `POST .../sync-xunji`：校验归属与状态（draft/confirmed）→ `planToTrains` → 若 `xunji_sync.localids` 存在则 train 带 localid（更新）→ 写入 → 回写 `xunji_sync`；响应 `{synced:true, movements:n}`。
- `POST .../pull-xunji`：读当日（include_full_data）→ `trainsToActual` → 无 done 组 400「训记里还没有打勾的组」→ 有则调 `fitnessService.updatePlan(userId, id, {status: done|partial, actual, note:"同步自训记 App"})`（复用 016 状态机：落日志+行动完成）；响应打卡摘要。
- `POST /api/fitness/plans` 入参加 `syncXunji?: bool`：落库+联动成功后尝试写训记，失败不抛错，响应附 `xunjiWarning`（FR-A1）。
