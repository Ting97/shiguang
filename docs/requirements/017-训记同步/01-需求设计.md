# 017 · 训记（SynFit）Open API 集成：计划双写 + 完成回读

> 状态：开发中 · 版本 v1.0 · 2026-10-14
>
> 背景：016 健身模块已上线「计划中心 + 今日行动联动 + 助手确认卡」。用户实际训练现场使用**训记 App**（SynFit）打勾记录实练重量×次数；`../life/fitness/xunji-api.md` 已实测打通训记 Open API（含官方 Skill 硬规则与踩坑记录）。本批把训记接入拾光：**拾光排计划 → 双写训记 → 训练现场 App 打勾 → 手动回读自动打卡**，形成闭环。

## 一、用户故事

- US1 作为用户，助手生成/我导入的当日计划确认后，**自动出现在训记 App 里**（计划组未打勾），训练时直接在 App 打勾记录实练——不用在两个地方各记一遍。
- US2 作为用户，训练完成后在拾光计划卡上点「从训记同步完成」，拾光自动打卡：实练重量×组×次落执行日志、联动今日行动完成——次日助手点评有真实数据。
- US3 作为用户，跑步课也同步为训记有氧日（cardio），全部训练单入口在训记 App。
- US4 作为用户，问助手「昨天练得怎么样」，助手可查训记当日实练数据做点评（即使还没回读打卡）。

## 二、功能需求（FR）

### FR-A 计划双写（拾光 → 训记）

- A1 确认卡（A.5）底部勾选「同时写入训记 App」（默认勾选）；保存时先落拾光计划+联动行动，**再写训记**；训记失败仅提示警告，**不回滚拾光**。
- A2 健身页计划卡「同步训记」按钮（draft/confirmed 且未打卡可用）；重复同步**走更新**（保留 localid/start/end），不重复建训练。
- A3 力量计划 → 训记动作对象（官方中文名 + 计划组 `done:false`：目标重量/次数；计时动作用 `time`）；跑步计划 → 有氧日（`cardio:true` + running preset + 距离/时长 metrics）。
- A4 动作名只用训记官方名：内置映射表 + movement catalog 校验；未匹配名拒绝同步并列出，由用户改名或确认。

### FR-B 完成回读（训记 → 拾光）

- B1 计划卡「从训记同步完成」：读当日实练（只取已打勾组）→ 预览确认 → 自动打卡 done（全部完成）/partial（部分组完成）+ actual 落日志 + 联动行动完成。已打卡计划拒绝。
- B2 聊天只读工具 `query_xunji_trains`：按日期查训记当日训练（默认昨天）；仅用户问及训记/当日实练时调用（官方规则 1）。

### FR-C 官方 Skill 硬规则服务端化

- C1 写前必须展示摘要并经用户确认（拾光确认卡/按钮即该确认，不在无确认路径写训记）。
- C2 按日期读缓存 90 秒；`too frequent` 按提示 retry 秒数等待/提示。
- C3 上限：单次 ≤4 条训练（同日）、每条 ≤15 动作、每动作 ≤20 组；每组至少 weight/reps/time/selfWeight 之一。
- C4 更新保留 `localid`/`start`/`end`；不带 localid 为新建；不删除已有训练。
- C5 禁用 dry_run（实测会真实落库）；写后用响应 res 覆盖当日缓存供验证。
- C6 key 管理：`XUNJI_API_KEY` 只存 .env（经 config.ts 读取），不落日志、不回显。

## 三、验收标准（AC）

1. 助手卡片勾选保存 → 拾光出现计划与今日行动，训记 App 当日出现对应训练（计划组未打勾）；取消勾选只落拾光。
2. 同一计划二次「同步训记」→ 训记更新原训练（localid 复用），**不产生重复**。
3. 训记打勾部分组 → 拾光「从训记同步完成」→ 计划 partial、actual 含实练明细、行动完成；全打勾 → done。
4. 助手「昨天练得怎么样」→ 走 query_xunji_trains 引用真实组数×重量。
5. 未配置 XUNJI_API_KEY → 相关按钮禁用+提示，聊天工具返回「未配置」而非 500。
6. 全门禁绿（test/lint/typecheck/build）+ 生产部署后线上双向实测。

## 四、非目标

自动定时拉取（违背官方按需读取规则）、训记官方计划接口（query_gzip）、删除接口（官方无）、多用户独立 key 绑定、miniapp 端、把训记当拾光计划的数据源（拾光仍是计划中心）。
