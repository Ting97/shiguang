### 3. 冒烟暴露并修复的契约问题（curl 直连实测）

| 问题 | 修复 |
| --- | --- |
| 默认 fetch 少 `method:POST`（GET 带 body 被 undici 拒绝） | 补 method |
| train 缺 `datestr`（报 datestr invalid；body 顶层放 datestr 无效，须在 train 上） | planToTrain 带 datestr |
| train 缺 `title`（报 title missing） | planToTrain 带 title |
| 读/写响应 `res` 是对象 `{trains:[...]}` 非数组；`localid` 是数字、`start/end` 是 epoch 毫秒 | 解析 res.trains；类型放宽 string\|number |
| 失败形态 `{success:false,res:"too frequent, retry after 20s"}`——错误文案在 res 字符串 | 成功判定收紧（res 须对象/数组）；too frequent 解析 retry 秒数 |
| catalog 形状 `{res:{movements:[{name,aliases}]}}` | 解析 movements+aliases 入校验集合 |
| 模型复述训记计划时无目标数据可说 | 工具返回补 `target`（首组 重量×次数） |

限频实测（读响应 limits）：读 full 30s / 写 45s / 写 15 动作/训练、20 组/动作——客户端 90s 按日缓存天然满足读限。

契约细节已回写：本目录 02 文档 + `life/fitness/xunji-api.md`（用户研究笔记）。

## 五、后记：确认卡「同时写入训记」默认改为不勾选（2026-10-16，REQ-024 后记）

用户要求「生成的训练计划在点击确认之前不同步给训记」：原勾选框默认 `useState(true)`，点「保存」会捎带写入训记——训记侧没有独立确认动作。现默认不勾选，写训记必须主动勾选后保存；计划卡上的「同步训记」按钮仍为显式入口。行为基线：**生成/保存计划永远不自动触碰训记**。
