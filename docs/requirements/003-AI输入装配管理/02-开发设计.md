## 1. 现状基线

## 2. 数据模型（`packages/db/migrations/028-ai-input-config.sql`）

```sql
-- ai_prompts 加两列：user 模板覆盖 + 注入配置（均 null = 代码默认，向后兼容存量行）
alter table public.ai_prompts add column if not exists user_template text;
alter table public.ai_prompts add column if not exists context_config jsonb;
-- context_config 形态：{ "inject": { "catList": false, "profile": true, ... },
--                        "caps":   { "entryLines": 40, "contactNames": 50, ... } }

-- 版本快照升级为三件套；content(text) 保留兼容旧版本（回滚优先 payload，老版本回退 content）
alter table public.ai_prompt_versions add column if not exists payload jsonb;
-- payload 形态：{ "system": "...", "userTemplate": "...", "contextConfig": {...} }
```

纯加列、幂等；上线即刻零行为变化（新列为 null → 代码默认）。

## 3. 输入注册表（新建 `apps/api/src/lib/ai-inputs.ts`）

代码内注册表定义每个 key 的**可调面**，后台只开放注册表内的项：

```ts
export interface InputSpec {
  userTemplate: string;        // 代码默认 user 模板（含占位符，如 {nowCst} {catList} {text}）
  placeholders: string[];      // 该 key 合法占位符全集（保存校验用）
  injects: Array<{ key: string; label: string; desc: string; source: string;
                   required?: boolean; default: boolean }>;
  caps: Array<{ key: string; label: string; min: number; max: number; default: number }>;
}
export const AI_INPUT_REGISTRY: Record<PromptKey, InputSpec>;
```

**各能力注入项注册表（首版盘点，基于已上线实现）**：

| key | user 输入构成 | 可调注入（默认开/必需） | 可调参数（默认） |
|---|---|---|---|
| extract_full | 当前时间 + 分类对照 + 联系人名单 + 用户话术 | 分类对照（开）、联系人名单（开）；时间/话术**必需** | 分类对照条数（50）、联系人条数（100） |
| extract_domain_schedule/todo/finance/mood/diet | 当前时间 + 用户话术 | —（仅 people 有名单）；时间/话术**必需** | — |
| extract_domain_people | 当前时间 + 联系人名单 + 用户话术 | 联系人名单（开） | 联系人条数（100） |
| review_day | 日事实聚合（必需）+ 动态明细 + 日程块明细 + 完成 todo 明细 + 画像块 | 三类明细各自开关（开）、画像（开） | 各明细行上限（现状 withCap 值） |
| review_week/month/year | 期事实聚合（必需）+ 各明细 + **下层小结链**（周←日/月←周/年←月）+ 画像块 | 明细开关、**小结链开关**（开）、画像（开） | 各明细行上限 |
| profile_merge | 旧画像 + 本月事实 + 本月复盘（全**必需**） | — | 画像条数上限（40） |
| space_classify | 候选空间列表 + 动态原文（全**必需**） | — | 候选空间上限（20） |
| todo_decompose | todo 标题+note（必需）+ 空间上下文 + 画像块 + 已有行动清单 | 空间上下文（开）、画像（开）、已有行动清单（开，去重依据） | 已有行动条数（30） |
| action_decompose | 行动+父 todo 上下文（必需）+ 空间上下文 + 画像 + 已有行动清单 | 同上 | 同上 |
| prompt_optimizer | key 用途+契约（必需）+ 当前内容（必需）+ 优化意图 | — | — |

## 4. 读取与装配（扩展现有 `apps/api/src/lib/prompts.ts`）

```ts
// 三件套读取：ai_prompts(enabled) 覆盖 → 代码默认；60s 进程缓存，PUT 主动失效（沿用既有机制）
export async function getPromptBundle(key): Promise<{
  system: string; userTemplate: string;
  config: { inject: Record<string, boolean>; caps: Record<string, number> };  // 合并默认值
}>

// 统一装配器：占位符替换 + 按开关/参数裁剪数据块
export function assembleUserPrompt(key, bundle, ctx: Record<string, unknown>): string
```

- **调用点接入**（替换硬编码 build 调用）：`apps/api/src/lib/analyze.ts`（extract_full / space_classify / decompose）、`entries/[id]/recognize`（单域）、review 四路由（明细 withCap 改读 caps）、`review-input.ts`（profile_merge；`loadProfileBlock` 受 inject.profile 控制）、decompose 路由。
- packages/ai 保持纯包：包内 `buildXxxPrompt` 保留为代码默认装配实现；apps/api 拿 bundle 后传入或覆盖。
- 关闭注入项：装配器按 `inject[key]` 跳过对应 ctx 块；明细类上限在 SQL LIMIT 生效（查询前读 caps，省 token 而非只截字符串）。

## 5. admin API（扩展现有 `/api/admin/prompts`）

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/admin/prompts` | GET | 清单响应扩展：`{ ..., userTemplate, userTemplateDefault, contextConfig, registry: InputSpec }`（注册表全文下发：占位符/注入项/参数范围，前端据此渲染） |
| `/api/admin/prompts/[key]` | PUT | body 扩展 `{ userTemplate?, contextConfig? }`；校验：模板占位符完整性（缺失/未知 → 400 列明）、caps 范围（min/max）、required 注入项不可为 false；保存写三件套快照 + 清缓存 |
| `/api/admin/prompts/[key]/restore` | POST | 回滚逻辑升级：优先取版本 `payload`（三件套），老版本（无 payload）仅回滚 system content |
| `/api/admin/prompts/[key]/preview` | POST | **装配预览**：body `{ sample?: string, period?: string }`（样例话术/复盘期段，缺省取管理员最近真实数据）→ 按**当前 bundle** 走与线上同一条 `assembleUserPrompt` → 返回 `{ userPrompt }`；**不调 LLM、零 token**；不落库，audit 仅记 `stage='prompt_preview'` 计数不记内容 |
| `/api/admin/prompts/[key]/optimize` | POST | 001 已上线，不变（优化的是 system；后续可扩展优化 user 模板，二期） |

## 6. /admin 前端（AI 管理详情页改三段）

1. **System prompt**：现状编辑器不变。
2. **输入装配**（新）：user 模板编辑器（等宽 textarea + 占位符高亮提示：注册表列全部合法占位符、当前模板缺失项标红 + 「一键补齐」）+ 注入项开关列表（label/desc/来源/required 锁定态）+ 参数数字输入（min/max 校验）+ **「装配预览」**：输入样例 → 右侧等宽面板展示最终 user 输入全文（与线上同构）。
3. **版本历史**：快照三件套展示（system/user/配置摘要），回滚整体恢复；启用开关关闭 = 整 key 回退代码默认。

保存一次提交三段（未改字段原样回传），走同一 PUT；沿用既有 403 门禁（`getAdminUser`）与 N3 浮层交互（002 已上线 Dismissable）。

## 7. 实施步骤

1. 028 加列（本地 + 服务器执行，幂等）。
2. `ai-inputs.ts` 注册表 + `getPromptBundle`/`assembleUserPrompt` + 单测（占位符校验、开关联动、默认值合并）。
3. /admin UI 三段改造 + preview 端点。
4. 逐能力接入装配器并回归：**extract_full → 六单域 → review 四档 → decompose/space_classify/profile_merge**（每接入一个即可部署观察）。

## 8. 测试要点

| 域 | 要点 |
|---|---|
| 校验 | 删占位符/加未知占位符保存被拒并提示；一键补齐后可存；caps 超范围被拒；required 注入前端锁定 + API 强拒 |
| 装配 | 开关关闭/参数调小后预览对应块消失、SQL LIMIT 生效；模板占位符替换正确（含转义边界） |
| 预览 | 零 token（audit 无 LLM 调用记录）；结果不落库/日志不记内容；未配置 key 预览 = 代码默认装配 |
| 版本 | 三件套快照完整；回滚整体恢复（含老版本仅 system 的兼容分支）；启用开关整 key 回退默认 |
| 回归 | 未配置 key 的各能力行为与当前线上一致：发动态识别、单域重识别、复盘四档（缓存/配额）、AI 拆解、空间归属、prompt 优化 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 配置调错导致识别/复盘劣化 | 三件套整体回滚 + 启用开关秒切默认；预览零成本验证；required 锁定；cap 在 SQL LIMIT 层生效 |
| 代码占位符演进 vs DB 旧覆盖模板脱节 | 保存时完整性校验拦截 + 一键补齐；注册表为唯一事实源 |
| 逐能力接入的回归面大 | 接入顺序分小步（§7.4），每步全量回归该能力；audit_logs 对比改造前后 token 用量 |
| 预览接口泄露个人数据 | 仅 admin 会话；结果不落库；日志只记计数 |
