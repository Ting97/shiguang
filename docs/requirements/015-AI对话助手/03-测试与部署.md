# 015 · AI 对话助手批次 A：chat 域 + 工具循环 + web 对话页（2026-10-12）

> 批次性质：智能化升级路线第一批（已确认路线：A 对话助手 → A.5 操作确认卡 → B RAG 记忆 → D 对外 MCP 端点）。定位「懂用户数据的私人经营助手」：**只读查询 + 建议教练**；写操作走 A.5「操作意图确认卡」（复用全站「AI 提议、人确认」范式），本批不含。**含一个新迁移（052，chat_conversations/chat_messages）**；小程序已暂停，全部改动仅 web/api/packages。

## 一、方案定案（与用户确认的三个决策）

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 工具层实现 | **原生 tool-calling**（进程内函数注册表，AI SDK `generateText({tools, maxSteps})`），不用 MCP/Skill | 应用内助手无跨客户端复用需求；注册表设计为协议无关（`{name, description, params(zod), execute(ctx, args)}`），批次 D 包 MCP server 零改动复用 |
| chat 配额 | **free 10 次/北京日，独立口径**（audit_logs stage='chat' ok=true 当日计数），Pro/admin 不限 | 与 30 次/30 天打卡配额（parse/review/asr）完全独立——对话高频，混口径会烧光打卡额度 |
| 上线边界 | 先只读，尽快跟 A.5 操作卡 | 建立查询信任后再给写权限；写操作永远经确认卡、不静默 |

## 二、实现清单

### packages/ai（纯包，禁 import DB）

- `src/glm.ts`：新增 `chatAgent(opts)`——多轮 messages + `AgentToolSpec[]`（zod 参数契约 + execute）+ maxSteps=5 循环；工具 execute 抛错时错误对象回传模型（循环不炸，模型改道或如实告知）；整循环总预算默认 60s，rate/server/network 失败重试一次（工具只读幂等），quota 触发全局熔断（与 chat() 同口径）。SDK 错误分类抽公用 `classifySdkError()`（原 sdkOnce 内联逻辑，行为不变）
- `src/prompt.ts`：新增 `CHAT_ASSISTANT_SYSTEM_PROMPT`（只依据工具查询结果回答、严禁编造数字、北京时间口径、建议克制、引导记账去首页动态）

### apps/api `src/server/chat/`（新域，跨域只准 import 其 index.ts）

- `tools.ts`：**协议无关工具注册表**，8 个只读工具（白名单参数化 SQL，一律强制 user_id 过滤；跨域读表登记 `CHAT_READABLE_TABLES` 照 insight 域 CQRS 模式）：
  1. `query_time_blocks`（区间活动时长聚合 + 最近明细）2. `query_transactions`（已确认流水收支汇总 + top 分类）3. `query_todos`（open/due_soon/done_recent）4. `query_contacts`（含 staleOnly 久未联系：importance≥4 且 30 天无往来）5. `query_interactions`（按人 ilike 匹配 + 往来明细含礼金）6. `query_mood`（近 N 天心情走势 + 均分）7. `get_review`（读 review_caches 已有小结，无缓存明确返回）8. `get_user_profile`（用户 AI 画像）
  - 金额统一「分」整数返回（提示词约定模型换算为元表述）；时间列一律 `to_char(col at time zone 'Asia/Shanghai')` 服务端转北京钟面（模型不做时区算术）；区间守卫 from≤to 且 ≤366 天
- `chat-quota.ts`：`getChatQuota/checkChatQuota`，free 10 次/北京日（`date_trunc('day', now() at tz 'Asia/Shanghai')` 日界），复用 ai 域 `isProValid`
- `service.ts`：`sendMessage` 编排——配额检查 → 会话定位（传入 id 校验属主，否则首句前 20 字建新会话）→ 落用户消息 → 历史 20 条回放 → system = 纳管 prompt（`getPromptBundle('chat_assistant')`）+ 上下文块（`assembleUserPrompt` 注入 toCstWallClock 当前时间；画像可经 context_config.userData 配置注入）→ chatAgent → 落助手消息（tool_calls JSONB 轨迹随行）→ 审计（stage='chat'，成败都记，配额只数成功）。改名/软删（deleted_at，列表隐藏行保留）
- 路由：`GET /api/chat`（列表+配额；`?id=` 会话历史）、`POST /api/chat`（发消息，zod 校验 conversationId?/text≤2000）、`PATCH|DELETE /api/chat/[id]`（改名/软删，属主守卫 + assertUuidParam）

### ai_prompts 纳管（管理台可调热更）

- PROMPT_KEYS 增 `chat_assistant`（category 新增「助手」，web 管理面板联合类型同步两处）；user 模板 = `## 用户上下文\n当前时间：{nowCst}`（nowCst 必需注入）；DEFAULT_PROMPTS 引包内 `CHAT_ASSISTANT_SYSTEM_PROMPT`——后台改文案 60s 缓存后生效

### apps/web

- 新页 `/assistant`：消息流 + 输入框（Enter 发送/Shift+Enter 换行）+ 空态快捷提问 chips×5 + 会话侧栏（PC 左栏/移动横滑，两步确认删除，全站 useArmConfirm 规范）+ 等待期文案轮换（理解问题→查询数据→整理回答）+ 工具轨迹徽标（「已查询：收支流水」）+ 配额徽标（「今日 3/10 次」/「Pro · 不限次数」）
- 首页右下角「✨AI 助手」悬浮入口（避开底部中央发布圆钮）；客户端超时放宽 90s（服务端 LLM+查询总预算 60s）
- MVP 非流式；失败保留已落库的用户消息、toast 错误、输入回填可重发
- 助手回复 Markdown 渲染：react-markdown + remark-gfm（默认不渲染原始 HTML，XSS 安全），元素映射全站设计令牌（`components/markdown.tsx`）；助手 prompt 同步补排版约定（加粗/列表/小表格，禁代码块与多级标题）

### 迁移 052（只增不改）

- `chat_conversations`（user_id/title/deleted_at/updated_at，user+updated_at desc 索引）+ `chat_messages`（conversation_id/user_id 冗余属主/role user|assistant|tool/content/tool_calls JSONB；conv 内时间序 + user 时间序双索引）。role 含 'tool' 预留，MVP 只落 user/assistant（工具轨迹凝结在 assistant 行 tool_calls）
