拾光 · 系统架构与业务架构总览

个人经营系统「钱 · 时间 · 人」——一句话 / 一段语音，AI 五域识别同时落进时间轴、财务账、人情簿，并做钱×时间×人的交叉复盘
线上：shiguang.ting97.cn Monorepo · 4 端 · 21 组 API · 21 张表 AI-First（GLM） 整理日期 2026-09-21 docs/12
TL;DR

一个 Next.js 同构单服务的全栈应用 + 多端壳：apps/api（Next.js standalone）同域承担「全部 REST API + Web 静态托管」，apps/web 纯静态导出由它服务；移动端是 Expo 原生 App（主力）与 WebView 壳两条线。业务内核是 AI-First 五域识别管线：一句话经 GLM 抽取「日程 / 待办 / 收支 / 心情 / 饮食」五域，高置信直接落库、低置信转待确认，时间日期由确定性引擎锚定防漂移；在此之上是日/周/月/年四级交叉复盘（喂全量明细 + 用户画像，越用越懂）与商业化配额（free/pro）。部署为腾讯云单机（Caddy + systemd + PostgreSQL 13），双 tar 秒级回滚发布。

一、业务架构：三轴一体

产品的一切功能都围绕三条业务轴展开，核心差异化在「一句话同时命中多轴」——"中午和老王吃饭花了260" 同时生成：日程块（社交·60min）+ 财务流水（餐饮支出 ¥260，对手方老王）+ 人际往来（老王·吃饭），数据天然打通。

⏱
时间轴（Time）

说一句"刚跑完步40分钟"→ AI 识别类别与起止 → 四级日历自动登记：日 24h 时间轴 / 周列式 / 月历 / 年度热力图。含待办（未来话术自动建 TODO，完成回写日程）。

💰
财务账（Money）

话术中含金额自动入账（收支方向/分类/对手方）；支付宝·微信账单 CSV 导入去重；账户体系；预算（月度上限预警）；分类统计与报表。

👥
人情簿（People）

联系人档案（生日/纪念日/重要度/农历）+ 星型关系图谱（AntV G6）+ 点开 TA 见交往时间线与礼尚往来账 + 长久未联系提醒。AI 人物识别对齐已有联系人称呼。

1.1 四大能力层（业务视角）

🎙 记录入口

文字一句话（Web / 移动端）；语音长按 30s（移动端原生录音 → 服务端 ffmpeg 转码 → GLM-ASR 转写 → 回填预览确认后发布）。

🧠 五域识别

AI-First：一次 GLM 调用联合抽取五域，置信度分流（直接落库 / 待确认 / 不适用），规则引擎只做灾难兜底。

📊 复盘洞察

日/周/月/年四级小结：喂全量原始明细 + 下层小结链 + 用户画像，钱×时间×人交叉归因；小结持久化可回看。

🔐 账户与商业化

手机号密码 / 短信 / 邮箱登录 + 邀请码注册；数据按用户隔离；free/pro 套餐 + AI 调用配额（audit_logs 全量计费口径）。

二、五域识别模型（业务核心）

一句话做五个独立判断，每域自带 applicable + confidence，互不强制：

🕒
日程 schedule
发生了/正做着某件具体的事，AI 直推起止时刻
time_blocks
📋
待办 todo
未来计划（明天/待会儿/打算…），due 必填
todos
💰
收支 finance
金额(分)+方向+分类+交易对象
transactions
😊
心情 mood
情绪词 + valence(-100~100)
entries.mood
🍽
饮食 diet
食物条目拆分 + kcal 估算 + 餐次
diet_records
第六域（联动）：话术中提到的人物由 people 域抽取（对齐已有联系人档案，"爸妈"等合称自动拆分），落到 interactions 人际往来，并在财务上自动关联对手方——这使三轴数据在同一句话上天然联通。
分流规则行为用户感知
confidence ≥ 0.6直接落库 + 登记簿记 applied发布即见日程/账目，可改可删
confidence < 0.6不落库，登记簿记 pending动态卡片提示「N 项待确认」，点开可修正或采纳
日程与已有时间块重叠冲突降级为纯动态（保留心情/账/人）警示条说明原因，可关闭（多端持久）
AI 判定 ongoing（区间横跨当下）落日程块 + 生成收尾待办时间轴显示"进行中"
AI 整体失败（限流/超时/额度熔断）规则引擎兜底（engine=rules，置信 0.4）打卡入口永不失败；单域可重识别补救

4.3 配额与计费口径

机制规则
审计记账audit_logs 记录每次 parse/review/asr 的阶段、engine、model、prompt/completion tokens——全站唯一计费口径（/api/tokens/usage 与配额共用）
套餐配额free：30 天滚动窗口 30 次 AI 调用；pro：不限（plan_expires_at 到期自动回落，无需定时任务）；管理员不限
复盘次数管控日 2 / 周 5 / 月 10 / 年 24 次；晚 20 点前各预留 1/2 次；月逐周 +2、年逐月 +2 解锁；数据改动 bonus+1 不破上限
稳定策略免费档拥塞：429/5xx 总预算内指数退避 → glm-4-flash 降级兜底；额度熔断后直接走规则引擎不再打 API

五、数据模型（21 张表 · 5 组）

账户与会话

  • profiles 用户主表（手机/邮箱/密码 hash/套餐/状态）
  • sessions 会话（token_hash sha256，30 天滑动）
  • sms_codes 短信验证码（hash，5min，限流）
  • email_codes 邮箱验证码
  • invite_codes 邀请码（一码一人）

记录与时间轴

  • entries 动态本体（raw_text/mood/analyzed_at）
  • entry_recognitions 五域识别登记簿（entry+domain 唯一）
  • time_blocks 日程块（起止/模式/来源）
  • todos 待办（due/remind/start_at）
  • activities 九大活动分类（按用户隔离）
  • voice_logs 语音打卡原始记录

财务

  • transactions 流水（方向/金额分/分类/对手方/外部单号去重）
  • accounts 账户（余额/类型）
  • budgets 预算（月度上限预警）

人际

  • contacts 联系人（生日/农历/纪念日/重要度/AI 画像）
  • interactions 往来（类型/摘要/发生时刻）

AI 沉淀与运营

  • diet_records 饮食条目（meal/kcal）
  • review_caches 四级小结持久化
  • review_gen_quotas 复盘次数管控（用户×周期）
  • user_ai_profiles 用户画像（月报后自动合并）
  • audit_logs AI 全量审计（计费口径）

关键联动：entries ←1:N→ entry_recognitions（每次识别留痕）；time_blocks/todos/transactions/diet_records/interactions 均挂 entry_id 可溯源到原话；transactions.counterparty ↔ contacts（礼尚往来）；contacts.alias 兜底称呼变体避免重复建档。

七、认证与安全

面方案
登录方式手机号+密码（scrypt）· 手机号+短信验证码（腾讯云 SMS）· 邮箱验证码；微信扫码预留（需企业主体）
会话HttpOnly Cookie（Web 同域）存随机 token，库存 sha256 可吊销；30 天滑动续期（剩余<15 天自动续）；原生端走 Authorization: Bearer
注册邀请码制（8 位易读字符，一码一人）；首个 /setup 账号为管理员（继承开发用户 UUID，存量数据零迁移）
数据隔离全表 user_id 隔离 + 每查询显式过滤；全站门禁（页面 307 / API 401）
风控验证码 hash 存储 5 分钟有效错 5 次作废；同号 60s/次、日 10 条；生产严禁 AUTH_DISABLED
AI 安全敏感日记数据仅出站给智谱 API；导出功能（/api/export）满足个保法可携带权；审计留痕可追溯每次 AI 消耗
