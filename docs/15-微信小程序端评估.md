# 15 · 微信小程序端评估（Taro + 全量对齐移动 Web）

> 背景：Web（Next.js 15 静态导出）与 Expo 原生端已上线，`docs/14` 方案 D 已论证小程序作为补充渠道。本文是其落地评估：通读移动 Web 端代码与架构后，给出新增小程序端所需改动的完整清单。**已定决策**：Taro 4 + React、首版全量对齐移动 Web、微信一键登录 + 短信绑定（code2session 个人主体可用，无需企业认证）。

## 一、结论摘要

| 项 | 结论 |
|---|---|
| API 层 | **零改动**。全部 27 组端点的 Bearer 通道天然支持小程序 |
| 服务端新增 | 1 个迁移（040）+ 2 个端点（微信登录/绑定）+ config + msgSecCheck 接入，约 1–2 天 |
| 共享逻辑 | packages/shared 纯函数 9 模块可直接 import（Taro 编译 TS 源码，比 Expo metro 还顺） |
| 主体工作 | `apps/miniapp` 全新 Taro 应用，UI 层全重写（20+ 页面），约 4–6 周（单人） |
| 硬前置 | **确认 ting97.cn ICP 备案状态**（docs/09 记为待确认）+ 小程序注册 + request 域名白名单 |
| 审核风险 | UGC 内容安全（msgSecCheck）是个人主体过审硬门槛；类目建议「工具-效率」 |

## 二、现状盘点：现有资产对小程序的支撑度

### 2.1 零改动直接复用

| 资产 | 位置 | 小程序怎么用 |
|---|---|---|
| Bearer 会话契约 | `apps/api/src/server/identity/auth.ts`、`packages/shared/src/bearer.ts` | `wx.request` header 带 `Authorization: Bearer <64hex>`；与 Expo 端完全同构（`POST /api/auth/login` → `{ok, token, user}`，token 存 storage） |
| 全部业务端点 | `apps/api/src/app/api/**`（27 组） | JSON in/out，无 web 专属假设；feed/parse/spaces/schedule/todos/contacts/finance/trading 全可直调 |
| CORS | `packages/shared/src/cors.ts` | 对带 Bearer 的请求动态回显 Origin；wx.request 不发 Origin → 返回空 CORS 头即可，无需改 |
| middleware 浅门卫 | `apps/api/src/middleware.ts` | 无 Bearer/cookie 的 `/api/*` 401，`/api/auth*` 与 `/api/health` 豁免——微信登录端点天然放行，无需改 |
| CSRF | `apps/api/src/server/platform/security/csrf.ts` | 仅约束 cookie 会话的写请求，Bearer 豁免——小程序无 cookie，无影响 |
| shared 纯函数 | `packages/shared/src/`：finance / date（含 bjToday 北京时区组）/ bearer / mood / types / csv-import / social / graph / reminders（lunar 链到 solarlunar） | Taro webpack 直接编译 TS 源码（`package.json` 子路径导出指向 `./src/*.ts`），比 Expo（因 metro 弃用 shared）更顺 |
| web 端纯逻辑 | `apps/web/src/lib/*`：bj-time / finance / mood / mt5-parse / group-tone 等 | 无 DOM 依赖的模块可平移 |
| API 契约先例 | `apps/mobile/src/api.ts`（129 行） | request 封装、401 处理、响应含 token 自动入库、北京时区 from/to 计算——小程序数据层蓝本 |
| 双主题令牌 | `apps/mobile/App.tsx` THEMES 常量（与 web globals.css `:root` 同源） | 映射为小程序 WXSS CSS 变量 |

### 2.2 需小适配

- **client-api.ts 的 fetch/FormData 语义**：小程序无 fetch/FormData。按 Expo 先例，miniapp 自带轻封装（`wx.request` + Bearer + 401 清 token + 响应 token 自动入库 + `wx.uploadFile` 分支，约 130 行），**不动 packages/shared**（避免给 shared 引入 wx 类型依赖，web 端零风险）。
- **Token 存储**：`expo-secure-store` → `wx.setStorageSync`（key 沿用 `"shiguang_token"`）。

### 2.3 全部重写（成本主体）

| Web 实现 | 小程序实现 |
|---|---|
| Tailwind 4（`@theme inline` + CSS 变量，`globals.css`） | WXSS/SCSS + CSS 变量双主题（dark/light 同源令牌），rpx 单位 |
| App Router 页面 + `next/link` + Nav 横滑顶栏 | Taro 页面 + tabBar（4 tab：动态/日程/财务/我的）+ 自定义导航（沉浸式头部） |
| 底部弹层范式（`fixed inset-x-0 bottom-0 rounded-t-2xl safe-bottom`，web 里是重复模式无统一组件） | 自绘半屏弹层组件（一次抽通用，全站复用）——比 web 端更值得先抽 |
| `useDismiss`（点外/Esc 关闭） | 遮罩 onTap + 页面 onUnload 关闭 |
| 语音：`lib/voice-recorder.ts`（Web Audio + MediaRecorder，30s） | `wx.getRecorderManager`（format `wav` 16k，与 `/api/asr` GLM-ASR 兼容——Expo wav 通道已验证同构）；长按/上滑取消手势用 touch 事件重写 |
| 图片：FormData 多文件并行上传（`publish-sheet.tsx` ≤9 图） | `wx.chooseMedia` + `wx.uploadFile`（字段名 `file`），并行与重试逻辑照抄 |
| 路由式 401（`shared/session.tsx` router.replace("/login")） | `Taro.reLaunch({ url: "/pages/login/index" })` 单点封装在 request 拦截器 |
| 部署换血自愈（`chunk-error-reloader`） | 不需要——小程序无 chunk 概念 |
| `safe-bottom` / `@media (hover:none)` 常显操作 / iOS 防缩放 | 小程序原生无这些问题，相关 CSS 约定不迁移 |
| Web 存量水合警告 #418（构建时刻红线烙进静态 HTML） | **天然消失**（无静态 HTML 水合） |

## 三、技术选型：Taro 4 + React

- 与仓库 React 19 + TS 体系一致，组件写法/hooks 心智与 web 端互通；docs/14 方案 D 已预判「Taro 用 React 语法写，与现有栈亲和」。
- **packages/shared 可直接 import**（webpack 编译 TS 源码），这是相对微信原生（需手工构建或复制 shared）与 uni-app（Vue 割裂）的决定性优势。
- 纯手写样式（对齐 web/Expo 的自绘风格），不引重 UI 库；Taro 只作编译层。
- 已知代价：多一层编译抽象（px→rpx、process.env 注入、monorepo watchFolders 配置——Expo 的 metro.config.js 经验可迁移）。

## 四、服务端改动清单（唯一要动的代码，约 1–2 天）

### 4.1 迁移 `packages/db/migrations/040-wechat-auth.sql`

```sql
alter table profiles
  add column if not exists wechat_unionid text unique,  -- 小程序 openid 已有（002 预留），unionid 备未来公众号/网站应用同主体打通
  add column if not exists avatar_url text;              -- 微信头像（wx.getUserProfile，可选）
```

无需动：`sessions`（user_agent 记 `miniapp` 即可）、`login_attempts`（identity 是自由 text，写 `wx:<openid>`）、`sms_codes`（purpose `bind` 已覆盖绑定场景）。

### 4.2 新端点（挂 identity 域，走 withRoute 家族 + service 层）

| 端点 | 语义 |
|---|---|
| `POST /api/auth/wechat/login` | 入参 `{code}`；服务端调 `api.weixin.qq.com/sns/jscode2session`（appid+secret）；按 openid 查 `profiles.wechat_openid` → 命中即复用 `createSession()` 返回 `{ok:true, token, user, bound:true}`；未命中返回 `{ok:true, bound:false, bindTicket}`——bindTicket 为一次性临时凭证（随机 64hex、sha256 入库、5 分钟过期，落新表或复用 app_config kv） |
| `POST /api/auth/wechat/bind` | 入参 `{bindTicket, phone, smsCode}`；校验 bindTicket → `verifySmsCode(phone,'bind',code)` → `update profiles set wechat_openid` → createSession；openid 已被其他账号占用时 409 |

复用现有基建：`assertLoginAllowed` / `noteAttempt`（identity `wx:<openid>`）/ `touchLastLogin` / `generateSessionToken` / 423 锁定语义。未配置 `WX_MINI_APPID/WX_MINI_SECRET` 时 503（与 SMS 通道「未开通」同语义）。

### 4.3 配置与安全

- `apps/api/src/server/platform/config.ts`：加 `wechat: { appid, secret } | null` getter（env 约定全仓禁散读 process.env）；`.env.example` 补 `WX_MINI_APPID / WX_MINI_SECRET`；生产凭据入服务器 `/opt/shiguangri/.env`。
- **msgSecCheck（审核硬门槛）**：动态文本发布、昵称/感悟等 UGC 写入口，服务端调 `api.weixin.qq.com/wxa/msg_sec_check`（免费，需 access_token 管理）；个人主体 UGC 不接大概率提审被拒。实现为 `server/platform/wechat.ts` 轻客户端（TC 换 access_token + 2h 缓存 + 失败放行降级不阻塞主流程），web/Expo 端发布链路同样受益（同一 API）。

### 4.4 测试

- services-smoke：`loginByWechat` 三分支（新 openid 未绑定 / 绑定成功 / openid 冲突 409）+ bindTicket 过期。
- routes-smoke 清单加 `/api/auth/wechat/login`、`/api/auth/wechat/bind`（401/400 层）。
- 迁移照例：测试库 `--fresh` 演练 → 生产 pg_dump → 执行 + 登记。

## 六、平台约束与合规

| 项 | 结论 |
|---|---|
| request 合法域名 | 微信后台配 `https://shiguang.ting97.cn`（HTTPS + Caddy 已具备）；**每月可改 5 次，先配后开发** |
| **ICP 备案** | **硬前置，需向域名所有者确认 ting97.cn 备案状态**（docs/09 §6 记为待确认）；未备案无法配置服务器域名 |
| 主体与类目 | 个人主体可跑通全部所选方案（code2session 可用；仅 getPhoneNumber/微信支付需企业主体——当前无此需求）；类目建议「工具-效率」，财务内容仅展示自有数据、规避金融类目 |
| UGC 内容安全 | msgSecCheck 服务端接入（见 4.3），个人主体提审大概率被查 |
| iOS 虚拟支付 | 当前无内购，无碍；未来订阅制需引导网页支付（docs/14 已记录） |
| 审核周期 | 1–3 天/次；全量功能建议分两期提审（见批次） |

## 七、用户侧前置动作清单（与开发并行）

1. 注册微信小程序（个人主体），拿 AppID/Secret。
2. 确认 ting97.cn ICP 备案状态；未备案先补备案（周期约 1–2 周，是关键路径）。
3. 微信后台配置 request/downloadFile 合法域名。
4. 类目提交「工具-效率」。
5. 服务器 `/opt/shiguangri/.env` 加 `WX_MINI_APPID/WX_MINI_SECRET`。

## 十、总结

现有三端资产——**Bearer API 全集、shared 纯函数库、Expo 契约先例、`profiles.wechat_openid` 字段预留（002 迁移）**——使小程序端的服务端改动收敛到「1 迁移 + 2 端点 + msgSecCheck」，成本主体在 UI 重写（4–6 周）。与 docs/14 方案 D 的定位一致：**补充渠道，不承担主体体验**；分享卡片 + 免安装触达是其独有价值。是否启动开发与排期另议。
